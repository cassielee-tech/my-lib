# 写作模板｜复盘手记

> 复制本页到 `0N-主题名.md` 开始写新的一篇。叙事主线固定为：**现象 → 定位 → 根因 → 方案演进 → 验证 → 检视 → 教训**。写完检查最后一节的"完稿自检"。

## 文章骨架

```md
# 实践总结｜<一句话需求名>：从 <入口> 到 <出口>

> 所属专栏：[实践总结](index.md) · 第 N 篇

::: info 本篇目标
复盘一个真实需求的完整生命周期：<Issue/需求> → 根因定位 → 方案演进（含检视意见）→ 分层验证 → 合入。读完你能带走 **<知识点链路>** 和一套 **<可平移的方法论>**。
:::

## 0. 事实基准

- 代码基线：仓 + 分支 + commit + 日期，文中 `文件:行号` 均按此核对；
- 关联 Issue / PR / 需求单链接。

## 1. 现象与影响面

- 问题怎么暴露的（报错 / 测试 / 用户反馈）；
- 影响面矩阵：哪些场景命中、哪些不命中、为什么。

## 2. 定位路径

- 排查链路：日志 → 断点 → 源码，每一步"排除了什么"；
- **走错的岔路也记下来**——这是下一篇最值钱的部分。

## 3. 根因

- 一句话说清根因；
- 为什么代码当初写成这样（历史约束、隐含假设）。

## 4. 方案演进

- 每轮方案：改了什么 → 检视意见是什么 → 为什么改；
- 最终方案的边界与取舍。

## 5. 验证

- UT / 上板对照实验 / 存量冒烟各自负责验证什么；
- 验证结果数据。

## 6. 教训清单

- 可平移的方法论（≤3 条，超出说明还没消化完）。

## 自测问题

- 3-5 个"三个月后还能不能答上来"的问题。
```

## 完稿自检

- [ ] 事实基准可复查：commit、行号、Issue/PR 链接都能打开；
- [ ] 定位路径包含至少一条走错的岔路；
- [ ] 教训不超过 3 条，且换一个需求照样适用；
- [ ] 敏感信息已脱敏（内部地址、账号、未公开节奏）。
