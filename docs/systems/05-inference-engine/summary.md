```text
转变（05-1）：只有前向 · 请求时长不可预知 · 吞吐×延迟双指标
   朴素两账单：串行喂不饱 / 静态批整批等最慢
        ↓
调度（05-2）：Continuous Batching —— 迭代级调度
   完成即退出 · 新到即补位 · 每步重组 → 利用率 40% → ~100%
        ↓
显存（05-3）：KV 账 0.5MB/token → 预留式浪费 60-80%
   Paged Attention：逻辑连续物理散装 · 块表映射 · 浪费 <10%
        ↓
进阶（05-4）：Prefix Cache 共享前缀只算一次（计算+显存双省）
   多卡推理：TP 的每层 AllReduce / EP 的 A2A / PD 的 KV 传输
   —— Decode 通信小而高频、延迟敏感，与训练通信互补
```

## 9. 动手练习

### 练习 1：算 KV 账

70B 模型（80 层、h=8192）、BF16、单卡 80 GB（权重 140 GB 需 TP=2）。计算：每 token 的 KV 显存、一个 32K 上下文请求的 KV 总量、TP=2 后每卡还能服务多少满上下文请求（预留式 vs 分页式各算一遍）。

### 练习 2：利用率推演

请求生成长度均匀分布于 100~1000 token。静态批（批大小 8）的平均算力利用率约多少？改为连续批后利用率的上界由什么决定？

### 练习 3：命中收益

系统提示 4K token，服务 100 个请求。无 Prefix Cache 与全命中两种情况下，Prefill 的总 FLOPs 相差多少倍？若部分命中（命中率 60%），给出计算式。

## 10. 自测题

1. 推理相对训练的三重转变是什么？哪一条是调度麻烦的根源？
2. 静态批的两层浪费分别是什么？
3. Continuous Batching 的调度单位是什么？三个机制各消灭什么浪费？
4. 连续批之后，新的瓶颈是什么？
5. 每 token 的 KV 显存公式是什么？Llama-7B 级是多少？
6. 预留式分配的浪费来自哪两个来源？典型比例是多少？
7. Paged Attention 的三个核心机制是什么？靠什么映射结构？
8. 分页的代价是什么？
9. Prefix Cache 为什么合法（causal 的哪条性质）？省哪两笔账？
10. 推理 Decode 通信与训练通信的性格差异是什么？

::: details 自测答案

1. 只有前向（无反向/优化器）；请求时长不可预知（自回归）；吞吐×延迟双目标。时长不可预知是根源——batch 维度随时变。
2. 提前完成请求的空转陪等；新请求排队等批边界。
3. 一步 Decode 迭代。完成即退出、新到即补位、每步重组——分别消灭空转、排队、批大小失配。
4. 显存能装下多少并发请求的 KV Cache。
5. 2 × 层数 × hidden × 2 字节；32×4096×2×2 ≈ 0.5 MB/token。
6. 内部碎片（按 max_len 预留、实际用不满）+ 外部碎片（连续槽位对不齐）；合计 60-80%。
7. 固定大小物理块、按需分配、块表（逻辑块→物理块）映射。
8. Attention kernel 按块表寻址（gather），实现比朴素连续 KV 复杂。
9. 前缀的 KV 只依赖前缀 token（causal：前面的 token 看不到后面）；省 Prefill 计算与 KV 显存（块级共享）。
10. 训练：大而低频（梯度 AllReduce，可重叠）；Decode：小而高频、延迟敏感（每 token 每层通信，抖动直接累积进延迟）。

:::

## 11. 本课小结

- 推理引擎 = 调度器 + 显存管理器 + 执行器，对抗的核心是"不可预知"；
- 连续批把批边界从"请求"降到"迭代"——吞吐的钥匙；
- 分页把 KV 浪费从 60-80% 压到 <10%——并发的钥匙；
- 前缀复用让共享前缀只算一次——计算与显存的双省；
- 多卡推理的通信挂回主线钩子（TP/EP/PD），Decode 的延迟敏感是通信库的另一半战场。
