## 7. 推理通信的完整版图

把本专栏（第 3/5/6 章）出现的推理通信与训练通信并排放好——这是给 HCCL 岗位的交接清单：

| 维度 | 训练通信 | 推理通信 |
| --- | --- | --- |
| 典型流量 | 梯度 AllReduce（GB 级、每步一轮） | ① TP/EP 每层小集合（MB 级、每 token 一轮）② PD 的 KV 大块 P2P（GB 级、每请求一次） |
| 频率/时机 | 低频、可与反向重叠 | ① 极高频、在关键路径（每字都过）② 低频、可与新请求并行 |
| 敏感指标 | **带宽**（β 主导） | ① **延迟**（α 主导，[《集合通信》03 章](../../collective/03-tree-algorithms-selection/03-selection-map.md)的小消息区）② 带宽 |
| 算法偏好 | Ring（大消息） | ① Tree/低轮次（小消息）② 大块直传/分层 |

三行结论：

1. **Decode 的 TP 通信与训练 TP 同构**，但消息更小、频率更高——训练里"够快"的算法（如 Ring）在 Decode 的 5 ms 步预算里可能太慢，小消息算法（低轮次的 Tree 族）反而合适（[H01-6](../../ascend/hccl-source/06-coll-algorithms.md) 的选型维度）；
2. **PD 的 KV 传输是新增形态**——大块、点对点、延迟宽容但带宽饥渴，正好落在机间高速链路（分层传输）的甜区（[《集合通信》05 章](../../collective/05-topology-hierarchical-overlap/02-hierarchical.md)的分层思想）；
3. **重叠逻辑两处成立**：KV 传输与后续请求 Prefill 并行、Decode 通信与算子执行交叠（[《单卡执行系统》07-4](../../device/07-stream-event-async/04-overlap.md) 的三条件不变）。

## 8. 专栏收官：训练与推理的两张全景图

《训练与推理系统》六讲至此收齐。两张最小全景图带走：

```text
训练：数据 → 前向 → 反向（梯度桶就绪即 AllReduce，与反向重叠）→ 更新
      显存账本：P+G+O 三大件（Offload/累积/重计算腾挪）

推理：请求 → 调度（连续批）→ Prefill（compute-bound）⇄ Decode（memory-bound，
      分页 KV + 前缀复用 + 迭代级混跑）→ 逐 token 流出
      指标三角：TTFT / TPOT / 吞吐（Chunked Prefill 缓解，PD 分离根治）
```

**给主线的三句话**：训练的通信是"梯度的民主"（全员取平均），推理的通信是"token 的接力"（每层传递、每步累积）；前者要带宽与重叠，后者要延迟与分层——**HCCL 的完整战场，一半在训练，一半在推理**。
