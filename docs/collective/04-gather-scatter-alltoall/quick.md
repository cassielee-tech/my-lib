# ⚡ 速通｜第 4 章：AllGather、ReduceScatter 与 AlltoAll（约 5 分钟）

> 适用：时间紧，或完整版跟不动时。这页用"办公室分发动作"讲完整章，读完抓住 80% 的主干。任何一节想深入，拉到文末点对应单元。

## 1. 复印发全员：AllGather

每人手里有一章稿子（合起来是一份完整报告）。**AllGather = 每人复印自己那章、发给所有人**——结束后人手一册完整报告。

- 形状变化：每人 `[1/4 本]` → 人人 `[完整 4 章]`；
- 报告被复制了 4 份（4 = 人数）；
- 谁在用：TP 前向（各卡算出激活的不同切片，拼全才能算下一步）、FSDP（参数平时分片存，用时拼全）。

::: details 小测 1：AllGather 和 AllReduce 的关系？
AllReduce = ReduceScatter + AllGather（黄金恒等式）。Ring AllReduce 的下半场舞步，单独跳就是一次完整的 AllGather——账本也正好是 AllReduce 的一半。
:::

## 2. 汇总后各撕一章：ReduceScatter

每人手里都有一份**带批注的全稿**（内容不同、要合并）。**ReduceScatter = 全员逐段求和，然后每人撕走自己负责的那一章**——你拿到"数学章的全组批注之和"，他拿到"语文章的"。

- 形状变化：每人 `[全稿]` → 每人 `[自己那章的合并版]`；
- 只规约、不复制全量；
- 谁在用：TP 反向（梯度求和后各拿自己参数段）、FSDP 反向（比 AllReduce **省一半**——别人的梯度段对我没用）。

::: details 小测 2：FSDP 反向为什么用 RS 不用 AllReduce？
参数本来就分片存：我只需要"我这段参数"的梯度。AllReduce 给每人全长（2S），RS 只给各段（S）——**语义上够用的最小原语**，通信直接省一半。
:::

## 3. 各部门互寄快递：AlltoAll

前两个都是"汇总/复制"，第三个是**搬家**：每个部门把自己手里的包裹按**收件地址**分好，同时寄出——寄给谁的、寄多少，**出发前就查好路由**。

- 形状变化：每人总量**不变**，但内部按"目的地"重排了（近似一次转置）；
- 和 AG 的本质区别：**总量守恒、人人拿到的都不一样**（AG 是总量翻倍、人人拿到一样的）；
- 谁在用：MoE 的 dispatch/combine（token 按路由结果寄往专家所在的卡）。

## 4. MoE 的快递为什么总堵：动态失衡

MoE 的"收件地址"是**路由器实时决定**的——今天上午热点在专家 3（他所在的部门爆仓），下午热点换到专家 7。而集合通信是**全员到齐才散场**：7 个方向都寄完了，也得陪最慢的那个等——**木桶效应，最慢方向 = 全体耗时**。

两条缓解路线：

- **模型侧**：辅助损失/均衡约束（让路由别扎堆）、容量因子限流（每个专家设收件上限，超了就丢——通信均匀了，牺牲一点计算）；
- **通信侧**：等大小块 + padding（凑成通信库喜欢的规整形状）、多小块流水（压缩等待空泡——下一课的 chunk/channel 就是钥匙）。

::: details 小测 3：为什么说"同步性放大了失衡的伤害"？
集合通信是同步协议：所有 rank 的 A2A 要一起结束。任何方向慢了，全体都在等它——失衡不是"局部慢"，而是"全体被最慢方向拖死"。
:::

## 3 句话带走

1. **AG 复制拼全**（`[S/N]→[S]`）、**RS 规约分持**（`[S]→[S/N]`）——TP/SP/FSDP 的日常动词；
2. **A2A 是定向搬运不是复制**——总量守恒、按目的地重排，MoE 的骨架；
3. **MoE 之难在动态失衡**——同步集合通信木桶效应；模型侧调流量、通信侧抗失衡。

## 黑话小词典

| 术语 | 人话 |
| --- | --- |
| AllGather | 复印自己那章发全员，人手一册全本 |
| ReduceScatter | 逐段求和后，每人撕走自己负责的一章 |
| AlltoAll | 按收件地址互寄快递：总量不变、流向大变 |
| dispatch/combine | MoE 进专家前寄出/出专家后收回的一对 A2A |
| 木桶效应 | 同步集合通信的耗时由最慢方向决定 |
| 容量因子 | 每个专家的收件上限，超了就丢 |
