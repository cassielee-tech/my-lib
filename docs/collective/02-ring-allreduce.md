### 1. 为什么大家手拉手围成圈

要让 8 个同学合作汇总成绩，有两种笨办法：**全连**（每人跟所有人单独传话——线路铺不开）和**找班长中转**（8 份卷子全挤班长一张桌子——班长就是瓶颈）。

聪明的办法是**围成一个圈**：每人只跟**左右两个邻居**打交道。

两个魔法性质：

1. **没有班长**：每人恒定 2 条线路，第 100 个同学入圈，前辈们压力一点不变；
2. **全员同时动**：任何时刻每人都在"收一张、发一张"——8 条线路同时满负荷，等于 8 倍带宽。

注意：这个"圈"是**排座位的逻辑顺序**，不是真拉网线——通信库让大家按这个顺序传就是了。

::: details 小测 1：环形为什么"没有中心瓶颈"？
每人只有左右两条链路、每个 rank 进出流量恒定；不存在所有数据必经的节点。对比星形：全班数据都挤班长一张嘴，人数越多班长越堵。
:::

### 2. 第一支舞：分头汇总（ReduceScatter）

每人把自己那份成绩切成 4 块（语文/数学/英语/物理），目标：**每人最终负责一科的完整汇总**。

规则只有一句：**每轮每人把一块"累积中的卷子"传给右邻居，从左邻居收一块、加上自己的数**。

4 人、3 轮的手推（拿纸走一遍胜过读十遍）：

```text
第1轮：我发"自己编号"的块给右邻 → 右邻加上自己的数（每块吸收 2 人）
第2轮：把刚加完的那块继续右传   → 每块吸收 3 人
第3轮：再传一轮                → 每块吸收 4 人 = 完全！
```

3 轮后：**每人手里恰好有一块"全组之和"**（我负责数学，数学块就汇聚到我手里）。为什么恰好 3=N−1 轮？一块数据每被传一次多吸收一个人的数，要吸收其余 N−1 个人，就要被传 N−1 跳。

::: details 小测 2：为什么总轮次是 N−1 而不是 (N−1)×N？
因为 N 块数据在环上**同时**流动（每人每轮都在传），不是一块块排队传。N 条流水线并行推进，每条走 N−1 跳，总轮次仍是 N−1。
:::

### 3. 第二支舞：传阅成全（AllGather）

现在每人有一块完整汇总，但目标（AllReduce）是**每人都要全部 4 块**。

规则更简单：**不加法了，把完全块绕圈传阅**——每轮每人把最新拿到的那块发给右邻居。又是 N−1 轮，每人集齐全部块。**AllReduce 完成**。

这就是上一章恒等式的舞蹈版：**AllReduce = RS（边传边加）+ AG（纯传阅）**。

### 4. 结账：魔法与诅咒

$$
T_{Ring} \approx \underbrace{2(N-1)\alpha}_{\text{起步价×轮次}} + \underbrace{\tfrac{2S(N-1)}{N}\cdot\tfrac{1}{BW}}_{\text{运费}}
$$

- **魔法（运费项）**：每人经手 ≤ 2S 字节，**与人数无关**——8 人是 1.75S，1024 人也才 2.0S。加人不加流量；
- **诅咒（起步价项）**：2(N−1) 轮的启动成本**随人数线性膨胀**——1024 人、每次 20µs，光启动就 40ms。

所以：**大消息用 Ring（运费说了算，它运费最低）；小消息别用 Ring（起步价说了算，它轮次太多）**。工程上还常把数据切成 2N 块（而非 N 块）——总量不变，但小包裹流水更满，运费更贴近账面。

::: details 小测 3：1 KB 的梯度同步用 8 rank Ring，会发生什么？
传输本身只要微秒级，但 2×7=14 轮的启动成本（约几百 µs）彻底淹没它——延迟项碾压带宽项。这种场景该换轮次只有 log₂N 的算法（下一课的 Tree/递归倍增）。
:::

### 3 句话带走

1. 环 = **没有班长 + 全员同时收发**：拓扑上的人人平等；
2. 两支舞：**RS 边传边加（每人得一块全和）→ AG 纯传阅（每人集齐全部）**= AllReduce；
3. 账本：**运费 ≤ 2S 与人数无关（大消息天选），起步价随人数线性涨（小消息噩梦）**。

## 02-1｜为什么是环：拓扑的自然性

::: info 本单元目标
围绕 **环形拓扑的带宽优势** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

算法先看舞台。N 个 rank 怎么连接，决定了数据怎么流动。

### 2. 三种连接方式的对比

假设 8 个 rank 要互相配合，比较三种拓扑：

**① 全连接（everyone-to-everyone）**：人人直连。链路数 O(N²)，物理上根本铺不出来——只在很小的机内域近似成立。

**② 星形（root 中转）**：所有数据过一个中心。中心的进出带宽是全组瓶颈——8 个人的汇总全挤老板一张嘴，rank 越多老板越堵。

**③ 环形（Ring）**：每人只连左右两个邻居：

```text
   ┌──────→ 1 ──────→ 2 ──┐
   0                      3
   └──────← 7 ←────── 6 ←─┘   （示意 8 rank，首尾相接）
```

#### 2.1 环的两个关键性质

**性质一：没有中心瓶颈。** 每个 rank 的进出链路数恒等于 2——**第 100 个 rank 加入时，前辈们的链路压力一点不变**。

**性质二：全员同时收发 = 链路满载。** 任何时刻，每个 rank 都在"收一块、发一块"。N 条链路同时工作，**有效吞吐是单链路的 N 倍**——这是星形永远做不到的（星形的中心同一时刻只能服务有限流量）。

::: warning "环"是逻辑的，不一定是物理的
真实硬件不是拉一根环形网线：机内高速互联（HCCS/NVLink）近似全连接，机间走交换网络。**Ring 是通信库在逻辑拓扑上的编排**——数据沿一个逻辑顺序流经所有 rank。物理链路能否支撑这个逻辑环，是第 5 章拓扑课的主题。
:::

对 α-β-γ 账本（第 1 章）先给一个预告：环的**带宽账是最优的**（每条链路恰好各走一份），但**轮次账是 O(N)**——每块数据要绕环 N−1 步。这笔交易值不值，取决于消息大小：第 4 单元用公式说清。

## 02-2｜第一阶段：ReduceScatter 轮转

::: info 本单元目标
围绕 **RS 阶段的轮转规则** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

目标：N 个 rank 各有一份向量（切成 N 块），结束时**每人手里有一块"完全规约块"**（= 全组该块之和）。工具只有一条环、N−1 轮。

### 3. 规则：每轮传"累积块"

设定（4 rank 示例）：数据切 4 块，记号 `Xᵣ` = "块 X 来自 rank r"。rank r 把块发给**右邻居**（r+1）。

**每轮规则**：每人把自己手里的一块**累积块**发给右邻居，同时从左邻居收一块，**加进自己对应的块**。

#### 3.1 4 rank 手工模拟（建议拿纸跟着走）

**初始**（每人 4 块，下标是来源）：

```text
Rank 0:  0₀  1₀  2₀  3₀
Rank 1:  0₁  1₁  2₁  3₁
Rank 2:  0₂  1₂  2₂  3₂
Rank 3:  0₃  1₃  2₃  3₃
```

**第 1 轮**：每人发自己编号的块（rank r 发块 r）→ 右邻居加进同名块：

```text
发：0₀→1   1₁→2   2₂→3   3₃→0
收后：Rank1 的块0 = 0₁+0₀；Rank2 的块1 = 1₂+1₁；Rank3 的块2 = 2₃+2₂；Rank0 的块3 = 3₀+3₃
```

**第 2 轮**：每人发"上一轮刚加完的块"（rank r 发块 (r−1) mod 4）：

```text
发：3₀₃→1   0₁₀→2   1₂₁→3   2₃₂→0
收后：Rank1 块3 = 3₁+3₀₃；Rank2 块0 = 0₂+0₁₀；Rank3 块1 = 1₃+1₂₁；Rank0 块2 = 2₀+2₃₂
```

**第 3 轮**：继续左移一块（rank r 发块 (r−2) mod 4）：

```text
发：2₀₃₂→1   3₁₀₃→2   0₂₁₀→3   1₃₂₁→0
收后：Rank1 块2 = 2₁+2₀₃₂ ✓完全！  Rank2 块3 = 3₂+3₁₀₃ ✓   Rank3 块0 = 0₃+0₂₁₀ ✓   Rank0 块1 = 1₀+1₃₂₁ ✓
```

#### 4. 阶段结束状态

N−1 = 3 轮后，**每个 rank 恰好持有一个完全规约块**（本约定下 rank r 持有块 (r+1) mod N，具体哪块随发送方向约定而变，本质不变）：

```text
Rank 0:  1₀₃₂₁ ← 块1 的全组和
Rank 1:  2₁₀₃₂ ← 块2 的全组和
Rank 2:  3₂₁₀₃
Rank 3:  0₃₂₁₀
```

**为什么恰好 N−1 轮？** 一块数据要从"只有自己的一份"长成"包含全组 N 份"，每被转发一次多吸收一个 rank 的贡献——绕环走 N−1 跳吸收 N−1 个别人，第 N 份是自带的。环上同时有 N 条这样的流**并行**推进，所以总轮次是 N−1 而不是 (N−1)×N。

## 02-3｜第二阶段：AllGather 轮转

::: info 本单元目标
围绕 **AG 阶段的轮转规则** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

RS 结束时每人一块完全块；AllGather 的目标：**让每人集齐全部 N 块**。规则比 RS 还简单——不加法了，纯转发。

#### 5.1 规则：完全块绕圈传阅

**每轮**：每人把自己手里"最新拿到的那块完全块"发给右邻居；收到后原样保存，下一轮继续转发。

#### 5.2 4 rank 手工模拟（接上一单元的结束状态）

```text
初始：Rank0 有块1✓   Rank1 有块2✓   Rank2 有块3✓   Rank3 有块0✓

第 1 轮发：块1→1号  块2→2号  块3→3号  块0→0号
  结果：每人有 2 块完全块

第 2 轮发：把刚收到的继续右传
  结果：每人有 3 块完全块

第 3 轮发：再传一轮
  结果：每人有 4 块完全块 ✓ AllReduce 完成
```

**轮次数**：一块完全块要到达"最远"的 rank 需要绕 N−1 跳；N 块在环上并行流动 → 总轮次 N−1。

#### 6. 两阶段合龙：恒等式落地

```text
        RS 阶段（N−1 轮，边传边加）          AG 阶段（N−1 轮，纯转发）
开始：每人 N 块部分数据   ────────►   每人 1 块完全块   ────────►   每人 N 块完全块
                                          = AllReduce 语义
```

第 1 章的黄金恒等式 **AllReduce = ReduceScatter + AllGather** 在这里从语义变成了可执行的舞蹈：两段舞步完全同构（每轮每人恰好收发一块 S/N），只是一段带加法、一段不带。

## 02-4｜Ring 的账本与变体

::: info 本单元目标
围绕 **Ring 的时间公式与适用边界** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

舞步会跳了，该算钱了——用第 1 章的 α-β-γ 账本给 Ring 结账。

#### 7. 时间公式

两阶段共 **2(N−1) 轮**，每轮每人收发 **S/N** 字节：

$$
T_{Ring} \approx \underbrace{2(N-1)\cdot\alpha}_{延迟项} + \underbrace{\frac{2S(N-1)}{N}\cdot\frac{1}{BW}}_{带宽项}
$$

**带宽项的魔法**：$\frac{N-1}{N} < 1$ 且随 N 增大趋近 1——

```text
N=8:    每 rank 经手 2S × 7/8 ≈ 1.75S
N=64:   ≈ 1.97S
N=1024: ≈ 2.00S
```

**无论多少人参加，每 rank 的搬运量永远 ≤ 2S**。加卡不加流量——这就是"带宽最优"的含义（对比星形：中心要经手 N·S）。

**延迟项的诅咒**：2(N−1)·α 随 N **线性膨胀**。N=1024、α=20µs 时，光启动就 40ms——小消息（本身只需几 µs 传输）被彻底淹没。

#### 7.1 一张选型直觉表

| 场景 | 主导项 | Ring 是否合适 |
| --- | --- | --- |
| 大消息（MB~GB）、中等 N | β | ✅ 天选 |
| 大消息、超大 N | β 为主，α 可观 | ✅ 但分层变体更好（第 5 章） |
| 小消息（KB 级）、任何 N | α | ❌ 轮次太多 |
| 小消息、N 为 2 的幂 | α | ❌ RD/Tree 几轮完事（第 3 章） |

#### 8. 工程变体：把块切得更细

教科书 Ring 把数据切 N 块；工程实现（如 Baidu-ring）常切 **2N 块**：

- **总量不变**：还是每人 2S(N−1)/N 字节，公式照旧；
- **流水更平滑**：块更小、在途数据更多，**链路等待间隙被填满**——β 项更贴近理论值；
- **代价**：调度与缓冲管理更复杂（每 rank 要管理 2N 个小块的收发状态）。

这引出一个通用工程直觉：**算法决定账本形状，chunk 粒度决定账本兑现率**——第 5 章的 Chunk/Channel 是它在拓扑层的一次放大。

```text
        ↓

   → 每人一块完全规约块
        ↓
AG 阶段（02-3）：N−1 轮"完全块传阅"，纯转发
   → 每人集齐全部块 = AllReduce ✓（恒等式落地）
        ↓

```

### 10. 自测题

1. 环形拓扑相比星形的两个关键优势是什么？
2. "环"是物理连线还是逻辑编排？
3. RS 阶段每一轮的规则是什么？总共几轮？
4. 一块数据为什么恰好需要 N−1 跳才能成为"完全块"？
5. RS 结束时每个 rank 手里是什么？
6. AG 阶段的规则与 RS 有什么不同？
7. 写出 Ring AllReduce 的时间公式。
8. "带宽项与 N 无关"的确切含义和物理原因是什么？
9. Ring 在什么场景下是坏选择？为什么？
10. 2N 分块变体改变了什么、没改变什么？

::: details 自测答案

1. 无中心瓶颈（每 rank 恒定 2 条链路）；全员同时收发，N 条链路并行满载。
2. 逻辑编排：通信库让数据沿一个逻辑顺序流经所有 rank；物理网络通常是交换式的，能否支撑看拓扑（第 5 章）。
3. 每人把一块"累积块"发给右邻居，同时从左邻居收一块加进自己的同名块；共 N−1 轮。
4. 一块每被转发一次吸收一个新 rank 的贡献；自带 1 份、要吸收其余 N−1 份，故需 N−1 跳。
5. 恰好一个"完全规约块"（全组该块之和），具体哪块取决于发送方向约定。
6. AG 不做加法，纯转发"完全块"；同为 N−1 轮、每轮每 rank 收发 S/N。
7. T ≈ 2(N−1)·α + 2S(N−1)/(N·BW)。
8. 每 rank 经手字节 ≤ 2S·(N−1)/N < 2S：加 rank 只是增加并行流动的块数，不增加任何一条链路/任何一个 rank 的流量；对比星形中心需经手 N·S。
9. 小消息（α 主导）场景：2(N−1) 轮的启动成本淹没传输本身；大 N 时延迟项线性膨胀更糟。
10. 改变：chunk 粒度更细、在途流水更满、β 项兑现率更高；不变：总字节数与公式形状。

:::

### 11. 本课小结

- 环的本质：无中心 + 全员同时收发——拓扑层面的"人人平等"；
- AllReduce 的 Ring 舞蹈 = RS（边传边加，N−1 轮）+ AG（纯转发，N−1 轮）；
- 每轮每人恰好一块 S/N：带宽项 ≤ 2S 且与 N 无关，延迟项 2(N−1)α 线性膨胀；
- 大消息天选、小消息噩梦——算法选型的第一课；
- 2N 分块：同样的账本，更高的兑现率。
