# 第 3 章｜Tree、Recursive Doubling 与算法选择

> 本课目标：掌握轮次只有 O(log N) 的两大算法族；理解大小消息的分界线从哪来；了解通信库内部的算法选型机制，学会用实测校准理论。

## 本章导学

::: tip 本课只记住 3 件事
1. **RD（递归倍增）**：每轮与**距离翻倍**的伙伴交换全量部分和，log₂N 轮后**人人都有全量**——轮次极少，但每轮都发全量 S 字节。

:::

### 1. 配对通话：RD（递归倍增）

公司 8 个人要对齐一条信息，不拉群、不找中转，怎么办？**配对打电话**：

```text
第 1 轮：0↔1、2↔3、4↔5、6↔7 两两对答案 → 每人知道 2 个人的信息
第 2 轮：跟隔一位的伙伴（0↔2、1↔3…）对 → 每人知道 4 个人的
第 3 轮：跟隔三位的伙伴（0↔4、1↔5…）对 → 每人知道全部 8 人的 ✓
```

**距离每轮翻倍，"知情圈"每轮翻倍**——3 轮 = log₂8。而且双方通完话**各自都记下合并结果**，所以不用再广播，人人手里都是全量。

代价：每通电话都要**把手里全部内容说一遍**——信息量一大（比如要对齐的是一份 500 页报告），电话费就爆了。另外人 数得是 2 的幂，不然配不齐。

::: details 小测 1：RD 为什么大消息吃亏？
每轮交换的是"全量部分和"：每 rank 总流量 S·log₂N。N=8 时 = 3S，而 Ring 只要约 1.75S——报告越厚，电话费差距越大。
:::

### 2. 层层转达：Tree（树）

另一个办法是**建组织树**：组员报给组长，组长汇总报给经理，经理报到总监（**上行归约**，每轮层级减半，log₂N 轮到顶）；总监拿到全量后沿原路发回（**下行广播**，又是 log₂N 轮）。

- 优点：**几轮就完事**（N=1024 只要约 20 轮，Ring 要 2046 轮）；**人数不是 2 的幂也优雅**；组织树天然匹配"组→经理→总监"的层级（预告：下一课的分层通信）。
- 缺点：**总监和经理的电话被打爆**（根节点链路热点），而且总监是单点。

::: details 小测 2：RD 和 Tree 都只有 log 轮，本质区别是什么？
RD 全员对称、双向交换（无需广播阶段，但需 2 的幂）；Tree 有中心（上行+下行两段、根部热点，但任意 N 都行、层级友好）。
:::

### 3. 怎么选：起步价 vs 运费

把上一章的记账本借来（α = 起步价/轮，β = 运费/字节）：

| | Ring（流水传抄） | RD（配对通话） | Tree（层层转达） |
| --- | --- | --- | --- |
| 轮次 | 2(N−1)，人多恐怖 | log₂N | 2·log₂N |
| 每 rank 流量 | ~2S **最少** | S·log₂N | 根部重 |
| 适合 | **大部头** | **小道消息** | 小道消息 + 层级场景 |

**分界点是算出来的**：两个公式相等解 S*。同一组参数（α=20µs、BW=25GB/s）下，N=8 时约 4.4 MB，N=64 时约 15 MB——**集群越大，"小消息"的定义越宽**。

真实通信库（HCCL/NCCL）内部就有个**自动选型器**：查表 + 公式动态比价；你也可以用环境变量（`HCCL_ALGO`/`NCCL_ALGO`）强制指定，再用基准测试从 8B 扫到 1GB 画条曲线，看它选得对不对。

::: details 小测 3：N=64 的集群同步 1 MB 梯度，选谁？
N=64 时分界点约 15 MB，1 MB < 15 MB → α 主导 → 选 Tree/RD 这类 log 轮次算法。若同步 512 MB 梯度则远超分界点 → Ring。
:::

### 3 句话带走

1. **RD = 配对通话**：距离翻倍、知情圈翻倍，log₂N 轮人人有全量——但每轮说全量、要 2 的幂；
2. **Tree = 层层转达**：上行+下行各 log₂N 轮，任意 N 优雅、层级友好，代价是根部热点；
3. **选型 = 算账**：小消息看轮次（Tree/RD）、大消息看流量（Ring），分界点随 N 和硬件移动，实测说了算。

### 黑话小词典

| 术语 | 人话 |

## 03-1｜Recursive Doubling：距离翻倍的会师

::: info 本单元目标
围绕 **RD 的配对规则与账本** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

Ring 的软肋是轮次：N−1 轮起步价。要砍轮次，思路只有一个——**每轮之后，"已合并的队伍规模"翻倍**。这就是 Recursive Doubling（RD，递归倍增）。

### 1. 舞步：距离每轮翻倍

规则：第 k 轮，rank r 与 rank (r XOR 2^(k−1)) 配对（即距离 1, 2, 4, … 逐一翻倍），**双方交换各自的部分和，各自加总**。

N=8 的完整配对表：

```text
第 1 轮（距离 1）：0↔1   2↔3   4↔5   6↔7   → 每人拥有 2 人之和
第 2 轮（距离 2）：0↔2   1↔3   4↔6   5↔7   → 每人拥有 4 人之和
第 3 轮（距离 4）：0↔4   1↔5   2↔6   3↔7   → 每人拥有 8 人之和 = 全量 ✓
```

**为什么 log₂N 轮就够？** 每轮配对后，双方都持有两支队伍的并集之和——"知情圈"每轮翻倍：1→2→4→8，log₂N 轮后知情圈覆盖全组。

**为什么不需要广播阶段？** 交换是**双向对称**的：双方交换后**各自加总**，所以结束时**每个 rank 都有全量结果**——AllReduce 一步到位，不像 Tree（下一单元）还要"先收上去、再发下来"。

### 2. RD 的账本

- **轮次（延迟项）**：log₂N 轮——N=8 时 3 轮，对比 Ring 的 14 轮；
- **每轮流量**：交换的是**当前部分和**（全量 S 字节）——每 rank 经手 **S·log₂N**。

代入 α=20 µs、BW=25 GB/s、N=8：

```text
Ring：T = 14α + 1.75S/BW
RD  ：T =  3α + 3.00S/BW

Ring 更快 ⟺ 11α > 1.25S/BW ⟺ S < 11 × 20µs × 25GB/s / 1.25 ≈ 4.4 MB
```

**S 小于约 4.4 MB 时 RD 赢，大于则 Ring 赢**——分界线不是拍脑袋，是账本算出来的。

::: warning RD 的两个约束
1. **需要 N 为 2 的幂**：非 2 幂时距离翻倍配不齐（工程上用"先掰平再倍增"的变体处理，但复杂度上升）；
2. **每轮发全量**：S 越大越亏——它把"轮次少"赚来的 α 全吐给了 β。
:::

::: tip 亲戚算法：Recursive Halving（RH）
做 **ReduceScatter** 时有个更省的版本：每轮把消息**对半分**、一半发出去、一半留下——发出去的量逐轮减半，总流量恰好 S(N−1)/N（**带宽最优**）且轮次 log₂N。RH（做 RS）+ RD（做 AG）的组合是经典的 Rabenseifner AllReduce：**log 轮次 + 带宽最优**，代价是只对 2 的幂优雅。
:::

## 03-2｜Tree：上行归约、下行广播

::: info 本单元目标
围绕 **Tree 的两段式结构与热点问题** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

RD 全员对称，但要求 2 的幂。另一族 log 轮次算法对**任意 N** 都优雅——树。

### 3. 结构：上行收集、下行分发

以 8 rank 的二项树（binomial tree）为例：

```text
上行归约（Reduce，log₂N 轮）          下行广播（Broadcast，log₂N 轮）

      0 ← 全量                          0 → 全量
     / \                               / \
    1   2                             1   2
   /   / \                           /   / \
  3   4   5                         3   4   5
 /                                      \
6                                         7（示意，非严格二项树）
```

- **上行**：叶子把数据发给父节点，父节点加总后继续上发——每轮"活的节点"减半，log₂N 轮后根持有全量；
- **下行**：根把结果沿原路发回，每轮"知道结果的节点"翻倍，log₂N 轮后人人有全量。

**Tree AllReduce = 上行 + 下行，总延迟 ≈ 2·log₂N·α**——N=1024 时约 20 轮（对比 Ring 的 2046 轮）。

### 4. Tree 的脾气：热点与不对齐的账

**热点问题**：靠近根的链路承载重流量（根的入边每轮收 S）——**非带宽最优**。对比 RD：每轮人人都在配对，链路负载对称。

**账本对齐**（N=8）：

| 维度 | Ring | RD | Tree |
| --- | --- | --- | --- |
| 轮次（α 项） | 2(N−1) = 14 | log₂N = 3 | 2·log₂N = 6 |
| 每 rank 流量（β 项） | ~1.75S ✅ 最优 | 3S | 依赖结构，根附近重 |
| N 非 2 的幂 | ✅ 优雅 | 需变体 | ✅ 优雅 |
| 对称性/容错 | 人人平等 | 人人平等 | 根是单点 |
| 拓扑友好（预 22 章） | 环 | 配对 | **层级天然匹配**（根=节点代表） |

::: tip 工程里的 Tree：不只是"另一条路"
1. **层级映射**：把树的"根"放在汇聚点（如节点代表网卡），上下行恰好贴合机内/机间两级拓扑——第 5 章分层算法的主角之一；
2. **引擎卸载**：HCCL 的 Tree 族常与专用执行引擎（CPU_TS/AICPU 等，见 [HCCL 源码 4](../ascend/hccl-source/04-comm-engines.md)）绑定——小消息场景让计算核心专心算，通信交给协处理器。
:::

## 03-3｜选型地图：大小消息的分界线

::: info 本单元目标
围绕 **"消息大小 × rank 数"的选型决策** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

三族算法齐了：Ring（带宽最优、轮次线性）、RD（log 轮次、全量交换）、Tree（log 轮次、层级友好）。现在画地图。

### 5. 分界线是算出来的

令两个算法的总时间相等，解出消息大小 S*：

$$
S^* \approx \frac{\alpha \cdot \Delta\text{rounds} \cdot BW}{\Delta\text{bytes-per-rank}}
$$

**N=8**（上单元算过）：S* ≈ 4.4 MB——小于它 RD/Tree 赢，大于它 Ring 赢。

**N=64**（α=20 µs、BW=25 GB/s，同一组参数）：

```text
Ring：126α + 1.97S/BW        RD：6α + 6S/BW
Ring 更快 ⟺ 120α > 4.03S/BW ⟺ S* ≈ 14.9 MB
```

规律：**N 越大，Ring 的轮次劣势越重，分界点越往大消息方向推**——大集群上"小消息"的定义被放大了。

#### 5.1 三维选型地图

| 场景 | 主导项 | 首选 |
| --- | --- | --- |
| 小消息（KB 级）· 任意 N | α | Tree / RD |
| 大消息（MB+）· N 为 2 的幂 | β | Ring（或 Rabenseifner） |
| 大消息 · N 非 2 的幂 | β | Ring |
| 大消息 · 超大 N（跨机） | β + α | **Ring + 分层**（第 5 章） |
| 小消息 · 跨机多节点 | α + 拓扑 | **Tree + 分层**（第 5 章） |

### 6. 没有银弹，只有账本

三条通用直觉，比背地图更重要：

1. **α 和 β 谁说了算，取决于消息大小与轮次差的乘积**——不是"消息小就用 Tree"这么机械，N 也会挪动分界线；
2. **拓扑是隐藏的第三维**：本章的账本默认"链路同质"，真实机器机内/机间带宽差一个数量级——下一章分层会把地图重画一遍；
3. **约束条件经常一票否决**：非 2 的幂直接排除朴素 RD；有专用通信引擎时 Tree 有额外加成。**先排约束，再算账。**

## 03-4｜工程视角：selector 与代价模型

::: info 本单元目标
围绕 **通信库内部的算法选择机制** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

理论地图在手，看工程怎么落地——通信库不可能让用户每次手选算法。

### 7. selector：库里的选型器

主流通信库（HCCL/NCCL）内部都有一个 selector，输入大致是 `(op, 消息大小, rank 数, 拓扑信息)`，输出算法与参数。两种实现风格：

- **静态表**：预先标定好"大小区间 × rank 数 → 算法"的查找表（快、但换个集群就可能失准）；
- **代价模型**：用实测校准的 α、β 代入公式动态比较（灵活、但依赖参数新鲜度）。

工程实践通常是**两者混合**：粗区间查表 + 边界附近用模型微调。

#### 7.1 显式干预与实测

- **环境变量覆盖**：HCCL 的 `HCCL_ALGO`、NCCL 的 `NCCL_ALGO` 可以强制指定算法——调优与排障的利器（详见 [CANN 常用命令：分布式环境变量](../ascend/cann常用命令.md)）；
- **基准实测**：用 hccl_test / nccl-tests 的 `allreduce` 拉一条"消息大小 → 带宽/时延"曲线，**分界线在哪、selector 选得对不对，一眼可见**；

```bash
# 典型用法：从 8B 扫到 1GB，画全量曲线
mpirun -n 8 ./bin/all_reduce_test -b 8 -e 1G -f 2 -w 5
```

::: warning 理论给方向，实测定边界
本章公式里的 α、β 是"这台机器、这个拓扑"的实测值——**换硬件、换网络配置，分界线就移动**。选型地图要背的是形状，不是数字。
:::

### 8. 本章收束

三族算法、一张地图、一个 selector——"从语义到选型"的链路补完。但本章所有账本都默认**一条同质链路**；真实集群是"机内高速 + 机间低速"的两层世界，算法要在这两层上重新编排——这是下一课（也是《集合通信》的收官课）的主题。

三个场景各排除哪些算法、为什么：① N=48 的集群同步 32 MB 梯度；② N=8 同步 64 KB；③ 需要把通信卸载给专用引擎、且 rank 数不定。

### 10. 自测题

1. RD 第 k 轮的配对距离是多少？"知情圈"每轮怎么变？
2. 为什么 RD 做 AllReduce 不需要广播阶段？
3. RD 每 rank 的总流量是多少？为什么大消息吃亏？
4. Recursive Halving 相比 RD 省在哪？它的适用算子是什么？
5. Tree AllReduce 的两个阶段各几轮？
6. Tree 的"热点"出在哪、为什么？
7. N 越大，Ring 与 RD 的分界点怎么移动？为什么？
8. 什么情况下"消息小就用 Tree"这句话会失效？
9. selector 的两种实现风格是什么、各自的风险？
10. 怎么用一条实测曲线验证 selector 的选择？

::: details 自测答案

1. 距离 2^(k−1)（1, 2, 4, …）；知情圈每轮翻倍，log₂N 轮覆盖全组。
2. 配对交换是双向的，双方交换后各自加总——结束时每个 rank 都持有全量结果。
3. S·log₂N（每轮交换全量部分和）；大消息时 β 项远超 Ring 的 ~2S(N−1)/N。
4. RH 每轮把消息对半、只发一半——总流量 S(N−1)/N 带宽最优且 log₂N 轮；适用算子是 ReduceScatter。
5. 各 log₂N 轮，共 2·log₂N·α。
6. 根节点及近根链路：每轮都要收发聚合流量，负载不对称——非带宽最优，根还是单点。
7. 越往大消息方向移：N 增大时 Ring 的轮次 2(N−1) 线性膨胀，α 差距拉大，需要更大的 S 才能让 β 项追回来（N=8 时 S*≈4.4MB，N=64 时≈14.9MB，同参数）。
8. 约束一票否决时（如非 2 的幂排除朴素 RD）、拓扑异质时（分层场景重画地图）、有引擎加成时。
9. 静态表（快但换集群失准）与代价模型（灵活但依赖 α/β 校准新鲜度）；工程常混合。
10. allreduce 基准从 8B 扫到 1GB 画"大小 → 带宽/时延"曲线，观察分段拐点是否与 selector 的算法切换一致，也可用环境变量强制单算法对照。

:::

### 11. 本课小结

- RD：log₂N 轮配对会师，双向对称无需广播，但每轮全量、需 2 的幂；
- Tree：上行 + 下行各 log₂N 轮，任意 N 优雅、层级与引擎友好，代价是根部热点；
- 分界线 S* 可用 α、β、N 算出，但随硬件移动——地图背形状、数字靠实测；
- selector = 静态表 + 代价模型，环境变量可覆盖，基准曲线是最终裁判。
