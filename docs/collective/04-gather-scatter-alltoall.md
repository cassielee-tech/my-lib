# 第 4 章｜AllGather、ReduceScatter 与 AlltoAll

> 本课目标：掌握三大单原语的语义（数据布局怎么变）、典型算法与账本；把它们挂到 TP/SP/FSDP/MoE 的真实用法上；理解 MoE AlltoAll 失衡的根源与缓解路线。

## 本章导学

::: tip 本课只记住 3 件事
1. **AllGather：`[S/N] → [S]`**（每人一碎片 → 人人有全量，复制拼装）；**ReduceScatter：`[S] → [S/N]`**（规约后各持一段）——它们是 Ring AllReduce 拆开的两个半场，也是 TP/SP/FSDP 的日常动词。
2. **AlltoAll 是"定向搬运"不是"复制"**：每人发给每人不同的一块，**总量守恒、按目的地重排**——MoE dispatch/combine 的骨架。
3. **MoE 的 A2A 之难在动态失衡**：路由在运行时决定流量，同步集合通信被最慢的方向拖死——**木桶效应**。
:::

## ⚡ 速通（约 5 分钟）

> 适用：时间紧，或完整版跟不动时。这页用"办公室分发动作"讲完整章，读完抓住 80% 的主干。任何一节想深入，拉到文末点对应单元。

### 1. 复印发全员：AllGather

每人手里有一章稿子（合起来是一份完整报告）。**AllGather = 每人复印自己那章、发给所有人**——结束后人手一册完整报告。

- 形状变化：每人 `[1/4 本]` → 人人 `[完整 4 章]`；
- 报告被复制了 4 份（4 = 人数）；
- 谁在用：TP 前向（各卡算出激活的不同切片，拼全才能算下一步）、FSDP（参数平时分片存，用时拼全）。

::: details 小测 1：AllGather 和 AllReduce 的关系？
AllReduce = ReduceScatter + AllGather（黄金恒等式）。Ring AllReduce 的下半场舞步，单独跳就是一次完整的 AllGather——账本也正好是 AllReduce 的一半。
:::

### 2. 汇总后各撕一章：ReduceScatter

每人手里都有一份**带批注的全稿**（内容不同、要合并）。**ReduceScatter = 全员逐段求和，然后每人撕走自己负责的那一章**——你拿到"数学章的全组批注之和"，他拿到"语文章的"。

- 形状变化：每人 `[全稿]` → 每人 `[自己那章的合并版]`；
- 只规约、不复制全量；
- 谁在用：TP 反向（梯度求和后各拿自己参数段）、FSDP 反向（比 AllReduce **省一半**——别人的梯度段对我没用）。

::: details 小测 2：FSDP 反向为什么用 RS 不用 AllReduce？
参数本来就分片存：我只需要"我这段参数"的梯度。AllReduce 给每人全长（2S），RS 只给各段（S）——**语义上够用的最小原语**，通信直接省一半。
:::

### 3. 各部门互寄快递：AlltoAll

前两个都是"汇总/复制"，第三个是**搬家**：每个部门把自己手里的包裹按**收件地址**分好，同时寄出——寄给谁的、寄多少，**出发前就查好路由**。

- 形状变化：每人总量**不变**，但内部按"目的地"重排了（近似一次转置）；
- 和 AG 的本质区别：**总量守恒、人人拿到的都不一样**（AG 是总量翻倍、人人拿到一样的）；
- 谁在用：MoE 的 dispatch/combine（token 按路由结果寄往专家所在的卡）。

### 4. MoE 的快递为什么总堵：动态失衡

MoE 的"收件地址"是**路由器实时决定**的——今天上午热点在专家 3（他所在的部门爆仓），下午热点换到专家 7。而集合通信是**全员到齐才散场**：7 个方向都寄完了，也得陪最慢的那个等——**木桶效应，最慢方向 = 全体耗时**。

两条缓解路线：

- **模型侧**：辅助损失/均衡约束（让路由别扎堆）、容量因子限流（每个专家设收件上限，超了就丢——通信均匀了，牺牲一点计算）；
- **通信侧**：等大小块 + padding（凑成通信库喜欢的规整形状）、多小块流水（压缩等待空泡——下一课的 chunk/channel 就是钥匙）。

::: details 小测 3：为什么说"同步性放大了失衡的伤害"？
集合通信是同步协议：所有 rank 的 A2A 要一起结束。任何方向慢了，全体都在等它——失衡不是"局部慢"，而是"全体被最慢方向拖死"。
:::

### 3 句话带走

1. **AG 复制拼全**（`[S/N]→[S]`）、**RS 规约分持**（`[S]→[S/N]`）——TP/SP/FSDP 的日常动词；
2. **A2A 是定向搬运不是复制**——总量守恒、按目的地重排，MoE 的骨架；
3. **MoE 之难在动态失衡**——同步集合通信木桶效应；模型侧调流量、通信侧抗失衡。

### 黑话小词典

| 术语 | 人话 |

## 04-1｜AllGather：从分片到完整

::: info 本单元目标
围绕 **AllGather 的布局变化与使用场景** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

### 1. 语义：每人贡献一片，人人拿到全量

```text
开始：rank 0 有 [A]   rank 1 有 [B]   rank 2 有 [C]   rank 3 有 [D]
结束：每个 rank 都有 [A|B|C|D]（按 rank 顺序拼接）
```

- 输入每人 **S/N**，输出每人 **S**——**数据被复制了 N 份**（对比 AlltoAll：总量守恒，下一单元）；
- 没有计算，纯搬运拼装。

#### 1.1 算法：Ring AllReduce 的下半场

第 2 章 AG 阶段**原封不动**就是一个完整的 AllGather 算法：N−1 轮完全块传阅。账本也自然是 AllReduce 的一半：

$$
T_{AG} \approx (N-1)\alpha + \frac{S(N-1)}{N}\cdot\frac{1}{BW}
$$

（另有 RD 风格的 log 轮次变体，选型逻辑同第 3 章。）

### 2. 谁在用 AllGather

| 场景 | 用在哪 | 为什么 |
| --- | --- | --- |
| **TP 前向**（列并行后的激活拼装） | 每层线性层输出后 | 各 rank 算出激活的不同切片，拼全才能进下一个非并行算子 |
| **SP 前向** | Norm/Attention 前的序列维拼装 | 序列并行把序列切段，算子要全序列时先 AG |
| **FSDP** | forward/backward 取参数前 | 参数平时分片存着，用时 AG 展开成完整副本 |

::: tip TP+SP 的"一半魔法"
Megatron 的 TP+SP 组合里，前向用 **AG**、反向用 **RS**（下一单元）——恰好把 AllReduce 拆成两半分别挂在前后向，通信量减半。这正是第 1 章恒等式在工程里的变现（详见 [大模型基础：并行通信总览](../model/01-landscape.md#_01-2-并行策略为什么产生通信)）。
:::

## 04-2｜ReduceScatter：规约后分着拿

::: info 本单元目标
围绕 **ReduceScatter 的布局变化与使用场景** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

### 3. 语义：全员求和，结果各持一段

```text
开始：rank 0 有 [A₀|B₀|C₀|D₀]   rank 1 有 [A₁|B₁|C₁|D₁]   … （每人都有全长的输入）
结束：rank 0 有 [A*]   rank 1 有 [B*]   rank 2 有 [C*]   rank 3 有 [D*]
      （A* = A₀+A₁+A₂+A₃，即"逐块求和后按块分发"）
```

- 输入每人 **S**（N 份待规约），输出每人 **S/N**——**Reduce 的"人人有份"换成了"各拿一段"**；
- 这是第 1 章 ReduceScatter 卡片的落地，也是 Ring AllReduce 的**上半场**（RS 阶段原封不动）。

#### 3.1 算法与账本

Ring RS：N−1 轮"累积块右移、边传边加"（第 2 章手推过）。账本与 AG 对称：

$$
T_{RS} \approx (N-1)\alpha + \frac{S(N-1)}{N}\cdot\frac{1}{BW}
$$

::: warning 一个容易混的记号
公式里的 S 指**输入全长**。RS 和 AG 各自传 S(N−1)/N 字节——**AllReduce = 两者相加 = 2S(N−1)/N**，与第 2 章账本完全一致。恒等式在账本层面也成立。
:::

### 4. 谁在用 ReduceScatter

| 场景 | 用在哪 | 为什么 |
| --- | --- | --- |
| **TP 反向** | 梯度规约 | 各 rank 算出的梯度要先求和；求完和再分片，每人正好持有自己负责的参数段梯度 |
| **SP 反向** | 与 TP 前向 AG 对偶 | 前向拼装多少，反向散回多少 |
| **FSDP** | backward 梯度规约 | 各 rank 累完本地梯度，RS 后每人只规约自己参数段的梯度，随后更新 |

#### 4.1 与 FSDP 的省钱逻辑

FSDP 反向若用 **AllReduce** 规约梯度：每人拿全长梯度（通信 2S(N−1)/N）。用 **RS**：只拿自己那段（S(N−1)/N，**省一半**）——因为参数本来就是分片存的，别人的梯度段对我没用。**"语义上够用的最小原语"是通信优化的第一直觉**（呼应 [《训练与推理系统》第 1 章：训练中的通信](../systems/01-training-loop.md#_01-4-训练显存与梯度通信)）。

## 04-3｜AlltoAll：定向重分发

::: info 本单元目标
围绕 **AlltoAll 的定向搬运语义与均衡算法** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

AG 复制、RS 规约——第三个原语干的是完全不同的事：**搬家**。

### 5. 语义：按目的地重排，总量守恒

每个 rank 的数据切成 N 块，**第 j 块只发给 rank j**（各 rank 收到的块数、块大小可以不同）：

```text
发送视角（rank 0 的数据按目的地切）：        接收视角（rank 0 收到来自各方的块）：
[→0][→1][→2][→3]                          [←0][←1][←2][←3]
                                              ↑ 每个"来自 j"的块被放进第 j 格
```

对每个 rank 来说：**发送总量 = 接收总量**（数据没有复制、没有减少）——但**内部布局按"目的地"重排了**。如果画成矩阵，AlltoAll 近似一次**转置**：行索引从"内容归属"变成"数据来源"。

#### 5.1 与 AllGather 的本质区别

| | AllGather | AlltoAll |
| --- | --- | --- |
| 语义 | 复制拼装 | 定向搬运 |
| 每 rank 持量 | S/N → **S**（变多） | V → **V**（守恒） |
| 谁拿什么 | 人人拿一样的全量 | 人人拿**不一样的**专属子集 |
| 典型用户 | TP/SP/FSDP | **MoE**、TP↔SP 布局互转 |

### 6. 均衡情况：逐对交换

当每个 rank 发往各方向的量**相等**（均衡），经典算法是**逐对交换（pairwise exchange）**：N−1 轮，每轮 rank r 与 (r XOR k) 互换双方互发的那一块——结构上就是"RD 的舞步、AG 的节奏"。

- 每 rank 总流量 ≈ 发送总量 V（带宽友好）；
- 轮次 N−1（α 项与 Ring 同量级）；
- 也可叠加 2N 分块、多 channel 等流水手段（第 5 章）。

::: tip 均衡是好日子，MoE 不是好日子
本单元的账本全部建立在"每方向等量"上。一旦各方向流量不等（下一单元的 MoE），逐对交换的每轮要对齐**较大方**，账本开始失真——这正是 A2A 成为"最难调优的集合通信"的原因。
:::

## 04-4｜MoE 的 AlltoAll 为什么难

::: info 本单元目标
围绕 **A2A 失衡的根源与缓解路线** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

MoE 每个 token 由路由器**动态**决定去哪个专家——而专家分布在不同 rank 上。

### 7. 失衡的链条

```text
路由动态决策 → 各 rank 发往各方向的量不均且不可预测
        ↓
逐对交换的每轮要对齐"较大方"（快的一方在等）
        ↓
同步集合通信：最慢的方向决定整体时长（木桶效应）
        ↓
热点链路 + straggler 双重浪费
```

**为什么同步性放大了伤害？** 集合通信是"全员到齐才散场"的协议：哪怕 7 个方向都发完了，最后一个方向的链路没空出来，全体 rank 都在等——**最慢方向 = 全体耗时**。

#### 7.1 两条缓解路线

**模型侧**（改变流量的分布）：

- **辅助损失 / 负载均衡约束**：训练时惩罚"专家冷热不均"，让路由本身更均匀（详见 [《并行策略》第 1 章：Token 分发](../parallel/01-moe-expert-parallel.md#_01-3-token-重排与-alltoall)）；
- **容量因子（capacity factor）限流**：每个专家设接收上限，超量 token 直接丢弃——通信变均匀的代价是少量计算被牺牲。

**通信侧**（在失衡下求效率）：

- **等大小块 + padding**：把不等长的发送拆成等大小小块矩阵（通信库喜欢的规整形状），短的一方补零——规整换吞吐，代价是白传 padding 字节；
- **多小块流水 + 多 channel**：把大块拆小流水化，压缩"等待对齐"的空泡（第 5 章的 chunk/channel 正是这里的钥匙）。

### 8. 本章收束：三原语各就各位

```text
AG：复制拼全   ← TP 前向 / SP 前向 / FSDP 取参数
RS：规约分持   ← TP 反向 / SP 反向 / FSDP 梯度
A2A：定向搬运  ← MoE dispatch/combine / 布局互转（难在动态失衡）
```

选原语的第一直觉：**"语义上够用的最小原语"**——要分片结果就别复制全量（RS 而非 AllReduce），要定向搬运就别全员广播（A2A 而非 AG）。算法与拓扑如何进一步托举这些原语，是下一课（《集合通信》收官）的主题。

### 10. 自测题

1. AllGather 的输入/输出形状分别是什么？数据被复制了几份？
2. Ring AG 的轮次与每 rank 流量是多少？
3. TP 前向为什么需要 AllGather？接在什么算子之后？
4. ReduceScatter 结束时每个 rank 手里有什么？
5. FSDP 反向用 RS 而不是 AllReduce 规约梯度，省在哪里？
6. AlltoAll 与 AllGather 的本质区别（从"总量"和"谁拿什么"两点答）？
7. 均衡 A2A 的逐对交换每轮在做什么？结构上像哪个算法的舞步？
8. 为什么说"同步性放大了 MoE 失衡的伤害"？
9. 容量因子限流的收益与代价分别是什么？
10. "语义上够用的最小原语"是什么意思？举一个本章的例子。

::: details 自测答案

1. 输入每人 S/N（一片），输出每人 S（按 rank 顺序拼接的全量）；数据被复制了 N 份。
2. N−1 轮完全块传阅；每 rank 流量 S(N−1)/N。
3. 列并行的线性层输出后：各 rank 持有激活的不同切片，拼全才能进入下一个需要全量输入的算子（如 Norm/非线性）。
4. 恰好一段"该段的全体之和"（S/N 的完全规约块）。
5. AllReduce 让每人拿全长梯度（2S(N−1)/N），RS 只拿自己参数段（S(N−1)/N）——参数本就分片存，别人的梯度段无用，省一半通信。
6. 总量：AG 变多（复制）、A2A 守恒（搬运）；谁拿什么：AG 人人拿一样的全量、A2A 人人拿不一样的专属子集。
7. rank r 与 (r XOR k) 互换双方互发的那一块；舞步同 RD（配对地址异或），节奏同 Ring（N−1 轮带宽友好）。
8. 集合通信全员到齐才散场：7 个方向发完也得陪最慢的方向等——最慢方向决定整体时长（木桶效应）。
9. 收益：通信变均匀、峰值可控；代价：超限 token 被丢，牺牲少量计算/精度。
10. 选语义够用且通信量最小的原语，而不是无脑 AllReduce；例：FSDP 梯度用 RS 而非 AllReduce。

:::

### 11. 本课小结

- AG 复制拼全、RS 规约分持——Ring AllReduce 的两个半场各自独立成军，支撑 TP/SP/FSDP；
- A2A 是定向搬运：总量守恒、按目的地重排，MoE 的 dispatch/combine 骨架；
- MoE 之难在动态失衡：模型侧调流量分布、通信侧在失衡下求效率；
- 选原语第一直觉：语义上够用的最小原语。
