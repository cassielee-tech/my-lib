# 单元 03-1｜Recursive Doubling：距离翻倍的会师

> 所属章节：[第 3 章｜Tree、RD 与算法选择](../03-tree-algorithms-selection.md)

::: info 本单元目标
围绕 **RD 的配对规则与账本** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

Ring 的软肋是轮次：N−1 轮起步价。要砍轮次，思路只有一个——**每轮之后，"已合并的队伍规模"翻倍**。这就是 Recursive Doubling（RD，递归倍增）。

## 1. 舞步：距离每轮翻倍

规则：第 k 轮，rank r 与 rank (r XOR 2^(k−1)) 配对（即距离 1, 2, 4, … 逐一翻倍），**双方交换各自的部分和，各自加总**。

N=8 的完整配对表：

```text
第 1 轮（距离 1）：0↔1   2↔3   4↔5   6↔7   → 每人拥有 2 人之和
第 2 轮（距离 2）：0↔2   1↔3   4↔6   5↔7   → 每人拥有 4 人之和
第 3 轮（距离 4）：0↔4   1↔5   2↔6   3↔7   → 每人拥有 8 人之和 = 全量 ✓
```

**为什么 log₂N 轮就够？** 每轮配对后，双方都持有两支队伍的并集之和——"知情圈"每轮翻倍：1→2→4→8，log₂N 轮后知情圈覆盖全组。

**为什么不需要广播阶段？** 交换是**双向对称**的：双方交换后**各自加总**，所以结束时**每个 rank 都有全量结果**——AllReduce 一步到位，不像 Tree（下一单元）还要"先收上去、再发下来"。

## 2. RD 的账本

- **轮次（延迟项）**：log₂N 轮——N=8 时 3 轮，对比 Ring 的 14 轮；
- **每轮流量**：交换的是**当前部分和**（全量 S 字节）——每 rank 经手 **S·log₂N**。

代入 α=20 µs、BW=25 GB/s、N=8：

```text
Ring：T = 14α + 1.75S/BW
RD  ：T =  3α + 3.00S/BW

Ring 更快 ⟺ 11α > 1.25S/BW ⟺ S < 11 × 20µs × 25GB/s / 1.25 ≈ 4.4 MB
```

**S 小于约 4.4 MB 时 RD 赢，大于则 Ring 赢**——分界线不是拍脑袋，是账本算出来的。

::: warning RD 的两个约束
1. **需要 N 为 2 的幂**：非 2 幂时距离翻倍配不齐（工程上用"先掰平再倍增"的变体处理，但复杂度上升）；
2. **每轮发全量**：S 越大越亏——它把"轮次少"赚来的 α 全吐给了 β。
:::

::: tip 亲戚算法：Recursive Halving（RH）
做 **ReduceScatter** 时有个更省的版本：每轮把消息**对半分**、一半发出去、一半留下——发出去的量逐轮减半，总流量恰好 S(N−1)/N（**带宽最优**）且轮次 log₂N。RH（做 RS）+ RD（做 AG）的组合是经典的 Rabenseifner AllReduce：**log 轮次 + 带宽最优**，代价是只对 2 的幂优雅。
:::
