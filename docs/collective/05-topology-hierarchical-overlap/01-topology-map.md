## 1. 两层世界

一台 AI 服务器内部 vs 服务器之间，是两个带宽量级：

| 层 | 典型互联 | 量级 | 形态 |
| --- | --- | --- | --- |
| **机内**（跨卡） | 昇腾 HCCS / NVLink / 昆鹏 UB | 百 GB/s 级 | 近似全互联（任意两卡高速直连） |
| **机间**（跨机） | PCIe 网卡 / RoCE / InfiniBand | 几十 GB/s 级（每卡） | 交换网络（多跳、共享） |

- 机内/机间**差近一个量级**，而且机内是"专线"、机间是"共用公路"；
- 关于 AI Server 内部的完整叙事见 [大模型基础：AI Server](../../model/01-landscape/02-parallelism-communication.md) 与 [算力厂商加速卡专题](../../device/accelerator-cards-2026.md)；HCCL 如何探测这两层拓扑，见 [H01-5：通信引擎与任务执行](../../ascend/hccl-source/05-comm-engines.md)。

### 1.1 第 2 章的伏笔：逻辑环 ≠ 物理连线

环是**逻辑编排**（第 2 章 warning）。同一批 64 个 rank（8 机 × 8 卡），两种排布：

```text
不管拓扑的环（rank 乱序）：环上相邻的 rank 大多在不同机器
   → 几乎每一跳都挤机间"共用公路" → 每卡约 2S 字节过网

拓扑感知的环（按节点分段排布）：同机的 8 个 rank 排在一起
   → 环上只有 8 跳跨机器，其余 56 跳走机内专线
   → 过网流量骤降到"每节点一份"量级
```

## 2. 拓扑感知：通信库的第一课

真实通信库（HCCL/NCCL）启动时都要做**拓扑探测**：识别哪些 rank 同机、经什么链路互联、有几张网卡——然后才决定算法与排布。这就是 [H01-5](../../ascend/hccl-source/05-comm-engines.md) 里"Server 内/Server 间"两套场景的由来。

**一个反直觉的结论**：拓扑感知排布的 flat ring，机间流量已经接近显式分层方案（下一单元）——因为贵的链路只搬"每节点一份"。所以：

::: warning 别背"分层一定快"
分层不是魔法咒语，它的本质只有一句话：**让贵的链路少搬字节**。凡是达到这个效果的排布/算法组合都算数——显式分层只是其中最清晰的一种形式。
:::
