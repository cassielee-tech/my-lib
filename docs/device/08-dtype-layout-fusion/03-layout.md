# 单元 08-3｜Layout：张量在内存里的摆法

::: info 本单元目标
围绕 **布局的系统代价与隐式转换** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。

第 3 章（03-4）说过布局是"双刃剑"——本单元从**系统层**看它：布局不只是某个算子的访问模式问题，而是**贯穿全图的账单**。

### 5.1 同一份数据，几种摆法

```text
逻辑上：图片批次 [N, C, H, W]
物理上（内存里字节怎么排）：
  NCHW：按图片排——同一张图的所有通道放一起
  NHWC：按像素排——同一位置的所有通道放一起（C 连续，对卷积/访存合并友好）
分块布局：为了矩阵单元的分块加载，把数据按块交织存放
```

**没有绝对好的布局，只有与消费方匹配的布局**：卷积可能偏好 NHWC，某个 GEMM 实现要求转置后的矩阵，通信原语对切分后的形状有自己的假设（《集合通信》的伏笔）。昇腾上还有为 Cube 通路服务的专用分块排布格式——名字先不背，记住"**硬件友好 ≠ 人眼友好**"即可。

### 5.2 转换的真实代价

把数据从一种摆法换到另一种（Transpose / Reformat / Contiguous）= **完整的一读一写**（第 3 章练习算过：`[8,4096,4096]` 的 fp16 张量转置一次 ≈ 537 MB 的 HBM 流量）。

更隐蔽的是**隐式转换**：图编译时，相邻算子期望的布局不一致，编译器自动插入一个 Reformat 节点——它不在你的代码里，却在你的时间线里。**优化好的网络里，Reformat 常常是"白吃白占"的大头之一**：06-3 说的图优化（融合）也包含"转换+计算合并"这类模式。

### 6. 布局决策的三条原则

1. **先测量再调整**：时间线上找 Reformat/Transpose 节点，算它占总时长的比例——不显著就别动（避免过早优化）；
2. **转换值得发生一次，不值得反复发生**：一次转换后的布局让后续多个算子受益才划算；两个算子各转一次来回折腾是典型浪费；
3. **跟着数据的最大消费者走**：一段计算里最贵的算子（通常是 GEMM/Conv）偏好的布局优先，前后小算子适应它——让"大户"满意，小户的分摊才划算。
