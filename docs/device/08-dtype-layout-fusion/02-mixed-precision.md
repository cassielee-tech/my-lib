"混合精度"不是把整个模型一刀切换成 BF16，而是**每个对象各用各的精度**——承重处用高规格，填充处用省料。

### 3.1 训练中的精度分配表

| 对象 | 典型精度 | 为什么 |
| --- | --- | --- |
| 权重（前向/反向用） | BF16/FP16 | 计算主体，省显存带宽 |
| **Master 权重（优化器里的正本）** | **FP32** | 参数更新的累计精度不能丢 |
| 梯度 | BF16/FP16 | 量大，低精度收益直接 |
| **优化器状态（AdamW 的 m/v）** | **FP32** | 统计量对精度敏感，且要配 FP32 正本 |
| 激活 | BF16 | 量最大，最需要省 |
| **累加器 / 归约统计（Norm 的均值方差）** | **FP32** | 见下面的"铁三角" |

三条经验法则：

1. **累加用高精度**：矩阵乘加单元内部用 FP32 累加器——几千次 BF16 乘加的误差若用低精度累加会迅速积累；
2. **统计量要准**：RMSNorm/LayerNorm 的均值方差是"除数"，算歪了整层跟着歪；
3. **BF16 基本免 Loss Scaling**：范围同 FP32，小梯度不容易下溢——这是它取代 FP16 成为 LLM 主流的工程原因（FP16 路线的放大-还原流程见[《训练与推理系统》第 1 章](../../systems/01-training-loop/03-lr-mixed-precision-clipping.md)）。

### 4. 推理侧与排障

**推理**的精度菜单更激进：权重 Weight-Only 量化（INT8/INT4 存储 + 反量化计算）、W8A8（权重激活都低精度）、KV Cache 量化——选型与代价见[《并行策略》第 2 章](../../parallel/02-efficient-llm-design/02-quantization.md)。

**精度问题的两张面孔**：

- **溢出**：出现 NaN/Inf，Loss 突然爆炸——查哪个对象超了范围（FP16 典型）；
- **下溢**：梯度悄悄变 0、Loss 不降——小数值低于表示范围（FP16 梯度典型）。

定位思路：先锁定**第一个出现异常值的张量**（逐层插入检查或开 DEBUG 日志），再决定是升精度、加 scaling 还是换 BF16。
