# 单元 04-2｜Tiling：把大算子切成块

> 所属章节：[第 4 章｜Kernel、Tiling 与流水线](../04-kernel-tiling-pipeline.md)

::: info 本单元目标
围绕 **Tiling 的两个维度与约束** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

大算子既放不进片上存储，也不能只让一个计算单元干——Tiling 同时解决这两个问题。

### 3.1 两个维度：先分人，再分趟

```text
一个 [8192, 8192] × [8192, 8192] 的 GEMM

第一层：多核切分（谁做哪块）              第二层：核内切分（每块内部怎么循环）
┌────┬────┬────┬────┐
│ B0 │ B1 │ B2 │ B3 │   256 个输出块        每 block 拿到 [512,512] 输出
├────┼────┼────┼────┤   分给 N 个核          内部沿 K 维再切 16 趟
│ B4 │ B5 │ B6 │ B7 │   → 每个 block          每趟：搬入两块输入 → 累加
├────┼────┼────┼────┤     一次"搬入-计算-搬出"    （tile 循环）
│ …  │ …  │ …  │ …  │
└────┴────┴────┴────┘
```

- **多核切分**决定并行度与尾块（02-4 的利用率账）：block 数最好 ≥ 核数且能整除；
- **核内切分**决定复用次数（03-3 的搬运账）：tile 形状决定每个字节在片上参与多少次计算。

两层各有约束，合在一起就是 Tiling 参数空间：`(block 划分, tile 形状, 循环顺序)`。

### 3.2 切分维度不是随便选的

以 GEMM $C[M,N] = A[M,K] \times B[K,N]$ 为例：

| 切分轴 | 切的是什么 | 约束与代价 |
| --- | --- | --- |
| M、N（输出维） | 把输出切块，各 block 独立算 | 天然无依赖，最常用 |
| K（归约维） | 把累加拆成多段 | 各段结果要**累加/规约**，跨核切 K 需要额外的 Reduce 通信 |
| 不切 | 整块驻留 | 只有小算子才可行 |

**归约轴是特殊维度**：切它可以降低单次片上需求，但必须有人把部分和合并——这个"合并"就是通信或额外 Kernel。《并行策略》会看到，并行策略里的 ReduceScatter 本质上就是在切归约维。

### 4. Tile 形状的四本约束账

设计 tile 形状时依次核对：

1. **容量账**：输入/输出 tile + 双缓冲能否放进片上 Buffer（03-4 练习 2 的算法）；
2. **对齐账**：tile 每行的字节数满足对齐要求（常见 32 B 或更大），维度是矩阵单元分块（如 16）的倍数，否则有效带宽和 Tensor Core/Cube 效率打折；
3. **并行账**：block 数覆盖所有核且尽量整除，控制尾块损失（02-4 练习 2）；
4. **复用账**：在容量允许下让 tile 尽量大——搬运量 ≈ 总量 ÷ 复用次数，tile 越大搬运越少。

::: tip 一句话本质
**Tiling = 在容量约束下最大化复用 × 在核数约束下最小化闲置。** 前半句是第 3 章，后半句是第 2 章，本章把它们订成 Host/Device 的合同。
:::
