## 把本章串成一条主线

请先合上各单元正文，沿"Kernel 两半 → 两级切分 → 队列流水 → 完整骨架"复述整章；遇到断点时，再回到对应单元查阅。

```text
Kernel = Host 合同 + Device 认领（04-1）
   Host：解析 shape → 算切分参数 → Launch（有固定开销！）
   Device：按索引认领 → 同一份代码跑在所有单元上（SPMD）
        ↓
Tiling：多核切分（利用率）× 核内分块（复用）（04-2）

        ↓

   节奏 = max(各段耗时)；不能突破带宽上限
        ↓
最小骨架：切分参数·索引认领·尾块边界·双缓冲·完成同步（04-4）
        ↓
第 5 章：用 Roofline 判断"改哪个方向"才值得
```

## 9. 动手练习

### 练习 1：GEMM 切分账

3. 若 block 改为 $[2048,2048]$，读取量放大倍数降为多少？但会引入什么新问题？

### 练习 2：流水收益

一个 Kernel 的每个 tile：搬入 2 ms、计算 2 ms、搬出 1 ms，共 10 个 tile。

1. 完全串行需要多久？理想三段流水后，节奏是多少，总耗时约多少？
2. 若搬入变为 4 ms（计算仍 2 ms、搬出 1 ms），流水后的节奏和计算单元空闲率是多少？此时该优化什么？

1. 总耗时约多少？启动开销占百分之几？
2. 若算子融合后变为 50 个 Kernel（每个计算 400 µs，启动开销不变），总耗时约多少？

## 10. 自测题

1. Kernel 的 Host 侧和 Device 侧各负责什么？
2. SPMD 是什么意思？为什么 Kernel 代码只写一份？
3. Kernel Launch 开销对小算子为什么致命？两种应对手段是什么？
4. Tiling 的两个维度分别对应哪两章的哪两个指标？
5. 为什么归约维（K 维）是特殊维度？切它需要付出什么？
6. 设计 tile 形状要核对哪四本账？
7. Double Buffer 怎样工作？流水后的节奏由什么决定？
8. 列出流水线"失灵"的三种典型情况。
9. 为什么缓冲级数再多也不能突破 HBM 带宽上限？
10. 最小算子骨架的五个部件是什么？

::: details 自测答案

1. Host 侧解析 shape、计算切分参数、准备内存、下发 Kernel；Device 侧每个执行单元按索引认领自己的一段，执行"搬入—计算—搬出"循环。
2. Single Program Multiple Data：同一份 Kernel 代码在所有执行单元上运行，靠各自不同的索引处理不同数据块。
3. 启动开销是微秒级固定成本，小 Kernel 的计算量与它同量级，导致 Device 出现空隙、Host 下发跟不上。应对：算子融合（减少 Kernel 数）与图模式下沉（整图一次性下发）。
4. 多核切分对应第 2 章的利用率/尾块；核内分块对应第 3 章的复用次数/搬运量。
5. 归约维切开后各段是部分和，必须累加合并——跨核切 K 需要额外的规约通信或 Reduce 步骤。
6. 容量账（片上放得下）、对齐账（行字节与矩阵分块对齐）、并行账（铺满核、控制尾块）、复用账（容量允许下 tile 尽量大）。
7. 两块缓冲交替：算 A 块时往 B 块搬下一个 tile。节奏由最慢的一段决定（throughput = 1 / max(各段耗时)）。
8. ① 建立与排空占比过高（tile 太少）；② 某段天然过长（瓶颈段无法被流水缩短）；③ 存在依赖或强制同步切断流水。
9. 流水只改变时间上的重叠，不改变单位时间进入芯片的总字节量——那是带宽的物理上限。
10. 切分参数、索引认领、尾块与边界处理、双缓冲流水、完成同步。

:::

## 11. 本课小结

- Kernel 是 Host 合同与 Device 认领的组合，启动开销决定了"小而碎"天然低效；
- Tiling = 容量约束下最大化复用 × 核数约束下最小化闲置；
- 归约维是特殊维度：切它可以，但要为"合并"付通信代价；
- 队列 + 双缓冲是最小可行流水，节奏由最慢段决定；
- 流水不能突破带宽上限，也不能缩短瓶颈段——它只是消除"互相等待"；
- 最小骨架五部件：切分、认领、尾块、双缓冲、同步——真实 GEMM 同构放大。
