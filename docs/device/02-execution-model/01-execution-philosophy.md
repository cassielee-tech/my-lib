# 单元 02-1｜三种执行哲学：CPU、GPU 与 NPU

同一个矩阵乘法 `y = x @ W`，交给 CPU、GPU 或 NPU，执行方式完全不同。差异不是"谁更快"，而是**硬件把晶体管花在了哪里**。

## 2. 延迟导向与吞吐导向

### 2.1 CPU：用一切手段压低单线程延迟

CPU 的每个核心都很"重"：大容量多级缓存、乱序执行、分支预测、深流水线。它擅长复杂的控制流——指针追逐、函数调用、动态分支——目标是让**每一条指令尽快完成**。

代价是：核心数量有限，规则的大规模数据并行反而发挥不出优势。

### 2.2 GPU：用海量线程掩盖延迟

GPU 走向另一个极端：数百上千个轻量核心，每个核心的能力远弱于 CPU 核心，控制逻辑和缓存都被压缩。

它不怕单个线程等待内存——只要同时存在大量可运行的线程，调度器就让"正在等待的"和"已就绪的"交替占用计算单元。**延迟没有被消除，而是被并行度隐藏了。**

### 2.3 NPU：用专用数据通路做张量计算

大模型负载中，GEMM、卷积等规则矩阵运算占了绝大部分计算量。NPU 干脆放弃通用性，围绕张量计算设计**专用数据通路**：

```text
CPU：   复杂核心 × 少量   →  通用、低延迟、昂贵
GPU：   简单核心 × 海量   →  通用、高吞吐、靠线程隐藏延迟
NPU：   专用通路 + 片上存储层次  →  矩阵计算高能效、不通用
```

三种处理器不是替代关系。一台训练服务器里，CPU 负责框架、调度与数据预处理，GPU/NPU 负责张量计算——异构协作是常态。

## 3. 从晶体管预算看分工

一颗芯片的晶体管数量是有限的，不同架构把预算花在不同地方：

| 维度 | CPU | GPU | NPU |
| --- | --- | --- | --- |
| 晶体管主要花在 | 控制逻辑 + 大缓存 | 大量 ALU + 寄存器堆 | 矩阵计算阵列 + 片上存储通路 |
| 核心数量 | 少（几个到几十个） | 多（数千 CUDA Core） | 多个 AI Core，内部再分 Cube/Vector |
| 延迟处理 | 缩短它（乱序、缓存） | 隐藏它（线程切换） | 组织好搬运，让它不发生（流水） |
| 擅长 | 复杂控制、串行逻辑 | 规模可变的并行计算 | 形状规则的张量运算 |
| 不擅长 | 大规模规则并行 | 复杂分支、串行依赖 | 非张量、动态不规则负载 |

这也解释了为什么**加速卡不能只看 TFLOPS**——峰值来自专用通路在理想条件下的吞吐，真实模型能否吃满，取决于负载特征是否匹配执行模型。产品层面的对比见专题 [2026 主流 AI 加速卡全景](../accelerator-cards-2026.md)。

::: warning 术语陷阱
"Core"在三种平台上含义不同：CPU 的 Core 是完整通用核心；GPU 的 Core 是一个线程执行通道；昇腾的 AI Core 是包含多种计算单元和存储的完整计算单元。跨平台比较时先确认对方说的是哪一种。
:::
