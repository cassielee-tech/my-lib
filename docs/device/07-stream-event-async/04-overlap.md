### 7.1 三种经典重叠模式

**模式 A：搬运与计算（提前备料）**

```text
搬运流：  [H2D batch N+1]                      ← 提前搬下一批
计算流：  [forward N] [backward N]              ← 同时算这一批
Event：    计算 N 用到 batch N+1 前必须等 H2D 完成
```

04-3 的 Double Buffer 是它在 **Kernel 内部**的版本；这里是**任务级**的版本——数据加载、H2D 传输与计算全程流水。

**模式 B：通信与计算（边对账边干活）**

```text
通信流：  [AllReduce bucket-1] [AllReduce bucket-2]
计算流：  [backward layer-31] [backward layer-30] [layer-29] …
```

DDP 的标准操作（《模型全景》第 2 章 《模型全景》02-4 预告过）：反向传播**从后往前**逐层产出梯度，后层梯度装 Bucket 先发走，通信与剩余层的反向同时进行。**前提**：梯度聚合必须在 `optimizer.step()` 之前全部完成——一个跨流的 Event 收尾。

**模式 C：多任务流水（多段接力）**

Prefill 与 Decode 分流、多个 micro-batch 接力、独立子图各占一条流——把"大任务内部的空闲"填满。具体形态在《训练与推理系统》的推理系统两章（待写）和《昇腾与 HCCL》展开。

### 7.2 重叠的两个敌人

**敌人一：假并行。** 任务名义上分了流，但同步点把执行序重新串成一条线（如每个小任务都 `synchronize`）——车道修了，闸门全关着。**诊断**：时间线上车道存在但互相咬死，总时长 ≈ 串行。

**敌人二：错并行。** 没有依赖关系就分道——数据竞争，偶发错误结果（07-3 的病一）。**诊断**：加同步后正确性恢复，即是它。
