# 单元 07-1｜异步执行：Host 跑得比 Device 快

> 所属章节：[第 7 章｜Stream、Event 与异步执行](../07-stream-event-async.md)

::: info 本单元目标
围绕 **Host/Device 异步模型** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

最容易被误解、又最影响一切行为的事实：**你调用一个算子时，它几乎一定还没开始执行。**

## 2. 提交与执行是两件事

```text
Host（CPU）                        Device（NPU/GPU）
y = op(x)                          ┌─────────────────┐
   │                                │ 任务队列：op1 op2 op3 …
   ├─ 解析、分发、打包任务 ────────► │  按顺序慢慢执行     │
   ▼                                │                   │
 立刻返回，继续跑下一行 Python        └─────────────────┘
```

Host 做一次 Launch 只要几微秒；一个 Kernel 执行动辄几百微秒到几毫秒。**如果每次调用都等设备做完再返回，CPU 会有 99% 的时间在干等**——所以所有现代框架都是异步提交：Host 一路把任务塞进队列，设备在后面按序消费。

### 2.1 队列会"假装"完成你的代码

异步模型下，这段代码的行为需要重新理解：

```python
a = x.npu()          # 拷贝任务入队
b = layer(a)         # 计算任务入队（还在排队！）
print(b.mean())      # ← 隐式同步点：必须等前面全部完成
```

`print` 需要具体数值，框架被迫在此处等待设备追上来——**`.item()`、`.cpu()`、打印、某些日志都是隐式同步点**。一段代码里这种点太多，异步就名存实亡。

### 2.2 两个必知的副作用

**① 报错是延迟的。** 设备在第 50 个任务处出错时，Host 可能已经提交到第 200 个任务、跑到完全无关的代码行——**Python 堆栈指向的位置基本不可信**。排障时临时改同步执行（`ASCEND_LAUNCH_BLOCKING=1`），让报错当场暴露（详见 [CANN 常用命令速查](../../ascend/cann常用命令.md)第 9 节）。

**② 计时必须用 Event。** `time.time()` 测的是"Host 提交完用了多久"，不是设备执行了多久。正确做法：在任务前后向流里插入 Event，执行结束后读 Event 时间差——这本身就是下一单元 Event 的第一个用途。

::: tip 一句话心智模型
**Host 是"写作业单的人"，Device 是"按单干活的班组"**——单子写完不代表活干完；想知道干没干完，得用下一单元的签认单（Event）。
:::
