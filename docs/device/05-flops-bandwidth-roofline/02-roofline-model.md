第 1 章的两个时间下界——$FLOPs/峰值算力$ 和 $Bytes/峰值带宽$——合起来就是 Roofline。

### 3. 一条屋脊，两段斜坡

设备能给出的性能上限（FLOPs/s）：

$$
P_{max} = \min\left( 峰值算力,\ AI \times 峰值带宽 \right)
$$

画在对数坐标上就是一条"屋顶"：

```text
性能上限(FLOPs/s)  ▲
                   │            ┌──────────── 屋顶：算力上限
                   │           /
                   │          /   ← 右坡不存在，这就是屋顶
                   │         /
                   │        / ← 斜坡：AI × 带宽（左坡，斜率 = 带宽）
                   │       /
                   │      /
                   └──────┴──────────────────► AI (FLOPs/Byte)
                        拐点
                  拐点 = 峰值算力 / 峰值带宽
```

**拐点（Ridge Point）** 是分水岭：

- 算子落在**左坡**（AI < 拐点）：性能 = AI × 带宽 → **Memory-bound**，算力再高也没用；
- 算子落在**屋顶**（AI > 拐点）：性能 = 峰值算力 → **Compute-bound**，带宽再宽也没用。

例：峰值 400 TFLOPS（BF16）÷ 带宽 2 TB/s = **拐点 200 FLOPs/B**。AI=0.17 的逐元素加：上限 = 0.17×2000 ≈ 34 TFLOPS，只用到算力的 8.5%；AI=1365 的 4096³ GEMM：上限 = 400 TFLOPS，与带宽无关。

### 4. 把算子放到图上

三步：

1. **画屋顶**：查目标设备的峰值算力（注意精度口径）和峰值带宽，得到拐点；
2. **算坐标**：算子的 AI 为横坐标，理想 AI 定"天生位置"，实测 AI 定"实际位置"；
3. **读结论**：

| 落点 | 含义 | 优化方向 |
| --- | --- | --- |
| 实际点远低于理想点（同在左坡） | 实现的带宽没用满 | **向上爬**：修访存模式、对齐、流水 |
| 理想点在左坡 | 算子天生搬运重 | **向右挪**：融合、改变算法/边界 |
| 实际点在屋顶但低于屋顶 | 计算通路没吃满 | 修 tile 形状、对齐、低精度（第 2、4 课） |
| 理想点已在屋顶 | 已经 Compute-bound | 换精度 / 换算法 / 接受现状 |

::: tip Roofline 是"天花板图"，不是"成绩单"
图上的屋顶是**可达的上限**，算子实际能摸到屋顶的七八成已属优秀。它的价值是定位方向，不是承诺摸顶。
:::
