## 1. 背景与问题

### 1.1 场景约束

- AIV/SDMA 类常规算法模板不支持 64bit 数据类型（见各算法 `op.unsupportedDataTypes = UNSUPPORTED_64BIT`），也不支持 PROD 规约（`op.isSupportProd = false`）。
- 此类场景只能使用 aicpu 的 `LocalReduce`（hcomm CPU 规约）能力，即 `aicpu_reduce_nhr` 系列 template。
- 该路径每轮 NHR 交换后需要 `HcommBatchModeEnd/Start + HcommThreadJoin` 做 CPU 侧同步，性能天然较差，需求明确不要求耗时。

### 1.2 现状（三个算子一致）

1. template 层：仅有 `aicpu_reduce_nhr` 的 Sole（扁平、单级）实现：
   - AllReduce：`src/ops/all_reduce/algorithm/template/aicpu/ins_temp_all_reduce_aicpu_reduce_nhr.cc`
   - ReduceScatter：`src/ops/reduce_scatter/algorithm/template/aicpu/ins_temp_reduce_scatter_aicpu_reduce_nhr.cc`
   - Reduce：`src/ops/reduce/algorithm/template/aicpu/` 下对应 Sole 模板（由 `ReduceSoleExecutor` 使用）
2. executor 层：仅有 SoleExecutor 注册，没有分级算法：
   - `AicpuAllReduceSoleNHRAicpuReduce`（`ins_v2_all_reduce_sole_executor.cc:431`）
   - `AicpuReduceScatterSoleNHRAicpuReduce`（`ins_v2_reduce_scatter_sole_executor.cc:404`）
   - `AicpuReduceSoleNHRAicpuReduce`（`reduce_sole_executor.cc:357`）
   三者均为 `TopoMatchOneLevel`：把通信域内全部 rank 扁平看作一级，跨框（`topoLevelNums > 1`）时不区分框内/框间链路，整域跑 NHR。
3. selector 层：三个算子的 `SelectAicpuAlgo` 在 `topoLevelNums > 1` 且特殊数据类型/规约时，硬编码路由到上述 Sole 算法（如 `all_reduce_auto_selector.cc:439-440`）。

即：**跨框（两级及以上拓扑）+ 64bit/prod/min/max 场景当前退化为扁平 Sole NHR，没有框内/框间分级编排。**

### 1.3 迭代目标

为三个算子新增**两级 sequence executor（nhr+nhr）**算法：

1. 不新增 template，完全沿用现有 `aicpu_reduce` 系列 template；
2. 在既有两级 sequence executor 文件中增加 `REGISTER`；
3. 排查并修改 costModel / Selector，保证默认只有 64bit 数据类型与特殊规约操作（prod/min/max）才会进入新 executor，其余场景路由不变。

## 2. 设计思路

### 2.1 总体方案

**只加注册、不改框架**：三个算子的两级 sequence executor 框架代码均已存在并被其它算法组合使用（如 `AicpuAllReduceSequenceMeshConcurNHR`、`AicpuReduceScatterSequenceMeshNHRAicpuReduce`、`AicpuReduceSequenceMeshConcurNHR`），本次仅新增"nhr+nhr"的模板组合注册 + selector 路由修改，不动 executor/template 主体逻辑，变更面最小、可审查性好。

### 2.2 关键选型：两级 RS 复用 `InsTempReduceScatterAicpuReduceNHRPcie`

仓内 aicpu_reduce RS 有两个实现，能力差异如下：

| 能力 | InsTempReduceScatterAicpuReduceNHR（Sole 版） | InsTempReduceScatterAicpuReduceNHRPcie（分级版） |
| ---- | ---- | ---- |
| 本 rank 定位 | `sliceIdx == myRank_`，假设 userRank==算法内索引 | `GetAlgRank(myRank_, subCommRanks_[0], myAlgIdx)`，支持任意 subCommRanks 映射 |
| 尾块处理 | 无（只认 sliceSize） | `tailSize` 支持（最后 rank 尾块） |
| 输出步长 | 无 | `outputSliceStride` 支持 |
| repeatNum 多轮 | 有 | 有（框内多框数据重复） |
| in/out 同 buffer | 无处理 | 自动后移 `hcclBuffBaseOff_`，避免读写冲突 |
| scratch 占用 | rankSize 倍 | rankSize*2 倍 |
| 静态 CalcCostCoeff | 有（固定 A=10） | 无（继承基类默认返回空 → 不参与 cost 排序） |

分级 executor 以 `algHierarchyInfo.infos[level]`（框内如 `[0..7]`、框间如 `[0,8,16,24]`）构造 template，userRank 不等于算法内索引，**Sole 版模板直接用于两级编排会错乱**；而分级版已具备 algIdx 映射、尾块、stride、repeatNum 等全部两级编排所需语义，且已被 `AicpuAllReduceSequenceMeshNHRAicpuReduce` / `AicpuReduceScatterSequenceMeshNHRAicpuReduce` 作为 sequence 中的 RS 模板验证过（该注册虽名为 Pcie，模板内部 `IsPcieProtocol` 自动判链路类型，非 pcie 链路走 `SendRecvWrite`，逻辑通用）。

**结论：两级 RS（框内、框间）均复用 `InsTempReduceScatterAicpuReduceNHRPcie`，满足"不新增 template"的要求。**

AllGather 阶段为纯数据搬运，不做规约，64bit 无障碍，复用 `InsTempAllGatherNHR`（已具备 `GetAlgRank` 分级映射，现用作多个分级算法的框间 AG 模板）。

### 2.3 各算子算法编排

#### 2.3.1 AllReduce：RS-L0 → RS-L1 → AG-L1 → AG-L0

复用 `InsV2AllReduceSequenceExecutorAicpu<AlgTopoMatch, T0, T1, T2, T3>`（四模板串行编排，executor 内已处理分轮、ccl buffer 对半切分、对称内存、数据量对齐等）：

```
Step1  框内 ReduceScatter：InsTempReduceScatterAicpuReduceNHRPcie  (infos[0]，NHR 交换 + aicpu LocalReduce)
Step2  框间 ReduceScatter：InsTempReduceScatterAicpuReduceNHRPcie  (infos[1])
Step3  框间 AllGather   ：InsTempAllGatherNHR                        (infos[1])
Step4  框内 AllGather   ：InsTempAllGatherNHR                        (infos[0])
```

与现有 `AicpuAllReduceSequenceMeshNHRAicpuReduce`（Mesh1D 框内 + Pcie 框间，单机 pcie 场景）相比，差异仅为：Step1 由 Mesh1D 换成 aicpu reduce NHR（框内也走 NHR）、Step4 由 `InsTempAllGatherMesh1D` 换成 `InsTempAllGatherNHR`，即"nhr+nhr"。executor 传入的 `TemplateDataParams`（sliceSize/tailSize/stride/repeatNum=1/offset）与分级版模板语义完全对齐，executor 编排代码不需要修改。

#### 2.3.2 ReduceScatter：RS-L0 → RS-L1

复用 `InsV2ReduceScatterSequenceExecutorAicpu<AlgTopoMatch, T0, T1>`（两模板串行编排）：

```
Step1  框内 ReduceScatter：InsTempReduceScatterAicpuReduceNHRPcie  (infos[0]，repeatNum=rankSizeLevel1，逐框数据块)
Step2  框间 ReduceScatter：InsTempReduceScatterAicpuReduceNHRPcie  (infos[1])
```

注意点：分级版模板 `CalcScratchMultiple = rankSize*2`，executor 将框内/框间 multiplier 相乘（≈ 4×L0×L1）后折算 `maxCountPerLoop`，单轮可处理数据量变小、loop 增多。耗时不做要求，接受该折损；正确性由既有分轮机制保证。

#### 2.3.3 Reduce：RS-L0 → RS-L1 → AG-L1 → AG-L0（AGL0 仅 root 写 user output）

Reduce 算子的 aicpu 分级 executor 为 `ReduceSequenceExecutorAicpu3Level`（`reduce_sequence_executor_aicpu_3level.cc`），本身支持两级注册（`TopoMatchTwoLevel` + `skipLevel2_` 跳层，现有 `AicpuReduceSequenceMeshConcurNHR` 即两级注册），root 语义由 `isRootRank_` 控制（非 root 的 AGL0 输出落到 ccl buffer，仅 root 落 user output，见 `GenTempAlgParamsAGL0`）。新增注册（L2 两个模板位因 skipLevel2 不会被拉起，按现有惯例填同款占位）：

```
REGISTER_EXEC_V2_MULTI(HCCL_CMD_REDUCE, <新算法名>, ReduceSequenceExecutorAicpu3Level, TopoMatchTwoLevel,
    InsTempReduceScatterAicpuReduceNHRPcie,   // RS-L0 框内
    InsTempReduceScatterAicpuReduceNHRPcie,   // RS-L1 框间
    InsTempReduceScatterAicpuReduceNHRPcie,   // RS-L2 占位（skipLevel2）
    InsTempAllGatherNHR,                      // AG-L2 占位（skipLevel2）
    InsTempAllGatherNHR,                      // AG-L1 框间
    InsTempAllGatherNHR);                     // AG-L0 框内（root 输出）
```

### 2.4 新算法命名

沿用现有命名法 `<引擎><算子>Sequence<框内算法><框间算法>`：

| 算子 | 新算法名 |
| ---- | ---- |
| AllReduce | `AicpuAllReduceSequenceNHRAicpuReduceNHR` |
| ReduceScatter | `AicpuReduceScatterSequenceNHRAicpuReduceNHR` |
| Reduce | `AicpuReduceSequenceNHRAicpuReduceNHR` |

### 2.5 Selector 路由设计

三个算子的 `SelectAicpuAlgo` 中，`topoLevelNums > 1` 且特殊场景的分支由"一律 Sole"改为"两级走新分级算法、三级维持 Sole"（本次只做两级）：

```cpp
// 以 all_reduce_auto_selector.cc 为例（reduce / reduce_scatter 同型修改）
if (isDataTypeOrReduceTypeSpecial) {
    if (topoInfo->topoLevelNums == TOPO_LEVEL_NUM_2) {
        selectAlgName = "AicpuAllReduceSequenceNHRAicpuReduceNHR";   // 新：两级分级
    } else {
        selectAlgName = "AicpuAllReduceSoleNHRAicpuReduce";          // 三级拓扑暂维持 Sole
    }
}
```

单机（`topoLevelNums == 1`）各分支（Mesh OneShot/TwoShot、单机 pcie-mix 的 `*SequenceMeshNHRAicpuReduce`、CLOS 的 Sole 等）**全部保持不变**。

**进入条件（需求约束：默认只有 64bit 数据类型和特殊规约操作 prod/min/max 才进入）**：

- 64bit 数据类型（`Is64BitDataType`：INT64/UINT64/FP64）→ 进入（此时 sum/prod/min/max 均由该 executor 承接，aicpu `LocalReduce` 全支持）；
- PROD 规约（任意数据类型）→ 进入（沿用现有 `isDataTypeOrReduceTypeSpecial` 判定）；
- 非 64bit 的 min/max → **维持现有常规算法路径**（AIV/aicpu 常规模板本身支持 MIN/MAX，且性能更优；若将其改路由到 aicpu 分级路径会造成无谓回退）。
  - 设计确认点：需求字面为"prod、min、max"。min/max 仅在伴随 64bit 数据类型时进入本 executor；如需求方确认非 64bit 的 min/max 也要切换到本路径，仅需把判定改为 `Is64BitDataType(dt) || reduceType ∈ {PROD, MIN, MAX}`（一行），不影响其它设计。

### 2.6 costModel 排查结论（不改公式）

1. **不参与性能排序**：`InsTempReduceScatterAicpuReduceNHRPcie` 未实现静态 `CalcCostCoeff`，继承 `InsAlgTemplateBase::CalcCostCoeff` 默认返回空（`alg_v2_template_base.h:28`）。ReduceScatter/Reduce 的 sequence executor `CalcCostCoeff` 已有"任一模板返回空则整个算法不参与 CostModel"的短路逻辑；AllReduce 的 sequence executor 聚合后同样得到空结果。⇒ 新算法不会被 cost table 按性能误选，仅由 selector 特判选中，与现有 `*SequenceMeshNHRAicpuReduce` 行为一致。
2. **`GetAlgNetMeta`**：三个 executor 均已实现，随注册自动生效，无需修改。
3. **属性过滤**：新算法 `REGISTER_ALG_ATTRS` 显式声明 `topo.minTopoLevelNum = topo.maxTopoLevelNum = TOPO_LEVEL_NUM_2`，通信域初始化阶段即被 `TopoAttrs` 过滤，3 级拓扑/单机拓扑不会误注册入选；`op` 侧不设数据类型白名单与 `isSupportProd` 限制（能力全集，路由交给 selector），与现有 Sole 版 aicpu reduce 算法保持一致。
4. **资源**：分级版模板 `slaveThreadNum = 0`、单线程，sequence executor 对 thread/notify 取 max 合并，无额外资源需求；`CalcChannelRequestNhr` 按各自 `subCommRanks` 分别建框内/框间链路。

### 2.7 兼容性与约束

- `HCCL_ALGO` 白名单/环境变量指定算法名走 `AlgAttrsRegistry` 检索，新算法名注册后即可被指定，符合现有机制。
- 对称内存（`supportSymmetricMemory`）：AllReduce/ReduceScatter 的 sequence executor 已有对称内存分支，新组合自动继承；Reduce 的 3level executor 与现有 `AicpuReduceSequenceMeshConcurNHR` 行为一致（未特判，随现状）。列入 UT 验证项。
- inplace：AllReduce/ReduceScatter 新算法沿用默认 `isSupportInplace = true`（executor 经 ccl buffer 中转）；Reduce 对齐现有 `AicpuReduceSequenceMeshConcurNHR` 设 `isSupportInplace = false`。
- 保序（DETERMINISTIC_STRICT）：selector 中优先于本分支拦截，走 `*StrictOrderedMesh`，不受影响。
- AICPU_COMPILE 宏：新注册放在 `#if CANN_VERSION_NUM >= CANN_VERSION(9, 0, 0)` 与现有 aicpu sequence 注册同区（模板均为 aicpu 引擎，无需 `#ifndef AICPU_COMPILE` 包裹，与同文件现有 aicpu 注册保持一致）。

## 3. 软件架构

### 3.1 分层与调用链（沿用 HCCL V2 算法框架）

```
Selector 层（本迭代修改：路由特判）
  all_reduce_auto_selector / reduce_scatter_auto_selector / reduce_auto_selector
        │  selectAlgName = "Aicpu*SequenceNHRAicpuReduceNHR"
        ▼
AlgAttrsRegistry / CostTable（不改：新算法不参与 cost 排序，靠 TopoAttrs 过误入）
        │
        ▼
Executor 层（不改代码，仅新增 REGISTER 组合）
  InsV2AllReduceSequenceExecutorAicpu      (4 模板串行：RS-L0/RS-L1/AG-L1/AG-L0)
  InsV2ReduceScatterSequenceExecutorAicpu  (2 模板串行：RS-L0/RS-L1)
  ReduceSequenceExecutorAicpu3Level        (6 模板，TopoMatchTwoLevel + skipLevel2)
        │  CalcRes / CalcAlgHierarchyInfo(TopoMatchTwoLevel) / Orchestrate
        ▼
Template 层（完全复用，不新增）
  InsTempReduceScatterAicpuReduceNHRPcie   (两级 RS：NHR 交换 + aicpu LocalReduce + Hcomm 同步)
  InsTempAllGatherNHR                      (两级 AG：纯 NHR 搬运)
        │  LocalCopy / LocalReduce / SendRecvWrite|Read（经 SAL/alg_data_trans_wrapper）
        ▼
HCOMM 基础通信（独立仓，dlsym 解耦——不新增跨仓依赖，符合仓架构约束）
```

依赖方向自上而下，未引入对 `cann/hcomm` 的编译期依赖，不违反分层架构约束。

### 3.2 两级编排数据流（以 AllReduce 为例）

```
user input ──RS-L0(NHR+aicpu reduce)──▶ ccl[out半区: 本rank归约slice]
ccl[out半区] ──RS-L1(NHR+aicpu reduce)──▶ 框间归约结果（定偏移）
框间结果 ──AG-L1(NHR)──▶ 各框完整 slice
各框 slice ──AG-L0(NHR)──▶ user output（全量）
数据超单轮容量时按 maxCountPerLoop 分 loop 循环执行上述 4 步
```

ReduceScatter 终止于 RS-L1（output 为本 rank 1/N 分片）；Reduce 的 AG-L0 仅 root 落 user output。

### 3.3 新增算法组合汇总

| 算子 | executor（复用） | TopoMatch | 模板组合（按 step 顺序） |
| ---- | ---- | ---- | ---- |
| AllReduce | InsV2AllReduceSequenceExecutorAicpu | TopoMatchTwoLevel | ReduceScatterAicpuReduceNHRPcie ×2 + AllGatherNHR ×2 |
| ReduceScatter | InsV2ReduceScatterSequenceExecutorAicpu | TopoMatchTwoLevel | ReduceScatterAicpuReduceNHRPcie ×2 |
| Reduce | ReduceSequenceExecutorAicpu3Level（两级注册） | TopoMatchTwoLevel | ReduceScatterAicpuReduceNHRPcie ×3(含 L2 占位) + AllGatherNHR ×3(含 L2 占位) |

## 5. 风险与对策

| 风险 | 说明 | 对策 |
| ---- | ---- | ---- |
| 分级版模板框内复用未经验证 | Pcie 版此前仅作框间模板使用 | 模板本身与层级解耦（algIdx 映射 + repeatNum + 尾块），ST 双机用例覆盖；关注框内 HCCS 链路 `SendRecvWrite` 路径 |
| scratch multiplier 相乘导致单轮数据量骤减 | RS executor multiplier = L0×2 × L1×2，loop 增多、Hcomm 同步次数增多 | 性能无要求；确认大数据量分 loop 正确性即可 |
| 三级拓扑误入两级 executor | `TopoMatchTwoLevel` 匹配失败会报错 | attrs 层 min/maxTopoLevelNum=2 提前过滤 + selector 三级分支维持 Sole |
| 非 64bit min/max 路由语义 | 需求字面含 min/max，现网 min/max 非 64bit 走常规模板 | 见 2.5 设计确认点，默认不改，评审定稿 |
| Reduce 对称内存路径 | 3level executor 未特判 symm memory | 与现有 AicpuReduceSequenceMeshConcurNHR 行为一致，ST 覆盖；异常则 attrs opCustomCheck 排除 symm 场景并回退 Sole |

## 1. 背景与问题

### 1.1 场景约束

- AIV/SDMA 类常规算法模板不支持 64bit 数据类型（见各算法 `op.unsupportedDataTypes = UNSUPPORTED_64BIT`），也不支持 PROD 规约（`op.isSupportProd = false`）。
- 此类场景只能使用 aicpu 的 `LocalReduce`（hcomm CPU 规约）能力，即 `aicpu_reduce_nhr` 系列 template。
- 该路径每轮 NHR 交换后需要 `HcommBatchModeEnd/Start + HcommThreadJoin` 做 CPU 侧同步，性能天然较差，需求明确不要求耗时。

### 1.2 现状（三个算子一致）

1. template 层：仅有 `aicpu_reduce_nhr` 的 Sole（扁平、单级）实现：
   - AllReduce：`src/ops/all_reduce/algorithm/template/aicpu/ins_temp_all_reduce_aicpu_reduce_nhr.cc`
   - ReduceScatter：`src/ops/reduce_scatter/algorithm/template/aicpu/ins_temp_reduce_scatter_aicpu_reduce_nhr.cc`
   - Reduce：`src/ops/reduce/algorithm/template/aicpu/` 下对应 Sole 模板（由 `ReduceSoleExecutor` 使用）
2. executor 层：仅有 SoleExecutor 注册，没有分级算法：
   - `AicpuAllReduceSoleNHRAicpuReduce`（`ins_v2_all_reduce_sole_executor.cc:431`）
   - `AicpuReduceScatterSoleNHRAicpuReduce`（`ins_v2_reduce_scatter_sole_executor.cc:404`）
   - `AicpuReduceSoleNHRAicpuReduce`（`reduce_sole_executor.cc:357`）
   三者均为 `TopoMatchOneLevel`：把通信域内全部 rank 扁平看作一级，跨框（`topoLevelNums > 1`）时不区分框内/框间链路，整域跑 NHR。
3. selector 层：三个算子的 `SelectAicpuAlgo` 在 `topoLevelNums > 1` 且特殊数据类型/规约时，硬编码路由到上述 Sole 算法（如 `all_reduce_auto_selector.cc:439-440`）。

即：**跨框（两级及以上拓扑）+ 64bit/prod/min/max 场景当前退化为扁平 Sole NHR，没有框内/框间分级编排。**

### 1.3 迭代目标

为三个算子新增**两级 sequence executor（nhr+nhr）**算法：

1. 不新增 template，完全沿用现有 `aicpu_reduce` 系列 template；
2. 在既有两级 sequence executor 文件中增加 `REGISTER`；
3. 排查并修改 costModel / Selector，保证默认只有 64bit 数据类型与特殊规约操作（prod/min/max）才会进入新 executor，其余场景路由不变。

## 2. 设计思路

### 2.1 总体方案

**只加注册、不改框架**：三个算子的两级 sequence executor 框架代码均已存在并被其它算法组合使用（如 `AicpuAllReduceSequenceMeshConcurNHR`、`AicpuReduceScatterSequenceMeshNHRAicpuReduce`、`AicpuReduceSequenceMeshConcurNHR`），本次仅新增"nhr+nhr"的模板组合注册 + selector 路由修改，不动 executor/template 主体逻辑，变更面最小、可审查性好。

### 2.2 关键选型：两级 RS 复用 `InsTempReduceScatterAicpuReduceNHRPcie`

仓内 aicpu_reduce RS 有两个实现，能力差异如下：

| 能力 | InsTempReduceScatterAicpuReduceNHR（Sole 版） | InsTempReduceScatterAicpuReduceNHRPcie（分级版） |
| ---- | ---- | ---- |
| 本 rank 定位 | `sliceIdx == myRank_`，假设 userRank==算法内索引 | `GetAlgRank(myRank_, subCommRanks_[0], myAlgIdx)`，支持任意 subCommRanks 映射 |
| 尾块处理 | 无（只认 sliceSize） | `tailSize` 支持（最后 rank 尾块） |
| 输出步长 | 无 | `outputSliceStride` 支持 |
| repeatNum 多轮 | 有 | 有（框内多框数据重复） |
| in/out 同 buffer | 无处理 | 自动后移 `hcclBuffBaseOff_`，避免读写冲突 |
| scratch 占用 | rankSize 倍 | rankSize*2 倍 |
| 静态 CalcCostCoeff | 有（固定 A=10） | 无（继承基类默认返回空 → 不参与 cost 排序） |

分级 executor 以 `algHierarchyInfo.infos[level]`（框内如 `[0..7]`、框间如 `[0,8,16,24]`）构造 template，userRank 不等于算法内索引，**Sole 版模板直接用于两级编排会错乱**；而分级版已具备 algIdx 映射、尾块、stride、repeatNum 等全部两级编排所需语义，且已被 `AicpuAllReduceSequenceMeshNHRAicpuReduce` / `AicpuReduceScatterSequenceMeshNHRAicpuReduce` 作为 sequence 中的 RS 模板验证过（该注册虽名为 Pcie，模板内部 `IsPcieProtocol` 自动判链路类型，非 pcie 链路走 `SendRecvWrite`，逻辑通用）。

**结论：两级 RS（框内、框间）均复用 `InsTempReduceScatterAicpuReduceNHRPcie`，满足"不新增 template"的要求。**

AllGather 阶段为纯数据搬运，不做规约，64bit 无障碍，复用 `InsTempAllGatherNHR`（已具备 `GetAlgRank` 分级映射，现用作多个分级算法的框间 AG 模板）。

### 2.3 各算子算法编排

#### 2.3.1 AllReduce：RS-L0 → RS-L1 → AG-L1 → AG-L0

复用 `InsV2AllReduceSequenceExecutorAicpu<AlgTopoMatch, T0, T1, T2, T3>`（四模板串行编排，executor 内已处理分轮、ccl buffer 对半切分、对称内存、数据量对齐等）：

```
Step1  框内 ReduceScatter：InsTempReduceScatterAicpuReduceNHRPcie  (infos[0]，NHR 交换 + aicpu LocalReduce)
Step2  框间 ReduceScatter：InsTempReduceScatterAicpuReduceNHRPcie  (infos[1])
Step3  框间 AllGather   ：InsTempAllGatherNHR                        (infos[1])
Step4  框内 AllGather   ：InsTempAllGatherNHR                        (infos[0])
```

与现有 `AicpuAllReduceSequenceMeshNHRAicpuReduce`（Mesh1D 框内 + Pcie 框间，单机 pcie 场景）相比，差异仅为：Step1 由 Mesh1D 换成 aicpu reduce NHR（框内也走 NHR）、Step4 由 `InsTempAllGatherMesh1D` 换成 `InsTempAllGatherNHR`，即"nhr+nhr"。executor 传入的 `TemplateDataParams`（sliceSize/tailSize/stride/repeatNum=1/offset）与分级版模板语义完全对齐，executor 编排代码不需要修改。

#### 2.3.2 ReduceScatter：RS-L0 → RS-L1

复用 `InsV2ReduceScatterSequenceExecutorAicpu<AlgTopoMatch, T0, T1>`（两模板串行编排）：

```
Step1  框内 ReduceScatter：InsTempReduceScatterAicpuReduceNHRPcie  (infos[0]，repeatNum=rankSizeLevel1，逐框数据块)
Step2  框间 ReduceScatter：InsTempReduceScatterAicpuReduceNHRPcie  (infos[1])
```

注意点：分级版模板 `CalcScratchMultiple = rankSize*2`，executor 将框内/框间 multiplier 相乘（≈ 4×L0×L1）后折算 `maxCountPerLoop`，单轮可处理数据量变小、loop 增多。耗时不做要求，接受该折损；正确性由既有分轮机制保证。

#### 2.3.3 Reduce：RS-L0 → RS-L1 → AG-L1 → AG-L0（AGL0 仅 root 写 user output）

Reduce 算子的 aicpu 分级 executor 为 `ReduceSequenceExecutorAicpu3Level`（`reduce_sequence_executor_aicpu_3level.cc`），本身支持两级注册（`TopoMatchTwoLevel` + `skipLevel2_` 跳层，现有 `AicpuReduceSequenceMeshConcurNHR` 即两级注册），root 语义由 `isRootRank_` 控制（非 root 的 AGL0 输出落到 ccl buffer，仅 root 落 user output，见 `GenTempAlgParamsAGL0`）。新增注册（L2 两个模板位因 skipLevel2 不会被拉起，按现有惯例填同款占位）：

```
REGISTER_EXEC_V2_MULTI(HCCL_CMD_REDUCE, <新算法名>, ReduceSequenceExecutorAicpu3Level, TopoMatchTwoLevel,
    InsTempReduceScatterAicpuReduceNHRPcie,   // RS-L0 框内
    InsTempReduceScatterAicpuReduceNHRPcie,   // RS-L1 框间
    InsTempReduceScatterAicpuReduceNHRPcie,   // RS-L2 占位（skipLevel2）
    InsTempAllGatherNHR,                      // AG-L2 占位（skipLevel2）
    InsTempAllGatherNHR,                      // AG-L1 框间
    InsTempAllGatherNHR);                     // AG-L0 框内（root 输出）
```

### 2.4 新算法命名

沿用现有命名法 `<引擎><算子>Sequence<框内算法><框间算法>`：

| 算子 | 新算法名 |
| ---- | ---- |
| AllReduce | `AicpuAllReduceSequenceNHRAicpuReduceNHR` |
| ReduceScatter | `AicpuReduceScatterSequenceNHRAicpuReduceNHR` |
| Reduce | `AicpuReduceSequenceNHRAicpuReduceNHR` |

### 2.5 Selector 路由设计

三个算子的 `SelectAicpuAlgo` 中，`topoLevelNums > 1` 且特殊场景的分支由"一律 Sole"改为"两级走新分级算法、三级维持 Sole"（本次只做两级）：

```cpp
// 以 all_reduce_auto_selector.cc 为例（reduce / reduce_scatter 同型修改）
if (isDataTypeOrReduceTypeSpecial) {
    if (topoInfo->topoLevelNums == TOPO_LEVEL_NUM_2) {
        selectAlgName = "AicpuAllReduceSequenceNHRAicpuReduceNHR";   // 新：两级分级
    } else {
        selectAlgName = "AicpuAllReduceSoleNHRAicpuReduce";          // 三级拓扑暂维持 Sole
    }
}
```

单机（`topoLevelNums == 1`）各分支（Mesh OneShot/TwoShot、单机 pcie-mix 的 `*SequenceMeshNHRAicpuReduce`、CLOS 的 Sole 等）**全部保持不变**。

**进入条件（需求约束：默认只有 64bit 数据类型和特殊规约操作 prod/min/max 才进入）**：

- 64bit 数据类型（`Is64BitDataType`：INT64/UINT64/FP64）→ 进入（此时 sum/prod/min/max 均由该 executor 承接，aicpu `LocalReduce` 全支持）；
- PROD 规约（任意数据类型）→ 进入（沿用现有 `isDataTypeOrReduceTypeSpecial` 判定）；
- 非 64bit 的 min/max → **维持现有常规算法路径**（AIV/aicpu 常规模板本身支持 MIN/MAX，且性能更优；若将其改路由到 aicpu 分级路径会造成无谓回退）。
  - 设计确认点：需求字面为"prod、min、max"。min/max 仅在伴随 64bit 数据类型时进入本 executor；如需求方确认非 64bit 的 min/max 也要切换到本路径，仅需把判定改为 `Is64BitDataType(dt) || reduceType ∈ {PROD, MIN, MAX}`（一行），不影响其它设计。

### 2.6 costModel 排查结论（不改公式）

1. **不参与性能排序**：`InsTempReduceScatterAicpuReduceNHRPcie` 未实现静态 `CalcCostCoeff`，继承 `InsAlgTemplateBase::CalcCostCoeff` 默认返回空（`alg_v2_template_base.h:28`）。ReduceScatter/Reduce 的 sequence executor `CalcCostCoeff` 已有"任一模板返回空则整个算法不参与 CostModel"的短路逻辑；AllReduce 的 sequence executor 聚合后同样得到空结果。⇒ 新算法不会被 cost table 按性能误选，仅由 selector 特判选中，与现有 `*SequenceMeshNHRAicpuReduce` 行为一致。
2. **`GetAlgNetMeta`**：三个 executor 均已实现，随注册自动生效，无需修改。
3. **属性过滤**：新算法 `REGISTER_ALG_ATTRS` 显式声明 `topo.minTopoLevelNum = topo.maxTopoLevelNum = TOPO_LEVEL_NUM_2`，通信域初始化阶段即被 `TopoAttrs` 过滤，3 级拓扑/单机拓扑不会误注册入选；`op` 侧不设数据类型白名单与 `isSupportProd` 限制（能力全集，路由交给 selector），与现有 Sole 版 aicpu reduce 算法保持一致。
4. **资源**：分级版模板 `slaveThreadNum = 0`、单线程，sequence executor 对 thread/notify 取 max 合并，无额外资源需求；`CalcChannelRequestNhr` 按各自 `subCommRanks` 分别建框内/框间链路。

### 2.7 兼容性与约束

- `HCCL_ALGO` 白名单/环境变量指定算法名走 `AlgAttrsRegistry` 检索，新算法名注册后即可被指定，符合现有机制。
- 对称内存（`supportSymmetricMemory`）：AllReduce/ReduceScatter 的 sequence executor 已有对称内存分支，新组合自动继承；Reduce 的 3level executor 与现有 `AicpuReduceSequenceMeshConcurNHR` 行为一致（未特判，随现状）。列入 UT 验证项。
- inplace：AllReduce/ReduceScatter 新算法沿用默认 `isSupportInplace = true`（executor 经 ccl buffer 中转）；Reduce 对齐现有 `AicpuReduceSequenceMeshConcurNHR` 设 `isSupportInplace = false`。
- 保序（DETERMINISTIC_STRICT）：selector 中优先于本分支拦截，走 `*StrictOrderedMesh`，不受影响。
- AICPU_COMPILE 宏：新注册放在 `#if CANN_VERSION_NUM >= CANN_VERSION(9, 0, 0)` 与现有 aicpu sequence 注册同区（模板均为 aicpu 引擎，无需 `#ifndef AICPU_COMPILE` 包裹，与同文件现有 aicpu 注册保持一致）。

### 3.2 两级编排数据流（以 AllReduce 为例）

```
user input ──RS-L0(NHR+aicpu reduce)──▶ ccl[out半区: 本rank归约slice]
ccl[out半区] ──RS-L1(NHR+aicpu reduce)──▶ 框间归约结果（定偏移）
框间结果 ──AG-L1(NHR)──▶ 各框完整 slice
各框 slice ──AG-L0(NHR)──▶ user output（全量）
数据超单轮容量时按 maxCountPerLoop 分 loop 循环执行上述 4 步
```

ReduceScatter 终止于 RS-L1（output 为本 rank 1/N 分片）；Reduce 的 AG-L0 仅 root 落 user output。

## 5. 风险与对策

| 风险 | 说明 | 对策 |
| ---- | ---- | ---- |
| 分级版模板框内复用未经验证 | Pcie 版此前仅作框间模板使用 | 模板本身与层级解耦（algIdx 映射 + repeatNum + 尾块），ST 双机用例覆盖；关注框内 HCCS 链路 `SendRecvWrite` 路径 |
| scratch multiplier 相乘导致单轮数据量骤减 | RS executor multiplier = L0×2 × L1×2，loop 增多、Hcomm 同步次数增多 | 性能无要求；确认大数据量分 loop 正确性即可 |
| 三级拓扑误入两级 executor | `TopoMatchTwoLevel` 匹配失败会报错 | attrs 层 min/maxTopoLevelNum=2 提前过滤 + selector 三级分支维持 Sole |
| 非 64bit min/max 路由语义 | 需求字面含 min/max，现网 min/max 非 64bit 走常规模板 | 见 2.5 设计确认点，默认不改，评审定稿 |
| Reduce 对称内存路径 | 3level executor 未特判 symm memory | 与现有 AicpuReduceSequenceMeshConcurNHR 行为一致，ST 覆盖；异常则 attrs opCustomCheck 排除 symm 场景并回退 Sole |
