# 需求实验方法论参考

> 本文档沉淀自算法需求（选型/分级类）的远程仿真实验实践，供后续需求做实验时参考。
> 适用场景：无本地 Linux 环境或需大规模并行执行时，在远程服务器上搭建仿真实验平台完成验证。

## 1. 实验环境篇（远程实验平台搭建）

### 1.1 远程连接安全模式

- 密码自动化本地缺 `sshpass` 时先安装；**首次用密码登录一次性部署本机公钥**到服务器 `authorized_keys`，之后全部免密操作
- 凭据纪律：**不写入任何文件 / 不进命令行参数 / 不进回复文本**；环境变量方式传递时注意其生命周期
- 后台任务 `nohup ... &` 须加 `< /dev/null` 断开 stdin，否则 SSH 会话挂起不退出

### 1.2 环境勘察清单（连接后第一时间一次性完成）

| 勘察项 | 命令/方法 | 关注点 |
| --- | --- | --- |
| OS / 架构 | `cat /etc/os-release`、`uname -m` | x86_64 / aarch64 影响 toolkit 与编译路径 |
| CPU / 内存 / 磁盘 | `nproc`、`free -h`、`df -h` 全挂载点 | 工作区选大盘（避免系统盘高水位） |
| 编译工具链 | gcc/g++/cmake/python3/git 版本 | 对照仓内 build.md 版本要求区间 |
| CANN Toolkit | `source <toolkit>/set_env.sh && echo $ASCEND_HOME_PATH` | 真实根目录与 `aarch64-linux/lib64` 布局；`${ASCEND_HOME_PATH}/pkg_inc/hccl` 下 hcomm 头是否齐备 |
| 既有代码 / 环境 | 常见路径 `find` 扫描 | 是否已有代码仓、专用工具（避免重复部署） |
| 外网连通 | 对代码托管站/镜像站 `curl -sI` | 第三方依赖下载可行性 |

### 1.3 代码同步与校验

- **rsync 工作区级同步**（含未提交修改与 untracked 新文件），排除本地产物目录；备份文件不需要的加 `--exclude`
- 同步后**双校验**：`git rev-parse HEAD` 一致 + `git status --short` 关键修改一致；`rsync -a` 会保留源 uid，需 `chown` 修正否则 git 报 unsafe repository
- 工作区落在**大盘目录**，不放系统盘

### 1.4 Toolkit 变更安全（覆盖安装前必做）

1. 备份：`lib64/libhccl*.so*` + `include/hccl` + `pkg_inc/hccl` 到独立备份目录
2. 安装后 **md5 比对**构建产物与 toolkit 内文件，确认替换生效
3. 保留备份目录路径于实验记录中，保证可回滚

## 2. 验证工具选型与能力边界

### 2.1 三类验证工具对比

| | 老版 checker（仓内 ST 仿真） | CheckerL2 | NPU 真机 |
| --- | --- | --- | --- |
| 载体 | `test/st/algorithm` 框架（`hccl_verifier`，产物 `hccl_checker_ops_stest`） | `hccl-vm` 起集群 + `mpirun` 真算子 + `@checker` 插件 | 真实组网 + `hccl_test` 二进制 |
| 原理 | 纯软件仿真：虚拟 rank/线程/内存，对算法生成的任务图做 GenGraph/SyncConflict/MemConflict/SemanticCheck | 真实执行流校验 + mock 集群拓扑 | 端到端真实执行 |
| 架构限制 | **无**（x86/aarch64 均可） | **x86-only，当前环境不可用** | 需真实 NPU 组网 |
| 覆盖能力 | 算法逻辑/选路/内存语义/同步正确性；参数矩阵（dtype/op/数据量/root/拓扑规模） | 运行态特性：对称内存、inplace、图模式大图、特殊拓扑 yaml | 性能、真实带宽、跨机行为 |

### 2.2 当前约束与默认选择

**CheckerL2 用不了（x86 限制），验证只能用老版 checker（仓内 ST 仿真）**。设计用例与回填结论时须以此为前提。

### 2.3 口径降级时的可覆盖性评估法

原定口径工具不可用时，逐条评估用例能否平移到可用工具，分三类处理：

| 用例类别 | 可平移性 | 处理 |
| --- | --- | --- |
| 参数矩阵类（dtype/规约/数据量/root/拓扑规模） | 可平移 | 参数直接映射改写用例 |
| 运行态开关类（对称内存/inplace/图模式） | **不可平移** | 评估后删除或标注"不适用"，留待原口径环境补验 |
| 拓扑形态类（CLOS/pcie-mix 等特殊形态） | 逐条评估 | 查仿真拓扑模型是否有构造入口；无入口则如实标"不可表达"，**不得臆造构造方式** |

### 2.4 回填口径标注要求

- 用老版 checker 口径执行的用例，回填必须**注明"仓内仿真口径"**，不得冒充原定工具口径
- 不可平移条目明确标注"留待 xx 环境补验"，不静默删除历史信息（保留原口径 lineage 引用）

## 3. 构建-安装-执行全流程（ST 仿真）

### 3.1 硬顺序约束（违反则编不过或链接旧库）

```text
1. source <CANN toolkit>/set_env.sh
2. bash build.sh                      # 编出 run 包
3. ./build_out/cann-hccl_*.run --full --install-path=<toolkit 根>   # 装进 toolkit
4. md5sum 校验安装替换成功
5. bash build.sh --st --noexec        # 编 ST（ST 链接的是【已安装】的 libhccl.so）
6. 手动运行测试二进制 / ctest
```

ST 用例链接 `${ASCEND_HOME_PATH}/lib64/libhccl.so`——**改代码后必须重新走 2→3→5**，只做 5 会链接旧库得到假结果。

### 3.2 执行控制

- `--st --noexec` 只编不跑；`--st_ops=<套件>` 按 ST_TASKS 过滤编译
- 临时实验用例用独立 `ST_TASKS` 门控注册（不进默认 `all`），不污染常规套件
- 运行时 `LD_LIBRARY_PATH` 须加 ST 自身 stub 库路径（`utils/src` 各子目录）

### 3.3 时延量级预期（避免过度设计分批）

| 操作 | 量级 |
| --- | --- |
| ST 全量编译（高核数服务器） | ~1 分钟 |
| 单套件仿真用例（常规数据量） | 秒级 |
| GB 级/rank 大数据量用例 | 数十秒内（任务图随 loop 线性，先跑小档实测再放大） |

先小后大、单点实测校准耗时，再决定批处理策略；不要在未实测前假设"大参数一定跑不动"。

## 4. 观测能力先行（跑实验前先解锁观测）

### 4.1 日志级别环境变量化

仿真日志桩的级别常为硬编码（默认仅 ERROR）。**加一个环境变量开关**（如 `ST_LOG_LEVEL`，默认值不变）——一行改动、一次编译，后续所有实验都受益；顺带保证默认行为零变化。

### 4.2 核心观测钩子清单

| 钩子 | 用途 |
| --- | --- |
| `[SelectorEngine] ... the selected algo type is X` | 逐用例选中算法（选路结论的权威证据） |
| `[DFX_CostTableDump] algName=..., cost=...` | 全候选池及 cost（候选池快照/曲线数据） |
| `[CalcAlgCost] seg[j] A/B/Bre/util/segCost` | 逐段成本参数（解析互验的原料） |
| gtest `[ RUN ]` 标记 | 输出流分段锚点 |

### 4.3 逐用例结果解析模式

按 `[ RUN ]` 标记把日志切段 → 段内取最后一条 `selected algo` → 输出 `用例名/结果/winner` 三列表（json/tsv 落盘）。一次批量运行即可产出结构化结果，不必逐用例起进程。

## 5. 实验设计方法（核心）

### 5.1 校准点先行

新实验前**先复跑既有用例**（参数已知、行为可预期）锚定环境与口径：确认选路路径生效、观测钩子可用、已知边界行为复现。校准通过后再扩展新维度，异常时才有区分"环境问题 vs 被测问题"的基线。

### 5.2 env 驱动单点用例 + 外层驱动脚本（参数化模式）

- 用例代码只写**一个读环境变量的单点用例**（扫描点/强制项/拓扑参数全部 env 化）
- 扫描、二分、矩阵遍历全部在外层驱动脚本里做（循环 + grep 解析）
- 收益：用例代码一次成型不再改，实验维度调整零编译成本；脚本可复跑可存档
- 强制选路类验证同理：增加读 `ST_FORCE_ALGO` 类环境变量的强制用例，token/配置先在此实证

### 5.3 临界点/阈值定位三板斧

1. **对数粗扫**：参数按 2 的幂网格扫描，找出相邻翻转区间
2. **整数二分**：区间内二分到最小粒度（元素级），不变式=下界旧值胜/上界新值胜
3. **解析互验**：从 dump 日志提取两条曲线的斜率/截距，解线性交叉点与黑盒值互证；**偏差 <1% 量级视为自洽**（打印截断与非线性项所致残差属正常），超出则两边必有一处理解错误

### 5.4 用例编号与 STC 1:1 对齐

仿真用例名与 STC 用例编号一一对应（如 `chk_rd_xxx` ↔ `CHK_RD_XXX`），跑完结果**直抄回填**，消灭"结果-用例"映射歧义。

### 5.5 服务器副本实验优先

- 实验性改动（日志开关/临时用例/驱动脚本）**只落在服务器实验副本**，不动本地 WIP
- 结论验证后再决定哪些落仓（临时用例通常不值得上库；日志环境变量等普适改进值得）
- 好处：实验可大胆试错，WIP 始终干净，回填结论时改与不改边界清晰

## 6. 验证前移省真机

- **一切假设先仿真实证再上真机**：HCCL_ALGO token 写法、环境变量生效性、拓扑构造可行性——仿真侧一条强制用例几十秒即可实证，避免真机 session 浪费在低级错误上
- 真机脚本要求（写进脚本注释）：
  - 自带**自动汇总**（跑完生成点位/选中算法/耗时的 TSV 并打印）
  - 自带**判读说明**（什么结果算通过、偏差多大算异常）
  - 每条 stdout tee 落盘，plog 与用例目录一一对应

## 7. 踩坑清单（高价值，先读再动手）

### 7.1 静态初始化顺序（SIOF）

- 现象：UT/单测可执行文件**启动即段错误**，栈在全局构造期
- 根因：注册宏（`REGISTER_*` 类）展开的全局 ctor 依赖另一 TU 的文件级 static 容器，`.init_array` 按链接序执行，被依赖 TU 排在后面则容器未构造即被遍历
- 修复：**被依赖全局所在 TU 前移**到构建脚本的源列表最前；根治方案是 Meyers 单例
- 崩溃诊断手筋：高优先级 `constructor` 打点（区分静态初始化期/运行期）+ `sigaction` 捕获 SIGSEGV 打 backtrace + `addr2line -f -C -e` 现场解析

### 7.2 双路径选路口径带条件

- 同一能力可能存在**两条选路路径**（cost 排序 vs 硬规则特判），按拓扑形态/设备类型分叉（去读 `op_common` 层的分叉点代码）
- 文档/用例口径必须**带分叉条件**描述，"永远按 cost 排序"类表述要核对适用条件；实验前先确认被测场景走哪条路径

### 7.3 断言口径三坑

| 坑 | 表现 | 对策 |
| --- | --- | --- |
| 门禁条件性 | 期望被过滤的场景没被过滤 | 先读门禁代码的**适用形态条件**，再构造满足条件的用例输入 |
| 系数存在性断言 | 全量 `EXPECT_GT` 失败但功能正常 | 多段聚合的结果只有部分条目产出该系数——断"存在性"而非"全量非零" |
| 阈值先读源码 | 用例参数踩在阈值另一侧 | 预期结果里出现的阈值常量，先 `grep` 源码常量定义再定用例参数 |

### 7.4 环境操作坑

- SSH 每条命令是独立会话，**export 不跨调用保持**——每条命令自含环境
- `nohup` 不断 stdin 会拖挂会话（见 1.1）
- `rsync -a` 保留源 uid，跨机同步后 `chown`
- xlsx 等不可 diff 的关键文件，改前按 `原名.bak_日期_阶段前` 备份，留出回退链

## 8. 产物与交付

### 8.1 归档结构

```text
<本地临时归档目录>/<服务器或实验主题>/
├── 全量运行日志（INFO 级，体量大但证据完整）
├── 结构化结果（json/tsv：逐用例 winner/cost）
└── 实验用例/驱动脚本/补丁副本（可复现）
```

### 8.2 STC 回填格式惯例

`PASS（日期 环境 evidence（环境/版本/提交/总结果）；本条 specifics（winner/关键断言））`

- 沿用表格既有风格与口径 lineage 引用（如"与前期 CI 结论一致"）
- 不可执行条目写明**原因与环境**（不适用/留待补验），不写单纯"未执行"

### 8.3 git 提交惯例

- 按性质分笔：`docs:`（STC 回填）/ `scripts:`（实验脚本）分开提交
- 提交信息带**证据细节**（环境、总结果、关键发现），日后可从提交记录直接还原结论
- 备份文件（`.bak_*`）、编辑器配置目录不入库
