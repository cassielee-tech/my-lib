# 2026 热门 AI Agent 产品地图：从通用执行到 Coding Agent

> 更新于 2026 年 9 月。Agent 产品变化很快，本文不是严格的“热度排行榜”，而是从产品活跃度、讨论度和代表性出发，整理一张便于选型的地图。

## 本章导学

::: tip 本文只记住 3 件事
1. Agent 与聊天机器人的差别在于能否围绕目标持续规划、调用工具并交付结果。
2. 通用、研究、Coding 和自托管 Agent 的工作边界不同，没有一个产品适合全部任务。
3. 选择 Agent 先看要交付的工作流，再看权限、数据、成本和审查方式。
:::

## 先弄清楚：Agent 和聊天机器人有什么不同？

普通聊天机器人主要完成一次“输入 → 回答”；Agent 更像一个能够持续工作的执行者：

```text
                  ┌──────────────┐
                  │   用户目标   │
                  └──────┬───────┘
                         ▼
┌──────────┐      ┌──────────────┐      ┌──────────────┐
│ 环境反馈 │ ───▶ │ 规划与判断   │ ───▶ │ 调用工具执行 │
└────▲─────┘      └──────────────┘      └──────┬───────┘
     │                                         │
     └──────────── 观察结果并调整计划 ◀────────┘
                         │
                         ▼
                  ┌──────────────┐
                  │ 交付最终成果 │
                  └──────────────┘
```

它通常具有四个特征：

1. **目标驱动**：用户给出目标，而不必写出每一步操作。
2. **任务规划**：将复杂目标拆成若干步骤，并根据结果动态调整。
3. **工具使用**：可以搜索网页、操作文件、运行代码、调用应用或 API。
4. **闭环执行**：执行后观察结果，失败时重试或换一种方法，直到产出结果。

并不是具有聊天界面的产品都算 Agent。判断重点在于：它能否在获得授权后，替你完成一段多步骤工作流。

## 一、通用工作 Agent

### 1. ChatGPT Work

ChatGPT Work 面向较长的多步骤任务，目标不是只给出一段回答，而是完成文档、表格、演示文稿、报告或网站等成果。它可以使用用户选择的文件、应用和上下文，也适合需要人随时检查进度、授权关键操作的工作流。

- **亮点**：多种内容成果在同一个工作空间内完成；支持跨文件和应用协作。
- **适合**：知识工作者、产品经理、研究人员，以及需要把研究直接变成可交付成果的人。
- **注意**：不同账号和地区的功能开放范围可能不同；涉及外部操作时仍要检查授权范围。

官方入口：[ChatGPT](https://chatgpt.com/overview/)

### 2. Manus

Manus 是具有代表性的通用执行 Agent。用户描述目标后，它可以自行拆解任务、浏览网页、整理资料，并制作报告、演示文稿或网页。它更强调“把事情做完”，而不是只告诉用户应该怎样做。

- **亮点**：覆盖研究、内容创作和网页操作，最终成果形态丰富。
- **适合**：竞品调研、旅行规划、信息收集、轻量网站与内容制作。
- **注意**：网页环境随时可能变化，涉及登录、支付或发布时应保留人工确认。

官方入口：[Manus](https://manus.im/)

## 二、深度研究 Agent

### 3. Perplexity Research

Perplexity Research 会围绕问题进行多轮搜索和阅读，再将信息整合为带来源的报告。相比普通搜索，它减少了用户逐个打开网页、筛选和归纳的工作。

- **亮点**：检索与引用是产品核心，适合快速建立一个陌生主题的资料全景。
- **适合**：技术调研、市场研究、产品比较和论文入门。
- **注意**：有引用不等于结论一定正确；重要结论仍应打开原始来源核验。

官方入口：[Perplexity](https://www.perplexity.ai/)

## 三、软件开发 Agent

### 4. Codex

Codex 是 OpenAI 的软件工程 Agent。它能够读取代码仓、修改文件、运行命令和测试，并把变更交给开发者审查；也支持同时委派多个相互独立的工程任务。

- **亮点**：覆盖理解、实现、测试、审查到交付的完整开发闭环。
- **适合**：跨文件功能开发、代码重构、测试补充、缺陷定位和代码审查。
- **注意**：Agent 能提高执行速度，但架构取舍和上线责任仍属于开发者。

官方入口：[OpenAI Codex](https://openai.com/codex/)

### 5. Claude Code

Claude Code 是 Anthropic 推出的终端型 Coding Agent。它直接在开发者熟悉的命令行环境中工作，能够理解代码库、编辑代码、执行测试，并与 Git 等工具配合。

- **亮点**：终端体验自然，适合深入代码库进行连续的工程操作。
- **适合**：后端项目、大型代码库维护、调试、重构和自动化脚本。
- **注意**：命令行权限较高，要特别留意写文件、网络访问和危险命令的授权。

官方入口：[Claude Code](https://www.anthropic.com/claude-code)

### 6. Cursor Agent

Cursor 将 Agent 深度放进编辑器。它能够搜索整个代码库、跨文件编辑、运行终端命令并根据报错继续修复，也提供后台或云端执行方式。

- **亮点**：编辑器、代码上下文和 Agent 操作结合紧密，上手成本低。
- **适合**：希望保持 IDE 工作习惯，同时使用 Agent 完成日常开发的程序员。
- **注意**：快速生成大量改动后，应分批审查差异并及时运行测试。

官方入口：[Cursor](https://cursor.com/)

### 7. GitHub Copilot Agents

GitHub Copilot Agents 把 Agent 能力融入 Issue、分支和 Pull Request。开发者可以把任务交给后台 Agent，由它修改代码、运行检查并提交 PR，团队再按原有流程审查。

- **亮点**：与 GitHub 协作链路结合紧密，任务状态和代码变更容易追踪。
- **适合**：已经深度使用 GitHub，希望把 Issue 转化为可审查 PR 的团队。
- **注意**：它最擅长边界清楚、验收标准明确的任务；模糊需求仍需先由人澄清。

官方入口：[GitHub Copilot Agents](https://github.com/features/copilot/agents)

### 8. Devin

Devin 将自己定位为云端 AI 软件工程师。它拥有独立的开发环境，可以处理功能开发、缺陷修复、代码迁移和重构等任务，并通过 PR 交付结果。

- **亮点**：适合异步委派和并行处理任务队列，减少开发者持续盯守。
- **适合**：拥有较完善测试和任务管理流程，希望消化工程待办的团队。
- **注意**：任务描述、环境准备和自动化测试越清楚，成功率通常越高。

官方入口：[Devin](https://devin.ai/)

### 9. CodeArts Agent

CodeArts Agent 是华为云面向软件研发场景的 Agent 平台，覆盖代码库理解、IDE 与命令行开发、团队协作，以及 Rules、Skills、MCP 等扩展机制，并强调企业级权限和治理。

- **亮点**：面向国内企业研发流程，兼顾代码生成、知识沉淀和团队治理。
- **适合**：重视私有代码、企业规范、研发流程集成和中文体验的团队。
- **注意**：企业落地时，应先验证现有代码托管、流水线和权限体系的集成成本。

官方入口：[CodeArts Agent](https://codearts.huaweicloud.com/index.html)

## 四、开源与自托管 Agent

### 10. OpenHands

OpenHands 是面向软件开发的开源 Agent 平台。它让 Agent 通过编写代码、使用终端和浏览网页来完成工程任务，同时提供 SDK，方便研究者和团队构建自己的软件工程 Agent。

- **亮点**：开放、可自托管、便于研究和二次开发。
- **适合**：希望控制模型与运行环境，或学习 Coding Agent 内部实现的开发者。
- **注意**：自托管不代表零成本，还需要考虑模型费用、沙箱隔离、升级和运维。

官方入口：[OpenHands](https://www.openhands.dev/)

### 11. OpenClaw

OpenClaw 是开源的个人 AI 助理，强调主动执行、跨应用协作和数据自主控制。与只服务于代码的软件 Agent 不同，它更接近可自托管的个人数字助理。

- **亮点**：开源和个人化程度高，可根据自己的工作流进行扩展。
- **适合**：喜欢折腾自动化、希望自己掌控数据和 Agent 运行环境的用户。
- **注意**：个人 Agent 常接触邮件、文件等敏感数据，部署时应采用最小权限原则。

官方入口：[OpenClaw](https://openclaw.ai/)

## 应该怎样选择？

不要先问“哪个 Agent 最强”，而要先问“我要把哪一段工作交给 Agent”。

| 你的需求 | 建议优先体验 |
| --- | --- |
| 从调研到文档、表格或演示文稿一站式完成 | ChatGPT Work、Manus |
| 快速研究陌生主题，并保留网页来源 | Perplexity Research |
| 在本地代码仓内完成真实工程任务 | Codex、Claude Code、Cursor Agent |
| 将 GitHub Issue 异步转成 Pull Request | GitHub Copilot Agents |
| 把明确的工程待办交给云端环境执行 | Devin |
| 国内企业研发、代码知识与规范治理 | CodeArts Agent |
| 自托管或研究 Coding Agent 的实现 | OpenHands |
| 搭建可定制的个人助理 | OpenClaw |

对开发者来说，一个实用的体验顺序是：

```text
IDE 内协作           终端/代码仓执行          异步委派             自建 Agent
Cursor Agent   ──▶   Codex / Claude Code  ──▶  Devin / Copilot  ──▶  OpenHands
```

先学会审查 Agent 的改动，再逐步放大任务范围。不要一开始就让 Agent 在缺少测试和权限边界的生产环境中自由执行。

## 使用 Agent 时必须保留的安全意识

1. **最小权限**：只开放完成当前任务所需的文件、网络和应用权限。
2. **关键操作确认**：删除数据、发布内容、发送消息、合并代码和支付必须人工确认。
3. **保护敏感信息**：不要把密钥、生产数据和隐私文件无边界地放进上下文。
4. **验证而非盲信**：检查引用、代码差异、测试结果和最终交付物。
5. **控制任务边界**：目标、限制条件、验收标准越明确，Agent 越容易稳定完成。

## 小结

当前 Agent 已经形成几条清晰路线：

- 通用 Agent 正从“回答问题”走向“交付完整成果”。
- 研究 Agent 把搜索、阅读、归纳和引用连接成一条工作流。
- Coding Agent 是工程化最成熟的方向之一，正在进入真实代码仓和团队协作流程。
- 开源 Agent 为自托管、可控运行环境和二次开发提供了更多选择。

真正重要的不是记住所有产品名称，而是理解它们背后共同的 **规划—工具—执行—反馈** 循环。后续学习 Agent 架构时，我们会把这个循环逐层拆开。
