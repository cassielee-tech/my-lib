# ⚡ 速通｜第 8 章：Context Parallel（约 5 分钟）

> 适用：时间紧，或完整版跟不动时。这页用"分组看监控查案"讲完整章，读完抓住 80% 的主干。任何一节想深入，拉到文末点对应单元。

## 1. 切时间段：谁需要通信

一段 **4 小时的监控录像**要查线索，4 个侦探**每人只看 1 小时**（序列切分）。

先检查查案流程里哪些活是"各看各的"：整理画面、写时间戳（Norm/MLP）——**逐分钟独立，切了毫无影响，零沟通**。唯一的问题是**做笔录**（Attention）：写第 3 小时的笔录，需要**之前所有时段**的关键线索——你手里只有第 3 小时的（causal：后面的 token 要看前面的 K/V）。

于是整章只剩一道题：**线索（K/V）怎么送到每个人手里**。这就是 CP 的全部通信。

::: details 小测 1：为什么 CP 下 MLP 完全不用通信？
MLP 的矩阵乘在**特征维**（h→4h→h）上做，每个 token 独立过 MLP——序列切成几段，各段各算，结果一分不差。
:::

## 2. 两条送线索的路：复印全套 vs 圆桌轮传

**路线 A——复印全套（AllGather）**：每人把手里 1 小时的线索卡复印 4 份，全员交换——**每人桌上摊开完整的 4 小时线索**，然后各自安静写自己那段的笔录。简单、直接，但两个毛病：**桌上要摊得下全套**（显存峰值 = 全长 K/V，CP 省的显存又借回去了）；**复印期间全体干等**（通信不可重叠）。

**路线 B——圆桌轮传（Ring）**：线索按小时分装成 4 叠，沿圆桌轮流转——你写第 3 小时笔录的过程中，依次收到第 0、1、2 小时的线索叠，**边收边写**（在线合并笔录），桌上**永远只有一叠**。传的总量和复印一样，但：桌上不堆（峰值低）、传阅时间被写笔录盖住（**通信与计算重叠**）——代价是调度复杂了一点点。

::: details 小测 2：两条路线的通信总量差多少？
一样！都约等于全长 K/V 的 (N−1)/N。差别全在**显存峰值**（全套 vs 一叠）和**可重叠性**（干等 vs 边传边算）。
:::

## 3. 三角形的活：别让有人闲死

causal 有个隐藏坑：**第 0 小时的人写笔录不用看任何更早的线索（没有更早），第 3 小时的人要看全部 3 叠**——工作量是一个三角形，有人闲死有人忙死。而轮传的节拍由**最慢的人**决定——又见木桶效应。

解法很朴素：**排班时把重的活错开均摊**（zigzag/斜切）——不按"谁的那小时归谁"分，按"每人总活量相等"分，四个人各背约一半三角形的当量。

一句话总结选型：**短序列、机内**，复印全套就够；**长序列、跨机**（通信量大），必须圆桌轮传把通信藏进笔录里——序列越长，每叠越重，越好藏。

::: details 小测 3：为什么序列越长，Ring 的"藏"越有效？
传输一叠线索的时间不变（正比于块大小），但**写完一叠笔录的时间随块变重而变长**——计算时间 ≥ 传输时间时，传阅完全被覆盖。
:::

## 3 句话带走

1. **CP 切序列**：只有 Attention 欠沟通（要看全长 K/V），其他层零通信；
2. **两条路**：AllGather 复印全套（简单、峰值高、干等）vs Ring 圆桌轮传（峰值低、边传边算、调度复杂）；
3. **causal 是三角形**：均衡排班（zigzag）别让木桶效应吃掉省下的时间；TP 切 head × CP 切序列 = 4D 并行完全体。

## 黑话小词典

| 术语 | 人话 |
| --- | --- |
| CP / 序列并行 | 监控按小时分给 4 个侦探 |
| K/V 流动 | 让每人都能看到全时段的关键线索 |
| AllGather | 复印全套线索摊桌上：简单但占地方 |
| Ring 轮传 | 线索叠沿圆桌轮转，边收边写 |
| 在线 softmax | 边收线索边合并笔录（先修正再合并） |
| causal 三角 | 越晚的时段活越多——工作量是三角形 |
| zigzag | 按"总活量相等"排班，不按时段归属 |
| 4D 并行 | TP 切 head × CP 切序列 × PP 切深度 × DP 切数据 |
