## 1. 三样东西，八份复制：ZeRO 的洞察

8 个人合租办公，每人都买了**一整套装备**：常用工具（参数 15 GB）、每周的作业本（梯度 15 GB）、还有一座**巨型工具房**（优化器状态 60 GB）——每人 90 GB，全楼 720 GB，其中 630 GB 是一模一样的 7 份复制。

ZeRO 的灵魂拷问：**工具房真的需要每人一座吗？** 观察发现：修工具是**各修各的**（优化器更新逐参数独立）——每人只负责 1/8 的家伙，完全可以。于是三级递进，**最贵的先切**：

- **ZeRO-1（切工具房）**：每人保管 1/8 的优化器状态——显存 90→37.5 GB，**其他什么都不用改，白省**；
- **ZeRO-2（加切作业本）**：梯度也各管一段——上交作业时每人**只留自己那段**（AllReduce 换成 ReduceScatter），**运费还减半**，纯赚；
- **ZeRO-3（加切工具）**：连参数都拆开分放——要用时再拼，显存 11.25 GB，但**每次开工前都得先把工具凑齐**（AllGather 参数），运费涨到 1.5 倍——放不下才用的最后手段。

::: details 小测 1：为什么 Z2 的通信量反而比 DP 少？
梯度分片后每人只需要"自己负责那段参数"的梯度——AllReduce（每人拿全长）降级成 ReduceScatter（各留一段），流量正好减半。
:::

## 2. 用时借、用完还：FSDP

ZeRO-3 的"拼工具"听起来很笨重——FSDP 把它做成了**图书馆模式**：

- 平时：所有书拆页分放在 8 个书架（参数分片）；
- 干活：**今天要用第 3 章就把第 3 章借齐**（逐层 AllGather），**看完立刻还**（释放），桌上永远只有一章；
- 妙招（prefetch）：**读第 3 章的时候，第 4 章已经在快递路上**——借书时间被读书盖住（通信与计算重叠）。

它和 TP 的本质区别一句话：**TP 连"算"都切了**（每人算自己那块，激活也省）；**FSDP 只切"存"**（拼齐了整层完整地算，激活不省）。所以 TP 吞吐极限高但只能机内、工程重；FSDP 简单弹性、随便跨机，但通信多一点——**没有免费的刀，只有匹配的刀**。

::: details 小测 2：FSDP 的显存峰值是什么？
当前拼齐的那一层（完整）+ 全部激活——参数省了，但激活因为"计算不切"而没省。
:::

## 3. 五把刀的排班表：组合

最后把五把刀放回工具墙，**开方前先诊断——什么放不下？**

| 诊断 | 开方 |
| --- | --- |
| 都放得下，要吞吐 | DP（+Z1/Z2 免费优化） |
| 单层放不下 | TP（机内 8 卡） |
| 总体放不下、想简单 | FSDP/ZeRO-3（一行 wrap） |
| 总体放不下、要极限 | Megatron 3D（TP 机内 × PP 跨机 × DP 扩展） |
| 序列放不下 | CP（切序列） |
| MoE | EP（专家分布式） |

每个策略 = 把一种冗余换成一种通信；组合 = **让每种通信落到性格匹配的链路**（TP 给机内专线、PP 给跨机 P2P、DP 给慢网也能忍的重叠流）。收官一句话：本专栏讲清了"为什么通信"——每个需求都能在《集合通信》的供给表里找到对应的那一行。

::: details 小测 3：70B 预训练、64 机 8 卡、要极限吞吐，怎么配？
TP=8（机内贴 HCCS）× PP 跨机分段（P2P 边界激活）× DP 用剩余卡扩展；激活紧张再叠 CP——即 Megatron 3D/4D 配方。
:::

## 3 句话带走

1. **ZeRO 按最贵的先切**：O 白省、G 减半（RS）、P 要付 AG 的钱——显存 ÷N 的三级台阶；
2. **FSDP = 图书馆模式**：逐层用时拼、用完还，prefetch 把借书藏进读书——只切存储、不切计算；
3. **组合先诊断**：什么放不下决定用哪把刀；每种并行都是"冗余换通信"，让通信落到匹配的链路。
