# 第 9 章｜ZeRO、FSDP 与混合并行

> 本课目标：理解 DP 三大件冗余与 ZeRO 三级分片（O → O+G → O+G+P）各自的显存/通信账；掌握 FSDP"用时拼、用完还"的参数生命周期与 prefetch 重叠；建立五把刀（DP/TP/PP/CP/ZeRO）的组合决策框架，完成本专栏收官。

## 本章导学

::: tip 本课只记住 3 件事
1. **ZeRO 的洞察**：DP 的浪费在三大件（参数/梯度/优化器状态）全员复制——按"最贵的先切"递进：**Z1 切 O（白省 60GB）、Z2 加切 G（通信 AllReduce→RS，减半）、Z3 加切 P（用时 AG 拼回，通信再涨）**。
2. **FSDP = ZeRO-3 的工程化身**：参数平时分片存、**每层用时 AG 拼回、用完立刻释放**——计算完整（不切算），只切存储；prefetch 让参数预取与当前层计算重叠。
3. **组合的口诀**：切什么取决于什么放不下——**参数放不下→TP/PP/ZeRO，序列放不下→CP，都放得下→DP**；五把刀不是竞争，是对着不同的墙。
:::

## 09-1｜ZeRO 的洞察：三大件冗余

::: info 本单元目标
围绕 **"按最贵的先切的分片递进"** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

### 1. DP 到底浪费了什么

回扣 [第 5 章](05-ddp.md)：DP 每卡一份完整模型。7.5B 模型（BF16 + fp32 Adam）的三大件：

| 三大件 | 大小 | 说明 |
| --- | --- | --- |
| 参数 P（fp16） | 15 GB | 前向/反向要用 |
| 梯度 G（fp16） | 15 GB | 反向产出、更新要用 |
| 优化器状态 O（fp32 m+v） | **60 GB** | **占 2/3 的大头** |

合计 90 GB（完整混合精度账见 [《训练与推理系统》02-1](../systems/02-training-memory-compute.md#_02-1-训练显存账本-四个大件)）——8 卡 DP 总共存了 **8×90=720 GB**，其中 630 GB 是**一字不差的 7 份复制**。ZeRO（Zero Redundancy Optimizer）的问题只有一个：**这些复制必要吗？**

关键观察：**优化器更新是逐参数独立的**——`θᵢ ← θᵢ − f(mᵢ, vᵢ, gᵢ)` 只看自己的那一位。那么 N 张卡完全可以**各更新 1/N 的参数**，谁也不需要完整的 O。

### 2. 三级递进：最贵的先切

| 等级 | 分片对象 | 每卡显存（N=8） | 每步通信 | 通信量（vs DP） |
| --- | --- | --- | --- | --- |
| DP | 无 | 90 GB | AllReduce(G) ≈ 26 GB | 1× |
| **ZeRO-1** | O | 15+15+7.5 = **37.5 GB** | 不变（G 仍全量 AllReduce） | 1× |
| **ZeRO-2** | O + G | 15+1.9+7.5 = **24.4 GB** | **ReduceScatter(G)** ≈ 13 GB | **0.5×** ✅ |
| **ZeRO-3** | O + G + P | 90/8 = **11.25 GB** | RS(G) + **AG(P)×前向/反向** | ~1.5× |

两级账本读懂设计：

**Z1 是"白省"**：O 分片后每卡只更新自己的参数段——**计算与通信都不变，显存直接砍掉 (N−1)O/N**。没有理由不做。

**Z2 的通信魔法**：梯度分片后，AllReduce 变 **ReduceScatter**——每人只需要"自己那段参数"的梯度，为什么要拿全长？（[《集合通信》04-2](../collective/04-gather-scatter-alltoall.md#_04-2-reducescatter-规约后分着拿) 的 FSDP 省钱逻辑，回扣 [01-4 的"最小够用原语"](../collective/01-collective-semantics-cost.md#_01-4-从语义到选型)）。**通信减半，纯赚**。

**Z3 的代价**：参数也分片后，前向/反向**用哪层就得先把哪层拼齐**（AllGather）——通信从 0.5× 涨回 1.5×。它换来的是"**任意大模型都能放下**"——这是用通信换显存的最后一档。

::: tip 选择的直觉
Z1/Z2 几乎免费，默认开；Z3 是"放不下才用"的最后手段——而下一段的 FSDP 会告诉你，Z3 的"拼参数"也可以做得很优雅。
:::

## 09-2｜FSDP：用时拼、用完还

::: info 本单元目标
围绕 **"参数的生命周期：分片存放、按层拼回、用完释放"** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

FSDP（Fully Sharded Data Parallel）= ZeRO-3 思想的 PyTorch 工程化。核心问题是：参数分片了，前向/反向要完整参数怎么办？

### 3. 洋葱式包一层，一次只拼一层

FSDP 的答案：**不拼整个模型，逐层"用时拼、用完还"**。

对每个 Transformer 层包一层 FSDP（nested wrap），它的参数生命周期：

```text
平时：    参数分片存放（每卡 1/N），不占整层显存
前向该层：AllGather(Pᵢ) → 拼齐 → 计算 → 立刻释放，只留分片
反向该层：AllGather(Pᵢ) → 拼齐 → 算梯度 → ReduceScatter(Gᵢ) → 释放
更新：    各卡只更新自己那段（Z1 的逻辑）
```

显存峰值 = **当前拼齐的那一层 + 全部激活**（激活不省——这是"计算不切、只切存储"的代价，与 TP 的本质区别见下表）。

| | TP（[第 6 章](06-tensor-parallel.md)） | FSDP（本章） |
| --- | --- | --- |
| 参数存放 | 分片 | 分片 |
| **计算** | **分片**（每卡算自己的块） | **完整**（拼齐了整层算） |
| 激活 | 随分片 ÷N | 完整（不省） |
| 通信 | 激活级、每层 4 次、不可重叠 | 参数级、每层 3 次、**可预取重叠** |

### 4. Prefetch：把拼参数藏进计算

逐层 AG 的通信在关键路径上吗？——**不在，因为可以预取**：算第 $i$ 层时，第 $i{+}1$ 层的参数已经在后台 AG——**通信与当前层计算重叠**（与 [第 5 章 DDP](05-ddp.md#_05-3-bucket-分桶的艺术) 的桶预取同一个思想，不同对象）。

FSDP 的使用体验（对照 [第 4 章](04-distributed-basics.md#_04-4-工程实操-跑起来与排障)的骨架）：

```python
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP

model = Transformer(...)                        # 每卡先有完整定义
model = FSDP(model, auto_wrap_policy=...)       # 包洋葱 → 参数即刻分片
# 训练循环与 DDP 几乎一样：loss.backward() 内部自动完成
#   AG(P)→算→RS(G) 的逐层接力，optimizer.step() 各更新各段
```

::: warning 三条工程备注
1. **`no_sync()` + 梯度累积**：累积步内不 RS，进一步省通信（回扣 [第 5 章 05-4](05-ddp.md#_05-4-通信计算重叠-把等待藏起来)）；
2. **Offload 兜底**：分片还能再甩到 CPU/NVMe（ZeRO-Offload/Infinity，[《训练与推理系统》02-3](../systems/02-training-memory-compute.md#_02-3-梯度累积与-offload-腾挪空间) 的 Offload 思想 × 分片思想的乘法）；
3. **选择直觉**：中小模型/想要简单 → FSDP（无 stage、无调度心智）；超大模型/极限吞吐 → TP+PP 的 Megatron 路线（通信更省但工程更重）——两者也可组合。
:::

## 09-3｜五把刀的组合策略

::: info 本单元目标
围绕 **"切什么取决于什么放不下"** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

五把刀凑齐了。真实的部署问题从来不是"选哪把"，而是"**怎么配**"。

### 5. 决策树：先诊断，再开方

```text
模型放得下单卡吗？
├─ 放得下 ──► DP（+ ZeRO-1/2：几乎免费的优化）
└─ 放不下 ──► 放不下的原因是？
    ├─ 单层就放不下 ────────► TP（机内 8 卡，层内切分）
    ├─ 单层放得下、总体放不下 ─► FSDP/ZeRO-3（切存储）
    │                          或 PP（切深度，跨机）
    ├─ 激活/KV 放不下 ────────► CP（切序列，[第 8 章](08-context-parallel.md)）
    └─ 是 MoE ───────────────► EP（专家分布式，[第 1 章](01-moe-expert-parallel.md)）
```

诊断的顺序就是开方的顺序：**先问显存墙在哪，再选刀**——这也是 [08-4](08-context-parallel.md#_08-4-cp-的账与-4d-组合) "切什么取决于什么放不下"的完整版。

### 6. 两个经典配方

**配方 A：Megatron 3D（极限吞吐）**——大厂预训练的标配：

```text
TP=8（机内）× PP=8~16（跨机）× DP（其余卡） [+ CP 长序列] [+ EP 若 MoE]
```

通信全部按性格归位：TP 贴机内专线、PP 走相邻 P2P、DP 低频可重叠——代价是配置复杂、负载要人工配平。

**配方 B：FSDP 系（简单弹性）**——中小团队与微调场景：

```text
ZeRO-2/3（+ Offload）× DP —— 一行 wrap，云上弹性伸缩
```

通信多一点、吞吐逊一点，换来工程上的省心——**没有最好的并行，只有与场景匹配的并行**。

#### 6.1 五把刀总表（背这张就够）

| 刀 | 切什么 | 通信对象/形态 | 通信性格 | 显存收益 | 位置约束 |
| --- | --- | --- | --- | --- | --- |
| DP | batch | 梯度 / AllReduce | 大而低频，可重叠 | 无（ZeRO 补） | 任意 |
| ZeRO | 存储状态 | G 的 RS + P 的 AG | 中频，可预取重叠 | 三大件 ÷N | 任意 |
| TP | head/特征 | 激活 / AG·RS·AR | 小而高频，不可重叠 | 三大件+激活 ÷N | **机内** |
| PP | 深度 | 边界激活 / P2P | 极小，有 Bubble | 三大件 ÷S | 跨机 ✅ |
| CP | 序列 | K/V / AG 或环传 | 与 S 成正比，Ring 可重叠 | 激活+KV ÷N | 跨机可行 |

::: tip 组合的本质
五把刀各自把**一种冗余或一堵墙**变成通信——组合 = 让每种通信都落到性格匹配的链路上（[第 4 章](04-distributed-basics.md#_04-3-拓扑感知排布-把编号贴到物理上)的拓扑感知排号把它们钉在物理上）。
:::

### 8. 专栏收官：三条带走的话

1. **通信是算法的一部分**：从 DP 的"必须取平均"到 CP 的"必须看到 K/V"——并行策略先定义正确性，再谈效率；
2. **每种并行 = 把一种冗余换成一种通信**：DP 换吞吐、ZeRO 换显存、TP 换层内算力、PP 换跨机扩展、CP 换序列容量——**没有免费的刀**；
3. **组合 = 让通信落到性格匹配的链路**：机内给 TP、跨机给 PP/CP、慢网给可重叠的 DP——拓扑感知（第 4 章）是最后一颗钉子。

### 10. 自测题

1. 三大件各多大？为什么说优化器状态是大头？
2. "优化器更新逐参数独立"这一观察为什么让分片合法？
3. Z1 为什么说几乎免费？
4. Z2 的通信为什么减半？用到什么原语替换？
5. Z3 的通信代价是什么？换来什么？
6. FSDP 一层的参数生命周期四个阶段是什么？
7. FSDP 与 TP 在"切不切计算"上的区别带来哪两项显存差异？
8. prefetch 重叠的是什么与什么？
9. 决策树的第一问是什么？三个分支各指向哪些刀？
10. 两种经典配方各自的取舍是什么？

::: details 自测答案

1. 7.5B：P=15 GB、G=15 GB、O=60 GB；O（fp32 m+v）占 2/3。
2. 更新 θᵢ 只依赖自己的 mᵢ、vᵢ、gᵢ——N 卡各更新 1/N 参数互不干扰，完整复制没有必要。
3. 显存砍掉 (N−1)O/N，而梯度的 AllReduce 与计算完全不变——没有代价。
4. 梯度分片后每人只要自己那段：AllReduce(G)（2G(N−1)/N）换成 ReduceScatter(G)（G(N−1)/N）——"最小够用原语"。
5. 每层前向/反向都要 AG 拼回参数，通信从 0.5× 涨到约 1.5×；换来任意大模型放得下（每卡 90/N GB）。
6. 分片存放 → AG 拼齐（前向）→ 释放 → AG 拼齐（反向）→ RS 梯度 → 释放 → 更新自己段。
7. FSDP 计算完整：激活不省（完整保存）；TP 计算分片：激活随分块 ÷N。
8. 第 i+1 层参数的 AG 与第 i 层的计算——参数预取藏进当前层前向/反向。
9. "模型放得下单卡吗？"放得下→DP(+Z1/Z2)；单层放不下→TP；总体放不下→FSDP/PP；序列放不下→CP；MoE→EP。
10. Megatron 3D：通信最优、吞吐极限，但配置复杂、负载要人工配平；FSDP 系：工程简单、弹性好，通信与吞吐略逊。

:::
