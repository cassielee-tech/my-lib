## 1. 四个工位的流水线：切深度

一家洗车店扩建成**四工位流水线**：冲水 → 打泡沫 → 刷洗 → 擦干。每辆车从工位 1 进、工位 4 出。

对应到训练：模型 32 层**按深度切成 4 段**（stage），每段住一台机器。数据像车一样流过去：前向从 Stage 0 流到 Stage 3，反向再流回来。

这种切法的通信便宜到不像话：**只有相邻工位递车**（P2P 传一个 micro-batch 的边界激活，MB 级）——不需要全员集合、不需要传梯度/参数（那些按层分家了，各存各的）。**模型再大，递的也只是"这层的输出"**——所以 PP 是三把刀里唯一**天生跨机友好**的（TP 只能挤机内，PP 的工位可以横跨厂房）。

::: details 小测 1：为什么 PP 的通信量与模型大小无关？
因为 stage 之间只传"边界激活"（这层算完的输出，大小由 batch×序列×隐层决定）；参数和梯度各 stage 自存自用，从不需要搬家。
:::

## 2. 车队拆小批 + 空转时刻：Bubble

只洗**一辆大车**（整 batch 一次流过）？工位 4 要等车缓缓漂过前三个工位才开工——同一时刻**只有一个工位在干活**。

聪明做法：把车队拆成 **M 辆小车**（micro-batch）**连续注入**——第 1 辆还在工位 2，第 2 辆已进工位 1。稳态时四个工位全部满负荷；空转只剩两头：**开头等第一辆车流到最深（fill）、结尾等最后一辆反向流回最浅（drain）**——这段空转就叫 **Bubble**。

公式一张名片：**Bubble 率 = (S−1)/(M+S−1)**（S = 工位数，M = 车数）。S=4 时：M=4 辆 → 空转 43%；M=64 辆 → 空转 4.5%。**车越多，启动/排空的固定开销摊得越薄**。

::: details 小测 2：S=8、M=56 时 Bubble 率是多少？
(8−1)/(56+8−1) = 7/63 = 11.1%。
:::

## 3. 边洗边交车：1F1B

新问题：GPipe 式调度（**所有车全洗完，再统一返工检查**）要求暂存**全部 M 辆车**的洗车记录（激活内存 O(M)）——想加大 M 压空转？先把暂存区撑爆。

关键洞察：**第 1 辆车的返工不必等第 64 辆洗完**——它自己的工序早就结束了。于是 **1F1B**：工位先热身（S−1 辆前向），之后**每接收一辆新车，就送走一辆检查完的旧车**——一进一出交替，暂存区里**恒定只有约 S 辆车**（内存 O(M)→O(S)）。

注意：1F1B **不减少空转**（两头还是要等），它解放的是暂存区——于是你能放心把 M 加到 64，**空转被间接压到 4.5%**。进阶版 Interleaved（每个工位再细分 v 个小段）能把空转再除以 v，代价是递车更碎更频繁。

::: details 小测 3：1F1B 既然不省时间，为什么人人都在用？
它省内存（O(M)→O(S)），允许加大 M；Bubble 率随 M 下降——"解内存、不解时间，最终解时间"。
:::

## 3 句话带走

1. **PP 按深度切**：只有相邻 stage 递车（P2P 激活，MB 级），三把刀里唯一跨机友好；
2. **Bubble = (S−1)/(M+S−1)**：micro-batch 连续注入填满流水线，两头空转靠大 M 摊；
3. **1F1B 边洗边交车**：在途激活 O(M)→O(S)，解放 M 上限，间接压死 Bubble。

## 黑话小词典

| 术语 | 人话 |
| --- | --- |
| stage | 流水线的一个工位（一段连续的层，住一台机器） |
| micro-batch | 车队里的一辆小车：batch 切小、连续注入 |
| Bubble | 流水线两头的空转（fill + drain） |
| GPipe | 全部洗完再统一返工的调度（内存 O(M)） |
| 1F1B | 一辆新车进、一辆旧车出的交替调度（内存 O(S)） |
| Interleaved | 工位再切小段，空转 ÷v，递车更碎 |
| 负载均衡 | 首尾工位少放几层，别让最慢的拖全队 |
