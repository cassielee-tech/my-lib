# 单元 07-3｜1F1B：解内存，不解时间

> 所属章节：[第 7 章｜Pipeline Parallel](../07-pipeline-parallel.md)

::: info 本单元目标
围绕 **"1F1B 用交替调度换内存"** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。

## 5. 关键观察：反向不必等全部前向

GPipe 的"全部前向 → 全部反向"是一个**不必要的串行**——micro-batch 1 的反向只依赖 micro-batch 1 自己的前向，谁也没规定它必须等 micro-batch M 前向完。

**1F1B（one-forward-one-backward）**：warmup 先做 $S-1$ 个前向把流水线填满，之后**每接收一个新 micro-batch 的前向，就完成一个旧 micro-batch 的反向**，交替推进直到 drain：

```text
Stage 0 视角（S=4, M=8）：
F1 F2 F3 [F4 B1] [F5 B2] [F6 B3] [F7 B4] [F8 B5] · B6 · B7 · B8
└warmup┘ └────────── 稳态：一前向一反向 ──────────┘ └cooldown┘
```

## 6. 1F1B 的账：内存 O(M) → O(S)

稳态下，每个 stage **同时在途的 micro-batch 激活数 ≈ S**（而非 GPipe 的 M）：

| 方案 | 在途激活 | Bubble 率 | 代价 |
| --- | --- | --- | --- |
| GPipe | O(M) 个 | $\frac{S-1}{M+S-1}$ | M 大 → 内存爆 |
| **1F1B** | **O(S) 个** | $\frac{S-1}{M+S-1}$（**不变！**） | 调度与同步更复杂 |

**注意：1F1B 不减少 Bubble**——总时间公式相同。它解放的是内存：M 从"受显存限制"变成"只受你想要的 Bubble 率限制"。于是可以放心加大 M，**间接**把 Bubble 压得更低——这就是"解内存、不解时间，最终解时间"的三段逻辑。

### 6.1 再进一步：Interleaved 1F1B（虚拟流水线）

Megatron 的改进：每个 stage 把自己的层再切成 $v$ 个**虚拟段**，调度粒度更细——Bubble 从 $(S-1)$ 拍降到约 $(S-1)/v$ 拍。代价是 P2P 次数 ×v 且每次传的激活更碎。一句话记住：**用更碎的通信换更短的空转**。

::: tip 三种调度的一句话族谱
朴素串行（全空转）→ GPipe micro-batch（填满流水，两头空转，内存 O(M)）→ 1F1B（交替推进，内存 O(S)）→ Interleaved（虚拟段，空转再除 v）。
:::
