# 单元 07-1｜为什么是 PP：按深度分段

> 所属章节：[第 7 章｜Pipeline Parallel](../07-pipeline-parallel.md)

::: info 本单元目标
围绕 **"按深度切分的通信优势"** 建立一条可以复述的因果链。读完后，尝试不看正文用一句话解释它。
:::

## 1. 第三把刀：切深度

三把刀凑齐了——DP 切**数据**、TP 切**层内**、PP 切**深度**：

```text
Stage 0（机器 A）   Stage 1（机器 B）   Stage 2（机器 C）   Stage 3（机器 D）
Layer 0-7     →      Layer 8-15    →     Layer 16-23    →    Layer 24-31 + Loss
        激活 ──────P2P────→ 激活 ──────P2P────→ 激活 ──────P2P────→
```

每个 stage 持有 $1/S$ 的层（三大件 ÷S），数据从 Stage 0 注入、逐段前向、在 Stage 3 算 loss、再逐段反向流回。

## 2. PP 的通信账：小到不像话

对比三把刀每步要传的东西：

| 并行 | 通信对象 | 大小（7.5B 级算例） | 通信对象范围 |
| --- | --- | --- | --- |
| DP | 全量梯度 | ~15 GB/步 | world group（全体） |
| TP | 每层激活 × 128 次 | ~128 MB/层 | tp_group（机内） |
| **PP** | **stage 边界激活** | ~128 MB/micro-batch | **只有相邻两台机器** |

PP 的三个结构性优势：

1. **P2P 而非集合**：Send/Recv 只发生在相邻 stage 之间——没有全员集合、没有规约（[H01-4](../../ascend/hccl-source/04-primitives-and-sync.md) 的 P2P 原语正是干这个的）；
2. **通信量小**：只传一个 micro-batch 的边界激活（B×S×h×2，MB 级），与模型大小**无关**——模型再大，传的还是那层输出；
3. **跨机友好**：相邻机器间点对点走网卡，不需要机内全互联的带宽——**PP 段天然横跨多机**，恰好补上 TP"只能住机内"的短板。

::: warning 但 PP 不是免费的午餐
按深度切分引入了三把刀里独有的一种浪费：**流水线的启动与排空时间（Bubble）**——机器在等数据流到自己这里。这是本章后半段的主角，也是 PP 一切调度算法要对抗的对象。
:::
