## 1. 把文章剪成积木，再给积木编号

模型不认识字，只认识数字。所以第一步是**剪纸**（Tokenization）：

```text
"我爱集合通信" → ["我", "爱", "集合", "通信"] → [102, 88, 4520, 3977]
```

- 剪出的每块叫 **Token**：可能是一个字、一个词、半个词，甚至一个符号——**不等于字或词**；
- 每块积木在**总目录**（词表）里有唯一编号：**Token ID**；
- 这本目录和模型是**配套出厂**的——换一本目录，同一个编号对应的就是另一块积木，模型直接查错。

编号只是"第 37 号货架"。第二步是**取货**（Embedding）：按编号从货架上取下一个**意义盒子**——一个长度为 H 的数字向量。从此模型操作的不再是编号，而是这些可计算、可学习的向量。

::: details 小测 1：Token、Token ID、Embedding 的关系？
剪出的积木块（Token）→ 它在词表目录里的编号（Token ID）→ 按编号从参数表取出的数字向量（Embedding）。三步走完，文字才变成模型能计算的数字。为什么 Tokenizer 必须和模型配套？因为编号和货架是绑定的，换目录就取错货。
:::

## 2. 考场规则：挡板与空位

一批考卷（Batch）一起改，题干有长有短。为了让表格尺寸对齐，短卷子末尾要**凑数空位**（Padding）。

考场里有两块完全不同的"挡板"（Mask）：

| 挡板 | 挡住什么 | 为什么 |
| --- | --- | --- |
| **Padding Mask** | 凑数的空位 | 空位不是内容，别让它干扰计算 |
| **Causal Mask** | **右边的未来** | 接龙考试不许偷看答案 |

Causal Mask 是这个考场的灵魂：第 5 个位置的考生只能看到第 1～5 个位置，**绝不能看到第 6 个**——因为第 6 个词正是它要预测的答案。

::: details 小测 2：Padding Mask 和 Causal Mask 能同时用吗？
能，它们解决两个不相干的问题：一个挡"凑数的假位置"，一个挡"未来的真答案"。训练时通常两块都装上。
:::

## 3. 出题的方式：全体考生同时作答

训练的出题法极其朴素：**把输入整体右移一位当答案**。

```text
输入：  [我, 爱, 集合, 通信]
答案：  [爱, 集合, 通信, !]      ← 每个位置都在预测"下一个词"
```

每个位置交卷的是一张**打分表**（Logits）：对词表里 V 个候选词各打一个分。注意**打分表不是概率**——要经过 Softmax 归一化后，才能读成"50% 是'通信'"。

因为 Causal Mask 的存在，**一次前向就能让所有位置同时作答**，不用一个词一个词来——训练高效；而生成文本时才需要逐词迭代（那是《训练与推理系统》第 3 章的故事）。

这套流程的尺寸链值得背下来：`[B,S] 编号 → 查表 → [B,S,H] 向量 → …… → [B,S,V] 打分表`。

::: details 小测 3：长度为 S 的序列（含开头、结尾标记），能出几道题？
S−1 道。第 1 到第 S−1 个位置各预测自己的"下一个"，最后的结尾标记之后没有答案了。这也是为什么训练吞吐用 tokens/s 衡量比"条数"更公平——每条文本剪出的积木数都不一样。
:::

## 3 句话带走

1. 文字进模型要走三步：**剪积木（Token）→ 查编号（ID）→ 取向量（Embedding）**，目录和模型配套；
2. 两块挡板各管各的：**Padding Mask 挡空位，Causal Mask 挡未来**；
3. 训练就是**右移一位的接龙考试**，一次前向全体作答，交卷的是打分表（Logits）。

## 黑话小词典

| 术语 | 人话 |
| --- | --- |
| Token / Token ID | 剪出的积木 / 积木在目录里的编号 |
| 词表（Vocabulary, V） | 全部积木的总目录 |
| Embedding | 按编号取出的"意义盒子"（可学习向量） |
| Padding / Padding Mask | 凑数空位 / 挡住空位的板子 |
| Causal Mask | 挡住未来的板子（不许偷看答案） |
| Logits / Softmax | 打分表 / 把分数变成概率 |
| Shift（错开一位） | 输入右移一位生成标准答案 |
| tokens/s | 每秒真正处理多少积木 |
