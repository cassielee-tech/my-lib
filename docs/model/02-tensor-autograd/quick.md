## 1. 张量就是一张多维表格

别被"张量"吓到，它就是**一张有多层结构的 Excel 表**：

- `[8]` = 一列 8 个数；
- `[4, 8]` = 4 行 8 列的表；
- `[2, 4, 8]` = 两本这样的表钉在一起。

**Shape 就是表格的尺寸**。模型里流动的所有数据——输入、权重、中间结果——全是这样的表格。

表格之间最重要的运算叫**矩阵乘法**（一次"对账式"的批量乘加）。它有条铁律：

```text
[M, K] × [K, N] → [M, N]
        ↑
  左表的列数必须等于右表的行数，对完账这个维度就"消失"
```

有了这条规则，你就能心算任何一层网络输出的尺寸，还能顺手算出数据量（元素个数 × 每个数的字节）。

::: details 小测 1：`[2, 4, 8]` 的表格 × `[8, 16]` 的表格，结果是什么尺寸？
前两维 `[2,4]` 表示有 2×4=8 个"词条"，每个词条是长度 8 的向量。每个向量乘 `[8,16]` 变成长度 16 → 结果 `[2, 4, 16]`。消掉的维度永远是"左尾 = 右头"的那一对。
:::

## 2. 出了次品怎么追责：计算图与反向传播

工厂每天出货，质检发现总有问题（Loss 不为零）。**是谁的锅？**

前向生产时，工厂顺便填了一张**流程单**（计算图）：每道工序用了什么原料、做了什么运算。追责时就把它倒过来走：

```text
质检结果（Loss）
  ← 最后一道工序担多少责任（局部梯度）
  ← 链式法则层层分摊：我的责任 = 我下游传回来的责任 × 我这道工序的敏感度
  ← 一直追溯到每个参数头上
```

每个参数分到的"责任值"就是**梯度**。两个关键事实：

1. **梯度和参数的 Shape 一定相同**——每个参数都要有一个责任值，不多不少；
2. **追责 ≠ 改参数**：`loss.backward()` 只是算出责任清单；`optimizer.step()` 才真的按清单调整参数。之后还要 `zero_grad()` 清空旧清单，否则新旧责任会混账。

::: details 小测 2：`backward()` 之后模型参数变了吗？
没有。`backward()` 只是把梯度算出来、记到每个参数的 `.grad` 里；要等 `optimizer.step()` 读这些梯度才真正修改参数。顺序永远是：算梯度 → （多卡时对账）→ 更新 → 清零。
:::

## 3. 多个车间一起干：责任也要对账

工厂开了多个车间（多张卡），每个车间用自己的原料批次干活，于是**各自追出的责任清单不一样**。

如果各改各的，每个车间的"生产标准"（参数）就分家了。所以：**更新参数之前，必须先把各车间的责任清单汇总**（AllReduce 求平均），让所有车间按同一份清单调整。

聪明的做法是不等全部追完责再对账：**追责是从后往前逐层进行的，后面几层的清单一出来就先装箱发出**（Bucket），对账和前面的追责同时进行——这就是"通信与计算重叠"。

::: details 小测 3：为什么梯度汇总可以和反向计算重叠？
因为反向传播从最后一层往第一层进行：后面层的梯度先生成，先装箱发走（AllReduce 在独立通道异步跑）；与此同时前面的层还在继续算梯度。等最前面的梯度装箱时，后面的对账已经完成大半。
:::

## 3 句话带走

1. 张量就是多维表格，**Shape 是尺寸，矩阵乘法的尺寸规则能心算一切**；
2. 反向传播就是**按流程单倒着追责**，梯度 = 每个参数的责任值，Shape 与参数相同；
3. 多卡训练**必须先对账（汇总梯度）再改参数**，且可以让对账追责并行。

## 黑话小词典

| 术语 | 人话 |
| --- | --- |
| 张量 / Shape | 多维表格 / 表格的尺寸 |
| 参数（Parameter） | 需要根据责任清单调整的表格（模型的知识） |
| 激活（Activation） | 生产过程中的中间半成品 |
| 计算图 | 前向时填的流程单，追责时倒着用 |
| 梯度 / 链式法则 | 每个参数的责任值 / 责任层层分摊的规则 |
| `backward()` / `step()` | 算责任清单 / 按清单改参数 |
| 广播（Broadcast） | 尺寸不齐时自动"复印补齐"再运算 |
| Bucket | 把多份责任清单打成一箱再对账 |
