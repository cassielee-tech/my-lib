张量可以先简单理解为“带有形状的多维数组”。维数不同，常见称呼也不同。

![从标量到三维张量](/images/llm/tensor-shapes.svg)

在大模型中最常见的激活张量形状是：

```text
[batch_size, sequence_length, hidden_size]
```

例如 `[2, 4, 8]` 表示：

- 一次处理 2 条文本；
- 每条文本有 4 个 Token；
- 每个 Token 用一个长度为 8 的向量表示。

张量总元素数量为 `2 × 4 × 8 = 64`。若数据类型为 FP32，每个元素占 4 Byte，总空间为 `64 × 4 = 256 Byte`。

### 维度、轴和下标

对张量 `X[batch, sequence, hidden]`：

- 第 0 轴是 batch；
- 第 1 轴是 sequence；
- 第 2 轴是 hidden；
- `X[1, 2, 3]` 表示第 2 条文本、第 3 个 Token、向量中的第 4 个数字。

计算机下标通常从 0 开始，但自然语言描述习惯从 1 开始，这是阅读 shape 时常见的混淆来源。

### dtype 决定一个元素占多少空间

| dtype | 每个元素占用 | 直观特点 |
| --- | ---: | --- |
| FP32 | 4 Byte | 精度较高，占用较大 |
| FP16 | 2 Byte | 占用减半，表示范围有限 |
| BF16 | 2 Byte | 与 FP16 同样大小，指数范围更接近 FP32 |
| INT8 | 1 Byte | 常用于量化推理 |

张量占用空间的基础公式是：

```text
字节数 = 所有维度乘积 × 每个元素字节数
```

这里算出的只是张量本身的理论数据量，不包含内存对齐、Allocator 管理和框架对象等额外开销。

### 为什么 shape 对 AI Infra 很重要

Shape 不只是数学信息，它同时决定：

- 能否执行某个算子；
- 算子大约需要多少次计算；
- 激活值和中间结果占多少显存；
- 张量切分后每个设备持有什么数据；
- 集合通信需要发送多少字节。

后续分析任何模型或算子，都建议在草稿上先写 shape。

## 2. 矩阵乘法是 Transformer 的主干计算

线性层写作：

$$
Y = XW + b
$$

如果先把 batch 和 sequence 两维合并，矩阵形状如下：

![线性层矩阵乘法的形状变化](/images/llm/matmul-shapes.svg)

矩阵乘法的规则是：

```text
[M, K] × [K, N] → [M, N]
```

中间维度 `K` 必须相等。结果的每个元素，都是长度为 `K` 的两个向量做点积。

### 先从一个输出元素理解矩阵乘法

假设：

```text
X = [[1, 2]]
W = [[3, 4],
     [5, 6]]
```

那么：

```text
Y[0,0] = 1×3 + 2×5 = 13
Y[0,1] = 1×4 + 2×6 = 16
Y = [[13, 16]]
```

可以把 `W` 的每一列理解成一个“特征探测器”：输入向量分别与各列做点积，得到新的输出特征。

### 为什么线性层可以改变 hidden size

输入 `X` 的最后一维是 `H`，权重 `W` 是 `[H, O]`。矩阵乘法会消去 `H`，留下 `O`，因此线性层可以把每个 Token 的向量从长度 `H` 映射成长度 `O`：

```text
[B, S, H] × [H, O] → [B, S, O]
```

前面的 `B、S` 可以理解为有 `B×S` 个 Token 各自使用同一份权重进行转换。

### 计算量估算

矩阵乘法 `[M, K] × [K, N]` 大约需要：

$$
2MKN\ \text{FLOPs}
$$

系数 2 来自一次乘法和一次加法。比如：

```text
[8, 16] × [16, 32] → [8, 32]
FLOPs ≈ 2 × 8 × 16 × 32 = 8192
```

这套估算以后会用于判断算子规模、理论耗时和模型的总计算量。

### FLOP 是什么

FLOP 表示一次浮点运算，例如一次加法或乘法。FLOPs 在不同语境中可能表示“浮点运算次数”，也可能表示“每秒浮点运算能力”，阅读时要结合上下文：

- 这个矩阵乘法需要多少 FLOPs：讨论工作量；
- 设备峰值是 300 TFLOPS：讨论每秒理论计算能力。

理论 FLOPs 相同的两个算子，实际速度仍可能不同，因为它们的访存、并行度、数据布局和 Kernel 实现不同。
