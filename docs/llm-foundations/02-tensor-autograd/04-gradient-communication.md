对于：

```text
Y = XW
X: [M, K]
W: [K, N]
Y: [M, N]
```

假设上游传来 `dY`，其 shape 必须与 `Y` 相同：

```text
dY: [M, N]
```

反向传播得到：

```text
dX = dY × Wᵀ  → [M, N] × [N, K] = [M, K]
dW = Xᵀ × dY  → [K, M] × [M, N] = [K, N]
```

一个非常有用的自检规则是：**某个变量的梯度 shape，必须与这个变量本身的 shape 相同。**

### 转置为什么会出现

转置 `Wᵀ` 会交换矩阵的两个维度：

```text
W:  [K, N]
Wᵀ: [N, K]
```

反向传播需要把上游梯度投影回输入或权重原来的空间，因此会调整矩阵方向，让矩阵乘法的中间维匹配：

```text
dY [M,N] × Wᵀ [N,K] → dX [M,K]
Xᵀ [K,M] × dY [M,N] → dW [K,N]
```

即使暂时不会严格推导公式，也可以用 shape 规则检查它是否合理。

## 8. 它与集合通信有什么关系

假设使用两个 Rank 做数据并行：

- Rank 0 使用数据批次 A，算出本地梯度 `dW₀`；
- Rank 1 使用数据批次 B，算出本地梯度 `dW₁`；
- 两个 Rank 必须用相同的平均梯度更新各自的模型副本。

因此需要：

$$
dW=\frac{dW_0+dW_1}{2}
$$

AllReduce 正好完成“所有 Rank 共同 Reduce，再把结果发给所有 Rank”。从 Autograd 的视角看，它发生在梯度产生之后；从通信库视角看，输入只是一段待聚合的 Device Memory。

这就是后续理解 DDP 的关键连接点：

```text
反向传播逐层产生梯度
    ↓
梯度被放入 Bucket
    ↓
Bucket 就绪后触发 AllReduce
    ↓
通信与剩余反向计算尽量重叠
```
