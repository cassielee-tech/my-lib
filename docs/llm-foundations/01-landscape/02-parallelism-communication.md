### 先区分“并发”和“并行策略”

使用多张卡并不自动等于完成了分布式训练。还必须回答：

1. 每张卡保存完整模型，还是只保存一部分？
2. 每张卡处理相同数据，还是不同数据？
3. 某个中间张量是完整的，还是分片的？
4. 下一步计算需要本地分片，还是需要先收集完整数据？

这四个问题决定了需要通信的张量、通信时机和通信原语。

### Collective 到底是什么

Collective（集合通信）是**通信组内多个 Rank 共同参与的一次操作**。它和普通点对点通信的区别是：

- `Send/Recv`：明确指定发送方和接收方；
- `Collective`：描述整个组最终要达到的数据状态，由通信库安排具体传输步骤。

例如 AllReduce 的语义只是“把所有 Rank 的输入归约，并让所有 Rank 都得到结果”。至于是组成 Ring 还是 Tree、分多少块、走哪条链路，是通信库的实现问题。

### 常见 Collective 的最小例子

假设有两个 Rank：

```text
Rank 0: [1, 2]
Rank 1: [3, 4]
```

执行求和类型的 AllReduce 后：

```text
Rank 0: [4, 6]
Rank 1: [4, 6]
```

而 AllGather 是把分片按顺序收集：

```text
操作前：Rank 0 持有 [A]，Rank 1 持有 [B]
操作后：Rank 0、Rank 1 都持有 [A, B]
```

ReduceScatter 可以先粗略理解为 AllReduce 的结果再切分：

```text
先把各 Rank 对应位置的数据相加，再让每个 Rank 只保留结果的一部分
```

### 数据并行（DP）

每张卡保存完整模型，处理不同的数据。每张卡算出的梯度不同，因此更新参数前必须同步梯度，典型操作是 **AllReduce**。

### 张量并行（TP）

把同一个矩阵乘法切到多张卡。某一层的局部输出需要组合后才能进入下一步，常见操作是 **AllReduce、AllGather、ReduceScatter**。

### 流水线并行（PP）

把不同网络层放在不同设备，设备之间传递激活值与梯度，主要表现为相邻 Stage 的 **Send/Recv**。

### ZeRO / FSDP

把优化器状态、梯度甚至参数分片保存。计算前后需要临时收集或重新分片，核心操作通常是 **AllGather** 和 **ReduceScatter**。

### 专家并行（EP）

MoE 模型把不同专家放到不同设备，Token 要被路由到对应专家，典型操作是 **AlltoAll**。
