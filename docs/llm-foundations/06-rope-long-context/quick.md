> 适用：时间紧，或完整版跟不动时。这页用"座位号与时钟指针"讲完整章，读完抓住 80% 的主干。任何一节想深入，拉到文末点对应单元。

## 1. 一个尴尬的事实：会议室里没人记得座位号

上一章的会议有个隐患：Attention 打分只看**内容**（Q 对 K 的匹配），**完全不知道谁先说谁后说**。

把"我、爱、你"和"你、爱、我"放进会议室——如果只看名牌内容不看顺序，两张打分表可能一模一样。这不行：**"狗咬人"和"人咬狗"必须是两回事**。

所以需要给每个座位发**座位号**（位置编码）。老办法是把号码牌直接贴在工件上（加一个位置向量）；现代主流做法更巧妙——**RoPE（旋转位置编码）**。

::: details 小测 1：没有位置编码的 Attention 缺了什么？
缺顺序和距离信息。它只能按内容匹配，分不清"我爱你"和"你爱我"，也不知道两个词隔了多远。
:::

## 2. 时钟指针：转角度，记距离

RoPE 的思路一句话：**给每个词的 Q 和 K 装上时钟指针，两个词的距离就是指针的夹角**。

想象每个 Q/K 向量是一排**两两一组的时钟**：

- 位置 1 的词，指针都从 12 点出发；位置 2 的词，指针多转一格……位置越靠后，转得越多；
- **不同组转速不同**：有的像秒针（转得快，管近距离），有的像分针时针（转得慢，管远距离）；
- 妙处在**点积只看夹角**：位置 m 的 Q 和位置 n 的 K 做点积，转过的角度互相抵消，只留下 **(n − m)** 的差——**相对距离**自然浮现，与"从第几位开始数"无关。

三个容易问的问题：

- **转 Q 和 K，不转 V**——因为分数只由 Q/K 决定，V 是被取走的内容，不需要记距离；
- **指针不改变长短**——旋转不改变向量长度，信息量不丢；
- **几乎没有额外参数**——转速是公式定好的，不是学出来的。

::: details 小测 2：为什么 RoPE 通常只旋转 Q 和 K？
因为位置信息只需要进入"打分"环节：转了 Q 和 K，点积里就带上了相对距离；V 负责"被取走的内容"，转它没有意义，还会扰动内容本身。
:::

## 3. 会议室扩容：不止是指针不够用

想支持更长的上下文，就像把 100 座的会议室扩成 10000 座，至少三道坎：

1. **指针没见过大角度**：训练时指针最多转过 100 格，推理时要转 10000 格——陌生相位，模型没学过（解决思路：RoPE Scaling 等外推技巧）；
2. **打分表平方爆炸**：10000 座意味着 1 亿格的打分表（S² 增长）——计算和显存都吃不消（解决思路：Sliding Window、FlashAttention）；
3. **笔记本堆成山**：每个座位的历史记录（KV Cache）都要留着，越长攒得越多（解决思路：GQA、量化、分页管理）。

::: warning 关键
**长上下文不是"把长度参数改大"就完事**——位置外推、平方计算、缓存显存是三件独立的事，要分别解决。
:::

::: details 小测 3：直接把 RoPE 的缓存表扩到 32K，就能获得 32K 长上下文吗？
不能。表能查到 32K 的角度，但模型训练时从没见过那些相位，效果不可靠（需要外推/微调）；而且就算位置没问题，S² 的注意力计算量和 KV Cache 显存照样压垮你。三道坎一道都绕不开。
:::

## 3 句话带走

1. Attention **只认内容不认顺序**，必须有人记座位号——RoPE 就是座位号系统；
2. **转 Q/K 的指针，点积只剩夹角（相对距离）**；不转 V、不加参数、不改长度；
3. 长上下文有三道坎：**陌生相位、平方打分表、KV Cache 山**，要分别解决。

## 黑话小词典

| 术语 | 人话 |
| --- | --- |
| 位置编码 | 座位号系统（让模型知道词序） |
| RoPE | 旋转式座位号：转指针、算夹角 |
| 旋转对 / 频率 | 两两一组的时钟指针 / 各组转速 |
| 相对位置 | 夹角（n−m），大家一起挪座位也不变 |
| 绝对 position id | 每个词先按自己的真实座位转 |
| 外推 / RoPE Scaling | 指针没转过的大角度怎么处理 |
| Sliding Window | 只跟附近几个座位开会 |
| Context Parallel | 把一条长会议拆到多个会议室接力 |
