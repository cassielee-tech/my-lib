# 02｜张量、矩阵乘法、计算图与反向传播

## 这一课要解决的问题

Transformer 里几乎所有复杂结构，最终都可以拆成张量运算。要理解模型、算子和集合通信，首先要形成三个习惯：

1. 看到运算先写出每个张量的 **shape**；
2. 看到 shape 就能判断数据如何流动、能否完成运算；
3. 不只看前向结果，还要追踪反向传播产生的梯度。

## 开始前：为什么要学这几个概念

大模型代码看起来包含 Attention、Embedding、Normalization 等很多模块，但加速器真正执行的仍是更基础的运算：矩阵乘法、加法、乘法、归约和数据搬运。

这一课相当于学习大模型系统的“机器指令级思维”：

- **张量**告诉我们数据长什么样；
- **shape**告诉我们数据各维代表什么；
- **矩阵乘法**是 Transformer 消耗计算量最多的操作之一；
- **计算图**记录运算依赖；
- **反向传播**沿依赖关系计算梯度；
- **梯度张量**最终会成为数据并行中的通信对象。

### 从后端代码理解张量

后端开发中，我们经常定义结构化数据：

```text
List<Request> requests
Request.tokens
Token.embedding
```

在深度学习中，为了让硬件高效批量计算，这些嵌套对象通常不会以对象形式保存，而会排成一块连续、多维的数据：

```text
[请求数量, 每个请求的 Token 数, 每个 Token 的向量长度]
```

这就是 `[batch, sequence, hidden]` 张量。Shape 可以看成这段连续数据的“解释方式”。

## 1. 什么是张量

张量可以先简单理解为“带有形状的多维数组”。维数不同，常见称呼也不同。

![从标量到三维张量](/images/llm/tensor-shapes.svg)

在大模型中最常见的激活张量形状是：

```text
[batch_size, sequence_length, hidden_size]
```

例如 `[2, 4, 8]` 表示：

- 一次处理 2 条文本；
- 每条文本有 4 个 Token；
- 每个 Token 用一个长度为 8 的向量表示。

张量总元素数量为 `2 × 4 × 8 = 64`。若数据类型为 FP32，每个元素占 4 Byte，总空间为 `64 × 4 = 256 Byte`。

### 维度、轴和下标

对张量 `X[batch, sequence, hidden]`：

- 第 0 轴是 batch；
- 第 1 轴是 sequence；
- 第 2 轴是 hidden；
- `X[1, 2, 3]` 表示第 2 条文本、第 3 个 Token、向量中的第 4 个数字。

计算机下标通常从 0 开始，但自然语言描述习惯从 1 开始，这是阅读 shape 时常见的混淆来源。

### dtype 决定一个元素占多少空间

| dtype | 每个元素占用 | 直观特点 |
| --- | ---: | --- |
| FP32 | 4 Byte | 精度较高，占用较大 |
| FP16 | 2 Byte | 占用减半，表示范围有限 |
| BF16 | 2 Byte | 与 FP16 同样大小，指数范围更接近 FP32 |
| INT8 | 1 Byte | 常用于量化推理 |

张量占用空间的基础公式是：

```text
字节数 = 所有维度乘积 × 每个元素字节数
```

这里算出的只是张量本身的理论数据量，不包含内存对齐、Allocator 管理和框架对象等额外开销。

### 为什么 shape 对 AI Infra 很重要

Shape 不只是数学信息，它同时决定：

- 能否执行某个算子；
- 算子大约需要多少次计算；
- 激活值和中间结果占多少显存；
- 张量切分后每个设备持有什么数据；
- 集合通信需要发送多少字节。

后续分析任何模型或算子，都建议在草稿上先写 shape。

## 2. 矩阵乘法是 Transformer 的主干计算

线性层写作：

$$
Y = XW + b
$$

如果先把 batch 和 sequence 两维合并，矩阵形状如下：

![线性层矩阵乘法的形状变化](/images/llm/matmul-shapes.svg)

矩阵乘法的规则是：

```text
[M, K] × [K, N] → [M, N]
```

中间维度 `K` 必须相等。结果的每个元素，都是长度为 `K` 的两个向量做点积。

### 先从一个输出元素理解矩阵乘法

假设：

```text
X = [[1, 2]]
W = [[3, 4],
     [5, 6]]
```

那么：

```text
Y[0,0] = 1×3 + 2×5 = 13
Y[0,1] = 1×4 + 2×6 = 16
Y = [[13, 16]]
```

可以把 `W` 的每一列理解成一个“特征探测器”：输入向量分别与各列做点积，得到新的输出特征。

### 为什么线性层可以改变 hidden size

输入 `X` 的最后一维是 `H`，权重 `W` 是 `[H, O]`。矩阵乘法会消去 `H`，留下 `O`，因此线性层可以把每个 Token 的向量从长度 `H` 映射成长度 `O`：

```text
[B, S, H] × [H, O] → [B, S, O]
```

前面的 `B、S` 可以理解为有 `B×S` 个 Token 各自使用同一份权重进行转换。

### 计算量估算

矩阵乘法 `[M, K] × [K, N]` 大约需要：

$$
2MKN\ \text{FLOPs}
$$

系数 2 来自一次乘法和一次加法。比如：

```text
[8, 16] × [16, 32] → [8, 32]
FLOPs ≈ 2 × 8 × 16 × 32 = 8192
```

这套估算以后会用于判断算子规模、理论耗时和模型的总计算量。

### FLOP 是什么

FLOP 表示一次浮点运算，例如一次加法或乘法。FLOPs 在不同语境中可能表示“浮点运算次数”，也可能表示“每秒浮点运算能力”，阅读时要结合上下文：

- 这个矩阵乘法需要多少 FLOPs：讨论工作量；
- 设备峰值是 300 TFLOPS：讨论每秒理论计算能力。

理论 FLOPs 相同的两个算子，实际速度仍可能不同，因为它们的访存、并行度、数据布局和 Kernel 实现不同。

## 3. 广播：看似自动，实际发生了数据扩展

在线性层 `Y = XW + b` 中，`Y` 可能是 `[M, N]`，而偏置 `b` 通常只有 `[N]`。框架会把 `b` 视作每一行都相同：

```text
Y: [M, N]
b:    [N]
结果: [M, N]
```

这叫广播。判断广播时从最后一维向前比较：两个维度必须相等，或者其中一个为 1，或者某一方不存在该维度。

广播通常只是语义上的扩展，不代表一定真的复制出 `M` 份数据。但具体 Kernel 如何读取、能否融合，会影响真实性能。

## 4. 计算图记录了“结果是怎样算出来的”

考虑最简单的线性模型：

$$
\hat{y}=wx+b,\qquad L=(\hat{y}-y)^2
$$

前向传播可以表示成一张有向无环图：

![线性模型的前向计算图](/images/llm/computation-graph.svg)

图中包含两类信息：

- **数据节点**：输入、参数、中间结果和最终 Loss；
- **运算节点**：乘法、加法、平方等操作。

PyTorch Autograd 在前向计算时记录必要的运算关系和中间值。调用 `loss.backward()` 时，再沿图反向计算所有需要梯度的叶子张量。

### 计算图不是业务流程图

业务流程图描述组件或请求的控制流程；计算图描述**一个数值由哪些张量运算产生**。边代表数据依赖：如果计算 `B` 需要 `A` 的结果，就存在 `A → B` 的依赖。

图中通常包含：

- **叶子节点**：用户直接创建的输入或模型参数；
- **中间节点**：某一步运算产生的临时结果；
- **输出节点**：最终 Loss；
- **边**：数据依赖以及反向传播时梯度返回的路径。

## 5. 反向传播就是链式法则的高效实现

如果一个变量经过多步运算影响 Loss，它对 Loss 的梯度等于沿路径上各个局部导数的乘积。

![反向传播与链式法则](/images/llm/backprop-chain.svg)

对线性模型：

$$
\frac{\partial L}{\partial \hat{y}}=2(\hat{y}-y)
$$

$$
\frac{\partial \hat{y}}{\partial w}=x,\qquad
\frac{\partial \hat{y}}{\partial b}=1
$$

因此：

$$
\frac{\partial L}{\partial w}=2(\hat{y}-y)x
$$

$$
\frac{\partial L}{\partial b}=2(\hat{y}-y)
$$

重要的不是背公式，而是理解反向传播的执行模式：

1. 从标量 Loss 出发，上游梯度初始化为 1；
2. 每个节点根据自己的局部导数，把梯度传给输入；
3. 同一个变量通过多条路径影响 Loss 时，各路径梯度相加；
4. 最终得到每个可训练参数的梯度。

### 导数和梯度的直观含义

先不考虑严格数学定义。把参数 `w` 稍微增加一点，如果 Loss 随之：

- 增大：梯度为正；为了减小 Loss，应让 `w` 变小；
- 减小：梯度为负；为了减小 Loss，应让 `w` 变大；
- 基本不变：梯度接近 0，说明当前 Loss 对 `w` 不敏感。

优化器最基础的更新形式是梯度下降：

$$
w_{new}=w_{old}-\eta\frac{\partial L}{\partial w}
$$

其中 `η` 是学习率。减号表示沿着梯度的反方向移动，从而尝试降低 Loss。

### 为什么需要链式法则

参数通常不会直接产生 Loss，而是经过多步运算：

```text
w → z → ŷ → L
```

要知道 `w` 对 `L` 的影响，需要把每一小段的影响连乘起来。这与后端排查“上游输入变化如何经过多层服务影响最终指标”类似，只是这里每一层传递的是精确的局部导数。

## 6. 用 PyTorch 验证一次反向传播

```python
import torch

x = torch.tensor(3.0)
y = torch.tensor(10.0)
w = torch.tensor(2.0, requires_grad=True)
b = torch.tensor(1.0, requires_grad=True)

y_hat = w * x + b
loss = (y_hat - y) ** 2
loss.backward()

print(y_hat.item())  # 7.0
print(loss.item())   # 9.0
print(w.grad.item()) # -18.0
print(b.grad.item()) # -6.0
```

手工核对：

```text
ŷ = 2 × 3 + 1 = 7
L = (7 - 10)² = 9
∂L/∂w = 2 × (7 - 10) × 3 = -18
∂L/∂b = 2 × (7 - 10) = -6
```

### `requires_grad=True` 做了什么

它告诉 Autograd：后续需要计算这个张量相对于 Loss 的梯度。反向传播完成后，叶子参数的梯度累积在 `.grad` 中。

注意梯度默认是**累积**的。标准训练循环每轮都要在反向传播前调用：

```python
optimizer.zero_grad()
```

否则新梯度会继续加到旧梯度上。梯度累积训练正是有意利用了这一行为。

## 7. 矩阵形式下的梯度 shape

对于：

```text
Y = XW
X: [M, K]
W: [K, N]
Y: [M, N]
```

假设上游传来 `dY`，其 shape 必须与 `Y` 相同：

```text
dY: [M, N]
```

反向传播得到：

```text
dX = dY × Wᵀ  → [M, N] × [N, K] = [M, K]
dW = Xᵀ × dY  → [K, M] × [M, N] = [K, N]
```

一个非常有用的自检规则是：**某个变量的梯度 shape，必须与这个变量本身的 shape 相同。**

### 转置为什么会出现

转置 `Wᵀ` 会交换矩阵的两个维度：

```text
W:  [K, N]
Wᵀ: [N, K]
```

反向传播需要把上游梯度投影回输入或权重原来的空间，因此会调整矩阵方向，让矩阵乘法的中间维匹配：

```text
dY [M,N] × Wᵀ [N,K] → dX [M,K]
Xᵀ [K,M] × dY [M,N] → dW [K,N]
```

即使暂时不会严格推导公式，也可以用 shape 规则检查它是否合理。

## 8. 它与集合通信有什么关系

假设使用两个 Rank 做数据并行：

- Rank 0 使用数据批次 A，算出本地梯度 `dW₀`；
- Rank 1 使用数据批次 B，算出本地梯度 `dW₁`；
- 两个 Rank 必须用相同的平均梯度更新各自的模型副本。

因此需要：

$$
dW=\frac{dW_0+dW_1}{2}
$$

AllReduce 正好完成“所有 Rank 共同 Reduce，再把结果发给所有 Rank”。从 Autograd 的视角看，它发生在梯度产生之后；从通信库视角看，输入只是一段待聚合的 Device Memory。

这就是后续理解 DDP 的关键连接点：

```text
反向传播逐层产生梯度
    ↓
梯度被放入 Bucket
    ↓
Bucket 就绪后触发 AllReduce
    ↓
通信与剩余反向计算尽量重叠
```

## 9. 本课容易混淆的点

### Tensor 和 parameter 不是一回事

参数是需要被优化器更新的张量；输入和激活值也是张量，但通常不是模型参数。

### 前向 shape 和梯度 shape 不同路径、同形返回

前向中 `X → Y`，反向中梯度从 `dY → dX`。方向相反，但 `dX.shape == X.shape`。

### `backward()` 不是更新参数

`loss.backward()` 只计算并累积梯度；`optimizer.step()` 才使用梯度更新参数。

### 多卡不一定都用 AllReduce

是否使用 AllReduce 取决于张量怎样切分。数据并行常用 AllReduce；FSDP、张量并行和专家并行会产生其他 Collective。

::: details 必做 1 参考答案与推导

已知：

```text
X: [2, 4, 8]
W: [8, 16]
b: [16]
```

前两个维度表示一共有 `2×4=8` 个 Token，每个 Token 是长度为 8 的向量。每个 Token 与 `[8,16]` 的权重相乘，输出长度变成 16：

```text
Y: [2, 4, 16]
```

元素数量：

```text
2 × 4 × 16 = 128 个元素
```

FP16 每个元素占 2 Byte：

```text
128 × 2 = 256 Byte
```

计算 FLOPs 时把前两维合并成 `M=2×4=8`，并令 `K=8、N=16`：

```text
FLOPs ≈ 2MKN
      = 2 × 8 × 8 × 16
      = 2048 FLOPs
```

这里仅计算矩阵乘法，不包含偏置加法。梯度必须与对应变量 shape 相同：

```text
dX: [2, 4, 8]
dW: [8, 16]
db: [16]
```

`db` 会把 batch 和 sequence 两个维度上的梯度进行求和，因为同一个偏置 `b` 被所有 Token 共享。

:::

6. 两个数据并行 Rank 为什么不能直接用各自的本地梯度更新？

## 本课自测答案

::: details 1. [M,K] × [K,N] 为什么得到 [M,N]？

结果矩阵需要为左矩阵的每一行、右矩阵的每一列计算一个点积。左矩阵有 `M` 行，右矩阵有 `N` 列，所以结果有 `M` 行和 `N` 列。

两个参与点积的向量长度都必须是 `K`，这个维度在点积求和后被消去。

:::

::: details 2. FP16 张量 [2,4,8] 占多少 Byte？

元素数量是 `2×4×8=64`。FP16 每个元素占 2 Byte，所以张量数据占：

```text
64 × 2 = 128 Byte
```

这是张量数据的理论大小，不包含框架对象、内存对齐和 Allocator 额外开销。

:::

::: details 3. 计算图在前向阶段保存什么，反向阶段使用它做什么？

前向阶段记录张量经过了哪些运算、运算之间的依赖关系，以及反向计算局部梯度所需的中间值。

反向阶段从 Loss 出发，按照计算图的反方向依次调用各运算的反向规则，用链式法则把梯度传回输入和参数。

:::

::: details 4. 为什么 dW.shape 一定与 W.shape 相同？

`dW` 的每个元素描述 `W` 中对应参数对 Loss 的影响。`W` 有多少个可调参数，就必须有多少个对应的梯度，因此两者 shape 相同。

矩阵公式也能验证：`Xᵀ [K,M] × dY [M,N] → dW [K,N]`，与 `W [K,N]` 一致。

:::

::: details 5. backward() 与 optimizer.step() 分别做什么？

- `loss.backward()`：沿计算图计算梯度，并把结果累积到叶子参数的 `.grad`；
- `optimizer.step()`：读取这些梯度，根据 SGD、Adam 等优化规则真正修改参数；
- `optimizer.zero_grad()`：清空旧梯度，避免无意累积到下一轮。

:::

::: details 6. 两个数据并行 Rank 为什么不能直接用各自的本地梯度更新？

因为两个 Rank 处理不同的数据，本地梯度通常不同。如果各自更新，两个模型副本会产生不同参数，下一轮便不再是同一个模型。

DDP 用 AllReduce 聚合所有 Rank 的梯度，使每个 Rank 得到同一个全局梯度，再执行相同的优化器更新。

:::

::: details 7. DDP 为什么能让梯度通信与反向计算重叠？

反向传播按层从后向前生成梯度，不必等所有层梯度都生成后再一次性通信。DDP 可以把若干梯度装入 Bucket：

```text
后面层的 Bucket 就绪 → 启动 AllReduce
与此同时 → Autograd 继续计算前面层的梯度
```

如果通信由独立 Stream 异步执行，便能与剩余反向计算重叠。重叠效果取决于 Bucket 大小、层的计算时间、通信耗时以及各 Rank 到达时间是否一致。

:::
