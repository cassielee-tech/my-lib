# HCCL aclgraph 模式零拷贝方案

**发布日期：** 2026-11-17

---

## 摘要

GE 图模式（GraphMode 接口、Offload 模式）已经实现了零拷贝通信：算子在执行时直接读写对端的 input/output buffer，数据不再经过 CCL buffer 中转。本方案把同样的能力带到 aclgraph 模式。

核心思路：**检测到 aclgraph 的零拷贝算子后，把 opMode 改为 OFFLOAD，让所有现有 OFFLOAD 路径自动生效**。不需要在每处 OFFLOAD 分支上加条件，不需要新增状态标志，不需要扩展 executor 置位——下游代码看到的就是一个标准的 OFFLOAD 算子，只是注册键（tag）换成了计数器构造的唯一值。

---

## 背景：GE 图模式的零拷贝是怎么工作的

整个过程分三步——注册、查表、算法使用——全部发生在图模式算子的执行期（host 侧），最终对端地址留在 ChannelInfo 里随图执行。

### 注册

GE 框架通过 GraphMode 接口下发算子，`param.opMode` 被设为 `OpMode::OFFLOAD`。`HcclGetChannel` 里的 OFFLOAD 分支调用 `RegGraphModeBuffers`，用 `param.tag + "_InputBuffer"` / `param.tag + "_OutputBuffer"` 作为键，把本端 input/output buffer 地址注册到 hcomm 的通信域注册表。

注册时对 tag 有三个硬性要求：

1. **每个算子实例唯一**——同一张图里跑两个 AllGather，tag 相同会冲突
2. **所有 rank 一致**——rank 0 用 tag T 注册，rank 1 查表时也必须按 T 找
3. **注册和查表用同一个 tag**——send 查对端的 output，recv 查对端的 input，键必须匹配

GE 的 `param.tag` 是图编译算子名（如 `"AllGather-3"`），天然满足这三个条件。**aclgraph 不满足**——普通入口的 `param.tag` 是共享常量（`"AllGather_<commName>"`），这是本方案要解决的核心问题。

### 查表

`BuildChannelInfo` 调用 `GetGraphModeBuffers`，按 tag 在对端注册列表里做字符串匹配，找到对端 buffer 地址填进 `ChannelInfo.remoteInputGraphMode / remoteOutputGraphMode`。

### 算法使用

模板里有一个 `enableRemoteMemAccess_` 标志。关了（普通单算子）走 CCL buffer 三跳；开了（GE 图模式）从本端 input 直接搬到对端 output 地址，一跳。

## 方案

### 核心改动

在 `HcclExecOp` 入口加一个 gate，检测到 aclgraph 的零拷贝算子时改两个字段：

```c
if (param.opMode == OpMode::OPBASE && IsStreamInCaptureMode(param.stream)
    && param.engine == CommEngine::COMM_ENGINE_AICPU_TS
    && IsAclgraphZeroCopySupportedOp(param.opType) && !IsNegotiationCommName(param.commName)) {
    u32 seq = ++counter;  // 从桶里取号（集合类按 opType，send/recv 按 pair）
    snprintf_s(param.tag + strnlen(param.tag, TAG_LENGTH),
               TAG_LENGTH - strnlen(param.tag, TAG_LENGTH),
               "_aclgraph_%u", seq);
    param.opMode = OpMode::OFFLOAD;
}
```

tag 构造：**在入口已设的 param.tag 后追加 `_aclgraph_<seq>`**。

```
all_gather 入口:  "AllGather_comm0"       →  "AllGather_comm0_aclgraph_3"
send 入口:        "SendRecv_comm0_0_1"    →  "SendRecv_comm0_0_1_aclgraph_7"
```

原始 tag 已带算子名、通信域名（send/recv 还带 rank 对），追加序号后变为唯一。带 `aclgraph_` 前缀方便日志排障时一眼区分 GE-OFFLOAD 和 aclgraph-OFFLOAD。

改完之后，下游所有现有 OFFLOAD 路径自动生效：

| 下游代码 | 原来需要改什么 | opMode=OFFLOAD 后 |
|---|---|---|
| `HcclGetChannel` 注册 gate | `\|\| isAclGraphZeroCopy` | **自动走** OFFLOAD 分支 |
| `HcclGetChannelImpl` 句柄挂载 | 同上 | **自动走** |
| `BuildChannelInfo` 查表 gate | 同上 | **自动走** |
| 所有 executor `enableRemoteMemAccess` | 13 处扩展 | **自动置位** |
| send/recv `OrchestrateOffload` gate | 4 处扩展 | **自动走 Offload 路径** |
| `SetOpParamAlgTag` algTag 基名 | 条件切换 | **自动用 param.tag（=memTag），缓存必 miss** |

### tag 构造

在入口已设的 `param.tag` 后追加 `_aclgraph_<seq>`，不另建新字段：

```
BuildAclgraphMemTag(comm, param, userRank):

    ctx = 获取或创建主计数 ctx（per-comm，key = "AclgraphTagCtx"）

    if 是 send 或 recv:
        // param.tag 已含 src/dst（入口设的 "SendRecv_<comm>_<src>_<dst>"）
        pairCtx = 获取或创建 pair ctx（懒建，key = "P2P_<src>_<dst>"）
        seq = ++pairCtx->seq                   // 该 pair 的第 N 次通信，号永不归零
    else:
        seq = ++ctx->collSeq[算子枚举值]        // 该类型算子的第 N 次执行，号永不归零

    // 检查剩余空间，不够则回退（send/recv 最坏 tag 159+20=179 超 160 buffer）
    if (剩余空间 < 追加长度) {
        不改 opMode，回退普通路径
    }

    param.tag = 原始tag + "_aclgraph_" + seq
    // 例: "AllGather_comm0_aclgraph_3"
    // 例: "SendRecv_comm0_0_1_aclgraph_7"
```

计数粒度按"匹配流"原则：集合类按（comm, opType）分桶，send/recv 按（comm, src, dst）分桶。号永不归零——销毁重建会使号从头数，和注册表旧条目重名。

### 线程分配

`GeGetThread` 的 OFFLOAD 分支在 `slaveThreadNum = 0` 时**完全不碰 resPack**（循环不执行，只读了个 size）。send/recv 的 `OrchestrateOffload` 单线程，sole 类集合算子也是单线程。需要验证：确认零拷贝激活时 Selector 不会选出 `slaveThreadNum > 0` 的多线程变体。如果会选出来，要么在 gate 里限定走 sole，要么补 resPack。

## 支持范围

| 算子 | 计数方式 | 说明 |
|---|---|---|
| all_gather / all_gather_v | 按类型计数 | |
| broadcast | 按类型计数 | input/output 同址 |
| all_to_all | 按类型计数 | 等量布局，偏移本地可算 |
| send | 按 pair 计数 | 只注册 input |
| recv | 按 pair 计数 | 只注册 output |

不在范围：allreduce（暂不接）、reduce_scatter（暂不接）、all_to_all_v 非等量（需 kernel 侧地址交换）、batch_send_recv（现状不支持）、scatter/reduce（模板骨架预留）。

## 资源缓存

**原来的缓存逻辑**：HCCL 的资源缓存键是 `param.algTag`，由 `SetOpParamAlgTag` 用 `param.tag` 和算法名拼出来。同一个通信域上同算子同算法的第二次执行命中 `ReuseCachedDeviceCtx`，跳过 `HcclGetChannel`。缓存里存着 ChannelInfo（含对端 buffer 地址），第二个图命中时会拿**上一个图的对端地址**。

**替换方法**：gate 把 `param.tag` 覆写为 memTag（每个图唯一），`SetOpParamAlgTag` 自动用 param.tag 拼出唯一的 algTag → 缓存必 miss → 每个图独立注册+查表。

```c
// SetOpParamAlgTag 里不需要改——param.tag 已经是 memTag 了
algTag = param.tag + "_" + algName + "_" + launchMode;
// memTag 唯一 ⇒ algTag 唯一 ⇒ 缓存必 miss
```

代价是放弃跨图资源复用（图构建低频，可接受）。CCU 引擎不受影响：CCU 不走我们的 gate，algTag 仍用共享键。

## 与 SymWin 的关系

SymWin（对称内存）也能做零拷贝——框架提前把 buffer 注册进对称窗口，通信时用窗口偏移量直接推算对端地址。

两个通道同时生效时（aclgraph 的算子恰好 buffer 也在 SymWin 里）怎么办？答案是：**什么都不用做**。两条通道各自独立工作，往同一个 ChannelInfo 字段里写地址——因为解析的是同一块 buffer，值一定相同。代码里不做任何互斥。

---

## 与 PR #3910（AICPU Task Cache）的关系

PR #3910 扩展 task cache 到图模式，同时加 `isZeroCopy` 标志：零拷贝激活时 task cache 禁用。我们把 opMode 改成 OFFLOAD 后，PR #3910 的机制**自动检测到**这是零拷贝 op（OFFLOAD → enableRemoteMemAccess → isZeroCopy=true），不需要我们显式设置。两条 PR 独立合入即可，无冲突。

---

## 前提条件

- CANN ≥ 9.1
- 各 rank 执行相同的算子调用序列（计数对齐）
- 同一个通信域的算子下发必须串行
- input/output buffer 来自图内存池（地址跨 replay 稳定）
- 只对 AICPU_TS 引擎生效（CCU 的算子走原路径）
- 条件子图要求所有 rank 走同一个分支
- 图更新只能重新构建（原地改参数不会重新注册）

---

## 兼容性

- `param.tag` 在 gate 处被覆写为 memTag——但 Selector 已经跑完（在 gate 之前），后续消费者（algTag、注册、查表）正好要用 memTag。下一个 op 入口重新设自己的 param.tag，覆写只影响本次调用
- eager 路径零改动（gate 条件不命中，opMode 不变）
- GE Offload 行为不变（GE 的 opMode 本来就是 OFFLOAD，gate 不碰）
- hcomm / runtime 全部接口零改动
- 不设环境变量开关：检测自身就是门禁
